# PR187 — migrate-legacy-task-folders

## 概要

PR168 で workspace のタスクドキュメント構造を新形式（`.work/tasks/{YYMMDD}_{title}/{branch-hyphenated}.md` の 1 ファイル統合）に刷新したが、既存の PR1〜PR167 の旧構造（`{YYYYMMDD}_{title}/PR{N}/{TODO.md,QA.md}` の 2 ファイル）はそのまま残してある。本 PR で旧構造を新構造に一括移行する。

### 背景

PR168 では「移行リスクのほうが高い」「必要になった時点で実施」と判断して移行を先送りした。実装後の運用で、旧構造のフォルダが残っていると pr-show / qa-review / merge 等の `find -type f -name "PR*.md"` 系コマンドが旧フォルダの古いドキュメントも拾ってしまうリスクがある。一斉に移行して構造を統一する。

### 何をするか

- 旧構造ファイルを走査するスクリプトを書く（ローカル一回限りでよい）
- 各 `{YYYYMMDD}_{title}/PR{N}/{TODO.md,QA.md}` を新形式 `{YYMMDD}_{title}/{branch-hyphenated}.md` に変換
  - 日付プレフィックスを 8 桁 → 6 桁にトリム
  - TODO.md と QA.md をマージして新 PR ドキュメントテンプレートに合わせる
  - ブランチ名は archive から取得（既マージ PR）または推定
- 旧フォルダを `git rm`、新ファイルを `git add`
- 動作確認: `find .work/tasks -type f -name "PR*.md"` で全件取得できることを確認

### 留意点

- 既マージ PR の TODO.md は履歴として残すだけで、運用上の意味は薄い → 完全変換にこだわらず、必要最小限のメタデータだけ保持する形でも可
- 「ブランチ名が分からない過去 PR」はファイル名を `PR{N}.md` で代替する案もあり
