# master 上スクリプト実行ガード

> ブランチ: `feat/master-script-guard`

## 概要

work プラグインの `scripts/` 配下にある状態書き換え系 Python スクリプト
(`index-tool.py` / `issue-tool.py` / `trim-index.py`) を、cwd が
`master` / `main` / `develop` のときは実行できないようにする。

背景:
- `mcp__plugin_work_work-tools__*` 経由でも CLI 直叩きでも、これらのスクリプトは
  `path.write_text(...)` で `.work/tasks/index*.yaml` や `.work/issues/_index*.yaml`
  を直接書き換える。
- 既存の `protected-branch-guard.py` は PreToolUse `Edit|Write` matcher にしか
  乗っていないため、`Bash` 経由 (= MCP server → subprocess) はすり抜けてしまい、
  master 上で `_index.archive.yaml` 等が勝手に書き換わる現象が発生していた。
- 「master では実行できません、ブランチを引いてから使ってください」を強制したい。

### 実施条件

即時実施可

## 仕様

ガード対象スクリプト:

| No | スクリプト | ガード | 理由 |
|---|---|---|---|
| 1 | `scripts/index/index-tool.py` | あり | index.yaml 系を書き換える主犯 |
| 2 | `scripts/index/trim-index.py` | あり | 同上（completed 削除） |
| 3 | `scripts/issue/issue-tool.py` | あり | `_index.archive.yaml` 書き換えの主犯 |
| 4 | `scripts/worktree/worktree-tool.py` | なし | master から worktree を切る入口。ここを止めると詰む |

判定方法:
- `git branch --show-current` を cwd で実行
- 結果が `{master, main, develop}` のいずれかなら exit 1 で停止
- メッセージは stderr に日本語で出す: 「保護ブランチ '{branch}' 上では実行できません。/work:start でブランチを切ってから実行してください。」

経路ごとの効果:
- MCP 経由: `_run_script` が `cwd=CLAUDE_PROJECT_DIR` で起動するため、master セッションでは exit 1 → `CommandResult.success=False`
- CLI 直叩き (`python scripts/index/index-tool.py ...`): その場の cwd で判定
- worktree セッション: cwd が worktree パス = feature ブランチ → 通過

## /work:start への影響（既知の破綻）

現行 `/work:start` の step 2 は master セッションから `index_add` を呼ぶ:
- ガード適用後、この step は失敗する
- 回避するには `/work:start` 側を以下のいずれかに改修する必要がある
  - (a) `worktree_create` を先に行い、その後 worktree を cwd にする経路を MCP server に追加
  - (b) `index_add` だけ guard 除外する subcommand 別ホワイトリスト方式に切り替える

このタスクでは guard 本体のみ着地させ、`/work:start` 改修は次ブランチで扱う
（次ブランチ候補に記載）。
