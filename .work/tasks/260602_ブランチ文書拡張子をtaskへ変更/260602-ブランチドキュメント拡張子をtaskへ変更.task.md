# ブランチドキュメント拡張子をtaskへ変更

> ブランチ: `refactor/branch-doc-ext-to-task`

## 概要

「1 git ブランチ = 1 ドキュメント」の正本ドキュメントについて、命名と呼称を `tasks/` フォルダ
基準に統一する。当初は拡張子変更のみだったが、ユーザー依頼により以下までスコープ拡大:

- **A. 拡張子変更**: `.branch.md` → `.task.md`（`tasks/` フォルダ名と整合）
- **B. 用語統一**: 「ブランチドキュメント / branch document / ブランチ文書」→「タスクドキュメント / task document」
  （git の「ブランチ」概念とは区別。`> ブランチ:` ヘッダー等の git ブランチ名は変更しない。
  changelog / 変更履歴の過去エントリは事実記録として不変）
- **C. `work:quick-task` スキルの新設**: **git ブランチ/コミットを必要としない軽量作業**
  （調査・確認のみの依頼、および gitignore 除外ファイルの編集など）を `work:start` に通さず、
  UserPromptSubmit フックで振り分けて `work:quick-task` に渡す。worktree/ブランチ/QA ゲート/merge なし。

## QA

### QA-001: 簡易調査タスク用スキルの名前と設計

**背景**: git ブランチ/コミットを必要としない軽量作業を `work:start`（ブランチ/ワークツリー生成）に
通すのは重い。フック側で振り分け、軽量な専用スキルに渡したい。

**決定**:
- スキル名 = **`work:quick-task`**（ユーザー選択）。
- 対象 = git ブランチ/コミットを必要としない作業全般。「全く変更しない調査」に限らず、
  **gitignore 除外ファイルの編集**も含む（コミットされないため、ブランチ不要）。
- 挙動 = worktree/ブランチ/QA ゲート/merge は行わない。調査結果や軽微な変更はその場で実施・報告し、
  記録が有用な場合のみ軽量なタスクドキュメントを残す（コミットは強制しない）。
- フック = UserPromptSubmit で「実装コミットを伴わない作業」と判断できる場合は `work:quick-task` へ、
  実装コミットを伴う場合は従来どおり `work:start` へ。判断は AI が行う。

**状態**: 解決済み

**反映先**: 新スキル `skills/quick-task/SKILL.md`、`hooks/prompts/user-prompt-submit.md`、`CLAUDE.md`
