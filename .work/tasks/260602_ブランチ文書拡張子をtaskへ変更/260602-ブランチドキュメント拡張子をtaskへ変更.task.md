# ブランチドキュメント拡張子をtaskへ変更

> ブランチ: `refactor/branch-doc-ext-to-task`

## 概要

「1 git ブランチ = 1 ドキュメント」の正本ドキュメントについて、命名と呼称を `tasks/` フォルダ
基準に統一する。当初は拡張子変更のみだったが、ユーザー依頼により以下までスコープ拡大:

- **A. 拡張子変更**: `.branch.md` → `.task.md`（`tasks/` フォルダ名と整合）
- **B. 用語統一**: 「ブランチドキュメント / branch document / ブランチ文書」→「タスクドキュメント / task document」
  （git の「ブランチ」概念とは区別。`> ブランチ:` ヘッダー等の git ブランチ名は変更しない）
- **C. 簡易調査タスク用スキルの新設**: 調査・確認のみで実装が不要な依頼では `work:start`（ブランチ/
  ワークツリー作成）を呼ばず、UserPromptSubmit フック側で振り分けて新スキルに渡す。新スキルは
  軽量なタスクドキュメントを作る（ブランチ/ワークツリー/QA ゲート/merge なし）。

### 実施条件

即時実施可（ただし C のスキル名・設計は QA-001 確定後に実装）

## QA

### QA-001: 簡易調査タスク用スキルの名前と設計

**背景**: 調査・確認のみで実装不要な依頼を `work:start`（ブランチ/ワークツリー生成）に通すのは重い。
フック側で振り分け、軽量な調査専用スキルに渡したい。スキル名と、ドキュメント生成の有無を決める必要がある。

#### 名前候補

| # | 案 | 内容 |
|---|---|---|
| 1 | `work:investigate` | 「調査する」。`work:start` と対になり意味が明快（推奨） |
| 2 | `work:scout` | 軽い偵察・下調べのニュアンス |
| 3 | `work:inquiry` | 質問・問い合わせ調査 |
| 4 | `work:quick-task` | 「簡易タスク」を前面に出す |

**推奨方式**: `work:investigate` — `work:start`（実装着手）と語感が対になり、調査の意図が一目で分かる。

#### 設計（推奨案）

- 新スキルは **軽量タスクドキュメント**（`.task.md`）を `.work/tasks/` に作成し調査結果を記録する。
  ただし **ブランチ/ワークツリー/QA ゲート/merge は行わない**（読み取り中心のため）。
- UserPromptSubmit フック: 依頼が「実装/編集を伴わない調査・確認」と判断できる場合は `work:start`
  ではなく新スキルへ振り分ける。実装を伴う場合は従来どおり `work:start`。

**状態**: 未解決（ユーザーの名前選択・設計確認待ち）

**決定したら反映先**: 新スキル `SKILL.md`、`user-prompt-submit.md`、`CLAUDE.md`（Skills 表・Lifecycle）
