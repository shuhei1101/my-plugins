# イシュースキャン自動ループ対応

> ブランチ: `feat/issue-scan-auto-loop`

## 概要

`work:issue-scan` スキルを強化し、1回の実行でブランチ作成 → スキャン → master への自動マージを完結させる。`ISSUE_SCAN_AGENTS` 環境変数で並列サブエージェント数を制御できるようにし、`/loop` スキルと組み合わせて継続的な自動スキャンを実現する。

### 実施条件

即時実施可

| # | 案 | 内容 |
|---|---|---|
| 1 | A | スキル内から Agent ツールを直接呼ぶ |
| 2 | B | サブエージェント呼び出し部分を別スキル（issue-scan-agent）として分離し、メインスキルから Skill ツールで呼ぶ |

**推奨方式**: A（Agent ツールはスキル内からも呼べる — スキルリファレンスにサブエージェント実行の記述あり）

**状態**: 解決済み → 案 A を採用

### QA-003: サブエージェントのコミット責務（並列実行時の git 競合）

**背景**: ユーザー要望は「サブエージェントがコミットまで行い、戻り値は『完了』のみ」。ただし全サブエージェントは同一 worktree 上で動くため、並列で `git commit` すると `.git/index.lock` が競合し、`_index.yaml` / `_index.archive.yaml`（共有ファイル）の read-modify-write も競合（ロストアップデート）する。純粋な「各自並列コミット」は技術的に成立しない。

| # | 案 | 内容 |
|---|---|---|
| 1 | A | メインが ID を先採番してサブエージェントに割り当て → 各サブエージェントは並列でスキャン＋分析＋`ISSUE-{自分のID}.md` の**ファイル書き込みのみ**（共有 index は触らない・コミットしない） → 全完了後にメインが `_index.yaml`/`_index.archive.yaml` 更新＋コミット＋マージを一括実行 |
| 2 | B | サブエージェントを直列起動し、各自が index 更新＋コミットまで行う（並列化を諦める） |
| 3 | C | 各サブエージェントを `isolation: worktree` で別ワークツリー／別ブランチに分離し、最後にメインが全ブランチをマージ |

**推奨方式**: A。ユーザーの本質的要望（メインのコンテキストにイシューの中身を載せない＝戻り値を最小化）は、サブエージェントがファイルをディスクに書き込み戻り値を ISSUE ID 一覧だけにすれば達成できる。重いスキャン処理は並列のまま、競合する共有ファイル更新とコミットはメインに集約するのが最も安全。エージェント側は「コミット直前まで（ISSUE ファイル作成まで）」を担当する。

**状態**: 未解決（ユーザー確認待ち）

**決定したら反映先**: エージェントファイルの責務範囲、SKILL.md のステップ構成（先採番・集約コミット）
