## QA

### Q1: `lang` キーをフロントマターに残すか？

現在の `lang: python/html/next/markdown` は環境変数 `DEV_KIT_PYTHON` 等でON/OFFを切り替えるために使われている。

- **残す（推奨）**: フロントマターに `lang: python` を記述し、env トグルを維持する
- **廃止**: lang を廃止し、paths パターンだけでトリガー制御する（env トグルも消える）

### Q2: 同一ファイルで required / optional が混在するパターンへの対応

injection_rules.yaml では、1つのリファレンスファイルが「特定のパターンでは required、汎用パターンでは optional」として登録されているケースがある。

例: `python/core/型ヒント.md`
- `**/*.py` では **optional**
- `**/shared/types.py` では **required**
- `**/features/**/types.py` では **required**

フロントマットで表現する案：

**案A: paths エントリをオブジェクト形式で個別指定（推奨）**
```yaml
---
paths:
  - pattern: "**/*.py"
    required: false
  - "**/shared/types.py"
  - "**/features/**/types.py"
lang: python
---
```
（string のエントリは required: true デフォルト）

**案B: required/optional_for で分割**
```yaml
---
paths:
  - "**/shared/types.py"
  - "**/features/**/types.py"
optional_for:
  - "**/*.py"
lang: python
---
```

**案C: required を最も強い値（true）に統一**
```yaml
---
paths:
  - "**/*.py"
  - "**/shared/types.py"
  - "**/features/**/types.py"
required: true
lang: python
---
```
（精度が落ちるが最もシンプル）
