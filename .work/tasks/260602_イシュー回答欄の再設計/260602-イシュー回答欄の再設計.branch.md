# イシュー回答欄の再設計

> ブランチ: `refactor/work-issue-answer-section`

## 概要

work プラグインのイシューファイル（`.work/issues/ISSUE-{N}.md`）の「ユーザー回答欄」を、
ユーザーがモバイル等で素早く・確実に回答できる形に再設計する。現状は回答欄がファイル末尾にあり、
回答済みかどうかが下までスクロールしないと分からない／QA に推奨が無い／「自由記述」が冗長／
「回答候補」という区分が回答そのものになっていない、といった課題がある。

ユーザー要望（音声入力）:

1. **ユーザー回答欄をファイル最上部へ移動** — 開いた瞬間に回答済みか判別でき、下までスクロール不要。
2. **QA は必ず QA番号 + タイトル + 選択肢 + AI 推奨を持つ** — どれを推奨するかが無いと判断できない。
3. **「自由記述」欄を削除** — 回答欄に直接書けるので不要。
4. **「回答候補」区分をやめ、その行自体を回答にする** — ユーザーは不要な選択肢を消すだけ。
   意思は `対応する / 対応しない`、QA は `QA-1: A / B / C` / `QA-2: {回答を入力}` の形。

### QA-001: 新しい「ユーザー回答欄」のレイアウト

**背景**: 要望を満たすレイアウトとして 2 案ある。回答欄を最上部に置き、各 QA に番号・タイトル・
選択肢・推奨を持たせる点は共通。違いは「QA の詳細（タイトル・背景・推奨理由）を回答欄に同居させるか、
下の AI 記入欄に分離するか」。

| # | 案 | 内容 |
|---|---|---|
| 1 | A | **回答欄に QA 詳細を同居**。最上部の回答欄に各 QA の番号・タイトル・推奨（理由 1 行）・選択肢・回答行をまとめる。ユーザーは 1 箇所だけ見れば判断も回答もできる（スクロール不要） |
| 2 | B | **回答行のみ最上部・詳細は下**。最上部はユーザー例どおり `意思: 対応する / 対応しない` と `QA-1: A / B / C` の回答行だけ。QA のタイトル・選択肢の意味・推奨は下の `## QA` 詳細を参照 |

**推奨方式**: A。要望「下までスクロールしなくても判断できる」を最もよく満たし、推奨も選択肢も
回答も 1 箇所に集約できる。Bは回答行と詳細が離れ、結局スクロールが発生する。

**状態**: 解決（案A）— ユーザー決定: 案A。さらに **QA も丸ごと「ユーザー回答欄」内に入れる**
（現状は末尾にある QA を回答欄へ移動）。構成は「タイトル+作成日 → # ユーザー回答欄（意思 + QA）→
通常のイシュー本文（概要・背景・対応案 …）」の順。

**決定したら反映先**: `references/work-dir/イシュー.md` / `.jp.md` のテンプレート、各 skill/agent
