# Readキャンセル原因フック調査

> ブランチ: docs/read-cancel-hook-investigation

## 概要

`Read` ツールがキャンセルされる現象の原因フックを調査した。

---

## 調査結果

### 現象

Claude が `Read` ツールを呼び出すと、該当ファイルの読み込みが実行されず「キャンセル」として表示される。

### 原因

**ref-inject 機構の `PreToolUse(Read)` フック**が `decision: "block"` を返すため。

インストール済みプラグインのうち `inject_references.py` が Read に対しても発火する:

| No | プラグイン | バージョン |
|---|---|---|
| 1 | work | 2.69.0 |
| 2 | claude-kit | 3.55.0 |
| 3 | dev-kit | 4.15.0 |

### 具体例: `plugins/work/references/work-dir/イシュー.jp.md` の Read がキャンセル

以下の 2 パターンが同時にマッチして block を返した:

| No | プラグイン | パターン | 注入リファレンス |
|---|---|---|---|
| 1 | claude-kit | `plugins/*/references/**/*.md` | `common/リファレンス同期.md` |
| 2 | dev-kit | `**/*.md` | `markdown/マークダウンテーブル.md` など |

### 仕組み

`inject_references.py` は `PreToolUse(Edit | Write | MultiEdit | Read)` の 4 つで発火し、パスパターンがマッチすると **`decision: "block"`** を返す。

- `Edit`/`Write`/`MultiEdit` での block: 意図通り（編集前にリファレンスを注入）
- `Read` での block: 副作用あり（ファイル内容を Claude が受け取れなくなる）

Read がブロックされると Claude はリファレンス注入テキストを受け取るが、**読もうとしていたファイルの実内容は一切得られない**。

### 設計的背景

Read にも hook を張る理由: 「Read → Edit」の流れで先にリファレンスを注入するため。ただし Read そのものが block されるため、純粋な調査目的の Read も同様にキャンセルされる。

### TTL キャッシュ

同一セッション内で一度 block した後は TTL（デフォルト 3600 秒）が切れるまで再注入しない。TTL 内は `return 0` で素通りするため、**2 回目以降の Read は block されない**（つまり 1 回目だけキャンセルされる）。

### 回避策

- Bash + `sed` / `cat` を使えば hook をバイパスして内容を読める（`Bash` ツールは PreToolUse:Read の対象外）
- 環境変数 `WORK_INJECTION_DISABLE=true` 等でプラグインごとに一時停止できる
