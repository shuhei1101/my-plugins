# ジェネレーターメタデータ — creator スキル生成物の出自トレース機構

## 概要

creator スキル群が生成するファイルに、生成元の情報（プラグイン名 / スキル名 / バージョン）を
HTML コメント形式で埋め込む。これにより:

1. プラグインのバージョンが上がったとき、影響を受ける生成物を機械的に特定できる
2. 古いバージョンで作られた生成物に新バージョンの改善を取り込むスキル（`version-sync`）が動作できる
3. ユーザーが生成物の素性を後から追跡できる

## アーキテクチャ

メタデータ埋め込みロジックは **`mark-generated` スキル** に集約する（claude-kit 配下に新規作成）。
各 creator スキル・生成系スキルは内部に書式を持たず、以下の流れで呼び出す:

```
[生成系スキル]
  ↓ Step N: 生成物のパス・ファイル種別が確定
  ↓ Step N+1: `/claude-kit:mark-generated` を起動して書式を取得
  ↓ Step N+2: 取得した HTML コメントをファイル最上部に挿入
  ↓ Step N+3: ファイルを書き出し
```

### なぜスキル化するか

- **重複排除**: 5つの creator スキル + work-kit 系で同じロジックを書く必要がなくなる
- **書式変更の一元化**: 将来 JSON 対応・バージョン書式変更時に1箇所だけ修正
- **他プラグインから参照可能**: `claude-kit:` namespace で呼べるため work-kit / worktree-kit などからも利用可能
- **references/ にしない理由**: references/ はバージョン別キャッシュフォルダに配置されるため、他プラグインからの絶対パス参照が壊れやすい

### 適用対象スキル（creator 以外も含む）

「**固定の構造を持つ生成物**を作るスキル全般」が対象。動的な実装コードや一回限りのモック生成は対象外。

| プラグイン | スキル | 生成物 | 対象 |
|---|---|---|---|
| claude-kit | skill-creator | SKILL.md / SKILL.jp.md | ◯ |
| claude-kit | hook-creator | hooks/*.py / hooks.json | ◯ (py のみ) |
| claude-kit | rule-creator | .claude/rules/**/*.md | ◯ |
| claude-kit | claude-creator | CLAUDE.md / CLAUDE.jp.md | ◯ |
| claude-kit | plugin-creator | changelogs/*.md | ◯ |
| work-kit | work-start | TODO.md / QA.md / spec / notes | ◯ |
| work-kit | pr-handoff | 次PR の TODO.md / QA.md | ◯ |
| work-kit | conversation-to-claude | rule / skill / CLAUDE.md / incident | △ (creator 経由なら不要) |
| work-kit | setup | テンプレ全般 | ◯ |
| ui-kit | mock | モック HTML | × (動的生成のため対象外) |
| ui-kit | implement | 実装コード | × (同上) |

**判断基準**:
- テンプレートから派生する固定構造の生成物 → 対象
- ユーザーごとに動的に作られる実装物 → 対象外

二重適用回避: creator スキル経由で生成しているスキル（例: conversation-to-claude が rule-creator を呼ぶ場合）は、上位スキル側ではメタデータ付与をスキップし、creator 側に一任する。

### `mark-generated` スキルの責務

1. ファイル種別（拡張子・パス）を引数で受け取る
2. 呼び出し元プラグイン名・スキル名・バージョンを取得（plugin.json から読む）
3. ファイル種別に応じた書式の HTML/Python/Shell コメントを返す
4. JP ミラーファイル（`*.jp.md`）の場合は警告コメントも追加

呼び出し例:
```
/claude-kit:mark-generated --plugin claude-kit --skill skill-creator --file SKILL.jp.md
```

返却例:
```
<!-- Generated by claude-kit/skill-creator v1.2.0 -->
<!-- This file is a Japanese mirror of SKILL.md. When updating SKILL.md, update this file too. -->
```

## メタデータ記法

### 基本書式

ファイルの先頭付近に HTML コメントとして埋め込む。**挿入位置**は次のルールに従う:

- ファイルに YAML frontmatter がある場合: frontmatter の **閉じ `---` の直後**
- ファイルに frontmatter がない場合: ファイルの最上部

```html
<!-- Generated by {plugin}/{skill} v{version} -->
```

例 (frontmatter あり):

```html
---
name: my-skill
description: ...
---
<!-- Generated by claude-kit/skill-creator v1.2.0 -->
```

例 (frontmatter なし):

```html
<!-- Generated by claude-kit/rule-creator v1.2.0 -->
# Some Rule Title
```

### なぜ frontmatter の前ではなく後に置くか

HTML コメントを frontmatter の `---` より前に置くと、Markdown レンダラ
（GitHub・Claude Code 含む）が frontmatter を認識しなくなる。`---` が
水平線として表示されてしまい、`name:` `description:` などの
メタデータも本文の一部として描画される。

### なぜ HTML コメントか

- **AI に読まれづらい**: frontmatter のように構造化されないため、特殊な意味付けがされにくい
- **Markdown でレンダリングされない**: ドキュメントの見た目に影響しない
- **どのファイル形式にも書ける**: SKILL.md / CLAUDE.md / hook の Python ファイル（行頭 `# Generated by ...` に置換）/ JSON のように HTML コメントが使えないファイルは別ルール

### ファイル形式別の書式

| ファイル形式 | 書式 |
|---|---|
| Markdown (`*.md`) | `<!-- Generated by {plugin}/{skill} v{version} -->` |
| Python (`*.py`) | `# Generated by {plugin}/{skill} v{version}` |
| Shell (`*.sh`) | `# Generated by {plugin}/{skill} v{version}` |
| Jinja2 (`*.j2`) | `{# Generated by {plugin}/{skill} v{version} #}` |
| JSON (`*.json`) | メタデータは埋め込まない（JSON はコメント不可、別途 `_generator` キーで対応も検討中だが現時点では対象外） |

### バージョンの取得元

- `plugins/{plugin}/.claude-plugin/plugin.json` の `version` フィールド
- creator スキルは生成時に自プラグインの `plugin.json` を読み取って埋め込む

## JP ミラー警告コメント

`SKILL.jp.md` を生成する際は、出自メタデータに加えて以下の警告コメントを書く:

```html
<!-- Generated by claude-kit/skill-creator v1.2.0 -->
<!-- This file is a Japanese mirror of SKILL.md. When updating SKILL.md, update this file too. -->
```

英語版の警告として "Japanese mirror" を選んだ理由:
- このコメントは AI（Claude）が読む可能性があるため英語
- 既存 CLAUDE.md などでも同様の英語警告を採用している

## version-sync スキル仕様

### 配置

`plugins/claude-kit/skills/version-sync/SKILL.md`

### トリガー

ユーザーが「{プラグイン名} のバージョンが上がったから関連する生成物を同期して」と指示したとき、
または `/claude-kit:version-sync {plugin-name}` で明示起動。

### 動作モード

**完全自動**。確認なしで全工程を実行する。理由:
- worktree + ブランチで作業されている前提
- コミット単位で差分をユーザーが確認できる
- 1ファイルごとに確認すると大規模リファクタで実用性が低い

### 工程

1. 引数で受け取ったプラグインの `plugin.json` から現行バージョンを取得
2. リポジトリ全体を grep で `<!-- Generated by {plugin}/` を含む全ファイルを検出
3. 各ファイルの埋め込みバージョンと現行バージョンを比較
4. 古いファイルを抽出し、`changelogs/` から差分を読み取り
5. ファイルごとに以下を実施:
   - changelog 差分の内容を反映（手動編集相当の更新を AI が行う）
   - メタデータ行のバージョンを現行に更新
   - ファイル単位でコミット
6. 最後にユーザーへ報告（コミット一覧 + 影響ファイル数）

### 安全策

- master ブランチでは実行を拒否
- 起動時に `git status` がクリーンであることを確認
- 各コミットメッセージに `[version-sync]` プレフィックスを付与
