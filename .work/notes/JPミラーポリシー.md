# JP ミラーポリシー — .md 作成時の .jp.md 強制

## 概要

my-plugins では、すべての `.md` ファイルに対応する `.jp.md` ミラーが必要。
hook-creator などのスキルが `.md` を生成した後、`.jp.md` の作成が漏れるケースがあった（PR106）。
PR108 で PostToolUse フックを追加し、作成漏れを自動検出・通知する。

## フック設計方針

- イベント: `PostToolUse`（Write ツール）
- 対象: 作成されたファイルが `.md` で終わり、かつ `.jp.md` で終わらない場合
- 除外: `.work/` 配下（タスクドキュメントはミラー不要）、`changelogs/`、`node_modules/`
- アクション: 対応する `.jp.md` が存在しない場合、作成を促すメッセージを出力

## 適用範囲

my-plugins ローカル設定（`.claude/settings.json`）。グローバル設定には追加しない。

## JP ミラーの警告コメント形式（PR123 で整理）

`rules-jp/` 配下の JP ミラーはブロッククォート（`> ⚠️ ...`）ではなく mark-generated の HTML コメント形式を使う：

```
<!-- Generated by claude-kit/rule-creator v{version} -->
<!-- This file is a Japanese mirror. When updating the English original, update this file too. -->
```

この形式により `version-sync` スキルが古い生成物を検出できる。

## エージェントファイルの JP ミラー（PR133 で検討）

`plugins/{name}/agents/*.md` もスキルと同様のマシン読み取りファイルなので、JP ミラーの要否を判断する必要がある。
- スキル（SKILL.md）はユーザー確認用に .jp.md を持つ
- エージェントファイルも同じ理由で .jp.md があると望ましい
- ただし現時点では JP ミラー同期ルール（`skill-jp-mirror-sync.md` 等）はエージェントファイルをカバーしていない

→ PR133 では `.jp.md` も一緒に作成し、必要に応じてルール追加を次 PR 候補とする。
## エージェントファイル JP ミラー同期ルール（PR137 で追加 → PR141 で削除）

PR137 で `agent-jp-mirror-sync.md` を追加したが、PR141 で不要と判断し削除。
警告コメントとチェックリストで十分カバーされており、他の同種ルール（skill-jp-mirror-sync.md 等）も存在しないため。

## jp-mirror-translator エージェントの移動（PR141）

PR133 で work-kit に追加した `jp-mirror-translator` エージェントを claude-kit に移動する。
エージェント自体は claude-kit の creator skills（skill-creator / rule-creator 等）が JP ミラー生成に使用するため、
claude-kit が所有する方が責務として適切。

creator skills の JP ミラー生成ステップで `jp-mirror-translator` エージェントを呼ぶよう変更し、
翻訳処理を一元化する。

## JP ミラーコメントへのソースファイル名追加（PR207）

全 `*.jp.md` の冒頭コメントにソースの英語ファイル名を追加し、一括適用する。

**旧形式:**
```
<!-- This file is a Japanese mirror. When updating the English original, update this file too. -->
```

**新形式:**
```
<!-- This file is a Japanese mirror of {source_file.md}. When updating the English original, update this file too. -->
```

ソースファイル名はベース名のみ（フルパスなし）。`foo.jp.md` のソースは `foo.md`。
