# 環境変数記法規約 — Claude 成果物内での記述ルール

Claude が読む成果物（スキル・ルール・CLAUDE.md・フックプロンプト・リファレンス）内で
環境変数名を記述する際の規約。

---

## 基本ルール

指示文書内で環境変数名を参照するときは **必ず `${VAR_NAME}` 形式** を使う。

```markdown
# 良い例
このスキルは `${WORK_BASE_BRANCH}` を読んでベースブランチを決定する。

# 悪い例
このスキルは WORK_BASE_BRANCH を読んでベースブランチを決定する。
```

### `${}` を使う理由

- 視覚的に明確（一目で環境変数だとわかる）
- シェル構文と一致（Claude がそのまま Bash コマンドにコピーできる）
- 曖昧さがない（裸の名前は文字列リテラルに見える）

> Markdown は実行されないので `${VAR_NAME}` は**表記法のみ**。実際の値は `settings.json` に設定し、
> フック / スクリプトが `os.environ` で読む。

---

## 命名規約

| ルール | 例 |
|--------|----|
| ALL_CAPS_SNAKE_CASE | `WORK_BASE_BRANCH`、`DEV_KIT_INJECTION_TTL` |
| プラグイン名をプレフィックスにする | `dev-kit` → `DEV_KIT_*`、`work` → `WORK_*` |
| サフィックスは挙動を表す | `_TTL`、`_LANG`、`_BASE_BRANCH` |

---

## ドキュメント化（CLAUDE.md / スキル内）

環境変数をサポートするプラグイン・スキルは、必ず以下のテーブル形式で一覧する。

```markdown
## 環境変数

| 変数 | 効果 | デフォルト |
|------|------|-----------|
| `${WORK_BASE_BRANCH}` | ワークツリー作成時のベースブランチ | `master` |
```

テーブル内でも `${}` 表記を使う。

---

## 場面ごとの書き方まとめ

| 場面 | 書き方 |
|------|--------|
| 指示文書（SKILL.md・ルール・CLAUDE.md・プロンプト） | `` `${VAR_NAME}` `` |
| Bash コマンド | `${VAR_NAME}` または `$VAR_NAME` |
| Python `os.environ.get` | `"VAR_NAME"`（プレーン文字列） |
| テーブルの見出し / カラム値 | `` `${VAR_NAME}` `` |
