# guard-kit を workspace に統合 — PR169

## 概要

`guard-kit` プラグイン（`git push` / `git merge` を検出してユーザー確認を挟む PreToolUse(Bash) フック）を `workspace` に取り込み、単一プラグインとして配布する。プロジェクトごとに env var で起動可否を切り替えられるようにする（`WORKSPACE_USE_WORKTREE` / `WORKSPACE_PR_ENFORCEMENT` などと同じ opt-out パターン）。

## 背景

- guard-kit は PreToolUse(Bash) フック 1 つだけの薄いプラグイン
- workspace 側も `master-commit-guard` という同種の PreToolUse(Bash) ガードを持っており、責務が近い
- 独立プラグインとして残しておくとインストール手順が増えるだけで、env トグル化したほうがユーザー体験が単純になる
- 既に PR164 で常時発火フックを env で opt-out するパターンが確立されている

## 統合方針

### 移植対象（guard-kit → workspace）

| guard-kit のパス | workspace での配置 |
|---|---|
| `hooks/hooks.json` PreToolUse(Bash) エントリ | `hooks/hooks.json` の PreToolUse(Bash) 配列に追加（既存 master-commit-guard と並列） |
| `hooks/scripts/git-guard.py` | `hooks/scripts/git-guard.py` |
| `hooks/prompts/git-guard.md` | `hooks/prompts/git-guard.md` |
| `hooks/prompts/git-guard.jp.md` | `hooks/prompts/git-guard.jp.md` |

### env トグル

- 変数名: `WORKSPACE_GUARD`
- デフォルト: 有効（true）
- 無効化値: `false` / `0` / `no` / `off`（PR164 の他 workspace 変数と同じ falsy 判定）
- 実装場所: `git-guard.py` の `main()` 先頭で `os.environ.get('WORKSPACE_GUARD', 'true')` をチェックして早期 return

### 削除対象

- `plugins/guard-kit/` フォルダ一式
- `.claude-plugin/marketplace.json` から guard-kit エントリを除外

### バージョンバンプ

- workspace: 2.39.0 → 2.40.0（PR167 が同じ 2.39.0 を使っていたため再 bump）

### ドキュメント整備

- `glossary.md` に「guard-kit 統合 (PR169)」「WORKSPACE_GUARD」エントリを追加
- `env トグル一覧 (PR164)` エントリに `WORKSPACE_GUARD` を追記
- `incidents.md` 追加なし（既知パターンの踏襲のため）

## 環境変数のスコープ優先順位（補足）

`settings.json` の優先順位（高 → 低）:

1. Enterprise managed policies
2. CLI 引数
3. `.claude/settings.local.json`（プロジェクト個人、git-ignore 対象）
4. `.claude/settings.json`（プロジェクト共有）
5. `~/.claude/settings.json`（ユーザーグローバル）

→ プロジェクト配下が必ずユーザー配下より優先される。「このプロジェクトだけ guard を切る」「このプロジェクトだけ guard を入れる」のどちらも実現可能。
