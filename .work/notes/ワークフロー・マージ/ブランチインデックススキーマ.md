# ブランチインデックススキーマ — `.work/tasks/index.yaml` の構造と運用

work プラグインがブランチの進行状況を管理する `.work/tasks/index.yaml`（および完了分の
`index.archive.yaml`）のスキーマと、それを操作する `index-tool.py` の仕様。

## スキーマ

トップレベルは `branches`（リスト）のみ。各エントリは `branch` を識別キーとする。

```yaml
branches:
  - branch: refactor/foo      # 識別キー（git ブランチ名）
    created: 2026-05-31         # 作成日。同名ブランチを時系列で識別するサロゲート
    title: 日本語タイトル        # ブランチ文書の H1
    type: refactor             # feat / fix / refactor / docs / chore / test
    summary: 一行説明
    task: 260531_日本語タイトル   # タスクフォルダ名（YYMMDD_日本語タイトル）
    completed: false           # false = 進行中 / true = 完了（archive 対象）
```

- 数値 `id` / トップレベル `last_id` / `tags` は**持たない**（撤廃済み）。
- `created`（`add` 時にシステム日付 YYYY-MM-DD を自動設定）は**カウンタではないサロゲート**。
  git は同名ブランチの同時存在を禁止するため active 集合では `branch` は常に一意。`created` は
  archive で同名ブランチが時系列で再登場した場合の識別用（`--created` で明示指定も可）。
- `index.yaml` は gitignore 対象でメインリポにのみ存在。`index.archive.yaml` は git 追跡。
- `.work/issues/` の issue インデックス（`issue-tool.py` 管理）は別系統で、そちらは独自の
  `id` / `tags` を持つ（本スキーマの対象外）。

## index-tool.py サブコマンド

| # | サブコマンド | 役割 |
|---|---|---|
| 1 | `add --branch B --title T --type T --summary S --task T [--created YYYY-MM-DD]` | 新エントリを追記（`created` 既定=今日） |
| 2 | `list-active` | 未完了を `branch\|title\|type\|task` で出力 |
| 3 | `completed-count` | 完了済み件数を出力 |
| 4 | `set-completed --branch B` | 指定 branch を `completed: true` に |
| 5 | `archive [index] [archive]` | 完了済みを archive へ移動（件数出力） |

※ `next-id` は撤廃（採番不要）。識別は常に `branch`。

## ライフサイクル

1. `work:start` … `add` で active エントリ追記。
2. 作業中 … `completed: false`。
3. `work:merge` … Step5 `set-completed --branch`、Step6 `archive` で完了分を archive へ。
4. `branch-index-cleanup` … git ブランチと index を突き合わせ整理（`branches`/`branch` で動作）。
5. `plugin-migrate` Step3 … 旧スキーマ（id/last_id/tags）を branch キーへ冪等移行。
