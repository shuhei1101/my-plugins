# イシュー対応ワークフロー — review → resolve → close

`.work/issues/` に溜まったイシューを「作成 → レビュー（捌く）→ 対応（消化）→ クローズ」で流すワークフロー。
スマホからの運用を含めて、ユーザーは判断だけを行い、ブランチ作成〜マージまで自動で進む。

---

## 全体像

```
issue-create / issue-scan     issue-review              issue-resolve (/loop)                merge / reject
  （not_started で作成）   →  （ユーザーが意思記入）  →  （1 起動 1 イシュー）           →  （closed/ へ）
                                                           accept + direct_merge=true → 即マージ
                                                           accept + direct_merge=false → マージ待ち
                                                           reject → 使い捨てブランチで即 master マージ
```

---

## 各フェーズ

- **作成**: `issue-create`（手動）/ `issue-scan`（スキャン）が `.work/issues/ISSUE-{N}.md` を作る。
  フロントマターなし。状態は `_index.yaml`（`status: not_started`・`branches: []`）。
  条件を満たすイシュー（QAなし・単一案・非UI）は `direct_merge: true` も記録。
- **レビュー**: `work:issue-review`（スマホ主用途）。`## 意思` を 1 択に絞り、`## QA` も回答。
  ユーザーの自由記述補足は `## 意思` の回答行に inline で記入。
- **対応**: `work:issue-resolve`（`/loop` 駆動、1 起動 N イシュー）。
  - `accept` + `not_started` → `work:issue-resolver` サブエージェントを 1 つ委譲。
    オーケストレーターが `direct_merge` を決定（`_index.yaml` に値があれば使用。なければ
    イシュー内容で判断: UI 系→false、refactor/test/backend→true、不明→true）。
    `direct_merge: true`（デフォルト）→ 最終コミット後に master へ直接マージしイシューをクローズ。
    `direct_merge: false` → マージ待ち最終コミットで停止（ユーザーが `work:merge`）。
  - `reject` → 使い捨ての 1 イシュー専用ブランチ（`chore/reject-ISSUE-{N}`）で `wontfix` クローズ
    し、同一 tick 内で**即 master へマージ**。蓄積しない。
  - 未レビュー / `in_progress`（別セッション対応中）→ スキップ。
- **クローズ**:
  - `direct_merge: true` → リゾルバーが `issue-tool.py close --resolution resolved` を実行。
  - `direct_merge: false` → `work:merge` がブランチの `## 関連イシュー` を `resolved` でクローズ。
  - reject → `wontfix`。どちらも `closed/` へ移動し `_index.archive.yaml` に記録。

## イシューの状態管理（フロントマター不使用）

状態は `_index.yaml`（gitignore・コミットしない）が持つ:

| フィールド | 値 | 設定者 |
|---|---|---|
| `status` | `not_started` / `in_progress` | 作成時 `not_started`。`work:start` 経由で `issue-tool.py set-status` が `in_progress` に変更 |
| `branches` | ブランチ名の配列 | `work:start` が追記 |
| `direct_merge` | `true`（省略可） | `issue-scan` が条件を満たすイシューに設定。手動作成時も設定可能 |

ユーザー回答（意思・QA）はイシューファイル**下部**の `# ユーザー回答欄`（`---` の後）に置く。

---

## reject の即マージ（使い捨てブランチ）

- reject は純粋なステータス変更なので、1 件ごとに `chore/reject-ISSUE-{N}` ブランチで
  close → コミット → `--no-ff` で即 master マージ → ブランチ削除 を 1 tick で完結。
- close は**メインリポ**で実行する（ワークツリーではない）。`_index.yaml` はメインリポの
  作業コピーのみに存在するため、ここを直接更新しないと整合が取れない。
- `master` 直コミットは `master-commit-guard` でブロックされるが、マージコミットは対象外。

---

## direct_merge の自動マージとガード

- `issue-resolver` が `direct_merge: true` でマージするとき、`git-guard` が 1 回確認を挟む。
  同じコマンドをリトライすれば 2 回目は通る。
- ガードを完全にスキップするには `WORK_GUARD=false` をセッション環境に設定する。

## 関連コンポーネント

| 種別 | 名前 | 役割 |
|---|---|---|
| スキル | `work:issue-create` | イシュー作成（QA 提起） |
| スキル | `work:issue-scan` | スキャンでイシュー作成（direct_merge 付与含む）。worktree 作成後、master の未コミット `.work/issues/` 変更をコピーしスキャン結果と一緒にコミット |
| スキル | `work:issue-review` | 未レビューを捌く（意思/QA 記入・スマホ主用途） |
| スキル | `work:issue-resolve` | レビュー済みを消化（/loop・1 起動 N イシュー・direct_merge 判定） |
| スキル | `work:start` | ブランチ作成 + イシュー連携（status/branches/関連イシュー） |
| エージェント | `work:issue-resolver` | 1 イシュー→ブランチ→最終コミット→direct_merge によりマージ or 待機 |
| スクリプト | `issue-tool.py` | `set-status` / `add-branch` / `close` |
| リファレンス | `work-dir/イシュー.md` | イシューファイル構成・_index.yaml スキーマの単一情報源 |
