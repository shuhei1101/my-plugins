# インタラクティブレビュースキル — AskUserQuestion を使った 2 つのレビュー

## 概要

AskUserQuestion機能（選択肢形式でユーザーへ質問を投げる）を活用して、work-kitに2つのスキルを追加する。

**想定ユースケース**: スマホからSSH接続でClaude Codeを操作する際、コードの差分やファイルを直接確認できないため、スキルが代わりに内容を整理して対話形式で提示する。

---

## スキル1: qa-review

### 目的

指定PRのQA.mdに記録された未決事項を、選択肢形式でユーザーに提示し、回答を収集する。

### 呼び出し方

```
/work-kit:qa-review PR{N}
```

### フロー

1. 引数からPR番号を取得
2. 対応するQA.mdを探して読み込む
3. 未解決のQA項目を抽出
4. 各QA項目をAskUserQuestionで1件ずつ提示:
   - 選択肢: 「OK（解決）」「要検討（保留）」「その他（自由入力）」
5. 回答結果をまとめてユーザーに報告

---

## スキル2: impl-review

### 目的

現在のPRブランチのコミット履歴を分析し、実装内容をユーザーが選択肢形式で確認・深掘りできるインタラクティブなレビュー体験を提供する。

### 呼び出し方

```
/work-kit:impl-review
/work-kit:impl-review PR{N}  # ブランチ指定時
```

### フロー

1. コミット履歴（`git log master..HEAD`）と差分（`git diff master..HEAD --stat`）を分析
2. 変更内容を「大枠リスト」として整理（例: API追加、モデル変更、UIコンポーネント追加 など）
3. リストの1件目から順にAskUserQuestionで提示:
   - 選択肢: 「OK / 次へ」「もっと詳しく教えて」「その他（自由入力）」
4. 「もっと詳しく」を選んだ場合:
   - その変更の詳細（変更ファイル・主な修正内容・影響範囲）を掘り下げる
   - 深掘りが終わったら大枠リストの次の項目へ戻る
5. すべてのリスト項目を確認したら完了レポートを表示

### 観点の選び方（未決 / QA-001参照）

変更タイプ（バックエンド / フロントエンド / インフラ等）ごとに提示する観点が異なる。
現状の推奨案: **AIが都度判断**（変更ファイルを見て自律的に観点を選択）。

---

## 技術メモ

- AskUserQuestionはClaude Code固有の機能（`AskUserQuestion`ツール）
- SKILL.mdにはAskUserQuestionツールを呼び出す旨を明記する
- 選択肢は「OK / 次へ」「もっと詳しく」「Other」の3択ベースが基本
- 深掘りループはAskUserQuestionを再帰的に呼ぶ形で実装
