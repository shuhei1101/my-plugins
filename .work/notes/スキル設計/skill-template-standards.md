# skill-template-standards — SKILL.jp.md テンプレート標準とサブエージェントガイド

## 概要

`skills.jp.md`（スキル作成ガイドの JP ミラー）に規定する、SKILL.jp.md の雛形と
サブエージェント委譲の標準ガイドライン。

## SKILL.jp.md テンプレートのセクション名

新規スキルを作成する際は、以下のセクション名を使う（英語ではなく日本語で統一）:

| 英語（SKILL.md） | 日本語（SKILL.jp.md） |
|---|---|
| `## Overview` | `## 概要` |
| `## Tasks` | `## タスク` |
| `### Step N: <action>` | `### ステップ N: <アクション>` |
| `#### Condition` | `#### 条件` |
| `#### Input` | `#### 入力` |
| `#### Process` | `#### 処理` |
| `#### Output` | `#### 出力` |
| `#### Notes` | `#### 注意事項` |
| `##### Checklist` | `##### チェックリスト` |
| `##### Branching` | `##### 分岐` |
| `##### Prohibitions` | `##### 禁止事項` |
| `## References` | `## 参照` |
| `→ Proceed to Step N+1` | `→ ステップ N+1 へ` |

## サブエージェント委譲ガイドライン

### マーカー記法

サブエージェントに委譲する処理ステップには以下のマーカーを付け、戻り値の形式を明記する:

| マーカー | 使うとき |
|---|---|
| `[サブエージェントで実行・完了を待つ]` | 単体のサブエージェント、完了を待ってから次へ |
| `[サブエージェントで並列実行・完了を待つ]` | 複数並列実行、全完了を待ってから次へ |
| `[サブエージェントで並列実行・完了を待たない]` | 結果不要な場合のみ（稀） |

```markdown
#### 処理
1. [サブエージェントで並列実行・完了を待つ] 既存スキルを Glob し description を収集する
   （戻り値: `[{name, description}]`）
→ ステップ 2 へ
```

詳細ガイドは `plugins/claude-kit/references/subagents.jp.md` を参照。SKILL.md 編集時に optional で自動注入される。

### 使用の判断基準

**向いている:**
- 必要なコンテキストが少ない（会話履歴・ファイル内容をほぼ参照しない）
- 単純な変換・書き写し・翻訳など
- 同じ処理を複数ファイル・項目に対して並列実行したい
- メインエージェントのコンテキスト圧迫を防ぎたい

**向いていない:**
- メインの会話履歴や大量のコンテキストを参照する必要がある
- サブエージェントの内部処理もメインで必要

### 制約

- 戻り値のみが返る（内部処理詳細はメインに返らない）
- 完了を必ず待つ（複数並列実行しても全完了を待つ）
- サブエージェントはコンテキストが空の状態で起動する（必要な情報はプロンプトで渡す）

## description frontmatter の方針

スキルの `description` は**短い一行の説明のみ**でよい。トリガーフレーズは書かない。

### 理由

- このプロジェクトのスキルはユーザーが明示的に呼び出す（`/skill-name`）
- 自動起動のトリガーマッチングは使用しない
- トリガーフレーズの長い記述はコンテキストを圧迫するだけで効果がない

### 正しい例

```yaml
description: スキルが何をするかの一行要約。
```

### 誤った例（書かない）

```yaml
description: |
  ユーザーが「〜したい」「〜して」と言ったとき、または `/namespace:skill-name` を明示的に呼び出したとき。
```
