# ui-dev — 開発系画面デバッグ規約 設計仕様

## 概要

`dev-kit:ui-dev` は、開発系画面(管理画面・内部ツール・デバッグ画面など)を作成・編集する際に
必ず適用する UI 規約。中心機能は「フロートデバッグボタン」によるデバッグ動線提供。

エラー発生時や挙動確認時に、画面に関する情報(関連ファイルパス + 直近 JS ログ)を JSON で
クリップボードにコピーし、そのまま Claude Code に貼り付けてデバッグできることを目的とする。

## スキル位置づけ

- **プラグイン**: `dev-kit`
- **スキル名**: `dev-kit:ui-dev`
- **対象**: 開発をサポートする画面の作成・編集(本番ユーザー向け画面では使わない)
- **トリガー**: 開発用 UI を作る・改修する依頼が来たとき(新規・既存問わず)
- **関連リファレンス**:
  - `references/common.md`(ログ規約)
  - `references/frontend.md`(参考)
  - `references/html.md` / `css.md` / `js.md`(参考)

## 共通化方針(最重要)

各画面に同じデバッグ実装をコピペするのは禁止。
スキルは以下を**共通モジュール**として提供する:

```
plugins/dev-kit/skills/ui-dev/templates/
├── uidev.css       — フロートボタン + モーダルのスタイル
├── uidev.js        — ロガーフック + モーダル制御 + コピー処理
├── example.html    — 参考実装例(任意の画面に組み込む形)
├── CLAUDE.md       — フォルダ用ガイド(自動読み込み、英語)
└── CLAUDE.jp.md    — 上記の日本語ミラー
```

各画面側はこの 2 ファイルを 1 回読み込み、関連ファイル情報を **`data-debug-files` 属性**
(または `window.__uidevFiles` グローバル)で宣言するだけにする:

```html
<link rel="stylesheet" href="/static/uidev.css" />
<script src="/static/uidev.js" defer></script>

<!-- どこかの要素にこの画面の関連ファイルを宣言 -->
<body data-debug-files='{"html":["pages/user_list.html"],"css":["styles/user_list.css"],"js":["scripts/user_list.js"],"backend":["api/users.py"]}'>
```

これで各画面では `data-debug-files` の中身だけ差し替えれば良く、ボタン・モーダル・ロガーは共通。

## フロートデバッグボタン仕様

### 必須要件

- 開発系画面には**常に**フロートボタンを設置(必須)
- ボタンクリックでデバッグモーダルが開く
- Ctrl+Shift+D でも開閉可能

### デフォルト

| 項目 | デフォルト |
|---|---|
| 位置 | 右下 (`position: fixed; bottom: 16px; right: 16px;`) |
| アイコン | 🐛 |
| サイズ | 48px 丸 |
| z-index | 9999 |

位置はモーダル内の「ボタン位置」セレクトで上下左右に変更でき、localStorage に保存。

## デバッグモーダル

### レイアウト構成

```
┌────────────────────────────────────────────────┐
│ ui-dev デバッグパネル | ボタン位置▼ | 📋コピー | × │  ← ヘッダー(固定)
├────────────────────────────────────────────────┤
│ 概要                                            │
│  - page / url                                  │
│                                                │
│ 関連ファイル                                     │
│  - HTML / CSS / JS / Backend / Other 分類      │
│                                                │
│ 直近ログ        レベル▼ 行数[ ]                  │
│  ┌────────────────────────────────┐            │
│  │ 12:34:56.789 info  ...          │ ← 320px  │
│  │ 12:34:57.001 warn  ...          │   固定枠  │
│  │ ...                              │            │
│  └────────────────────────────────┘            │
├────────────────────────────────────────────────┤
│ Ctrl+Shift+D で開閉(フッター)                   │
└────────────────────────────────────────────────┘
```

- タブなしの縦スクロール
- セクション順: 概要 → 関連ファイル → 直近ログ(最下)
- ヘッダー: タイトル | ボタン位置セレクト | コピーボタン | 閉じる
- ログ枠は固定高 320px(中身の量で枠サイズが変わらない)
- ログのレベル/行数設定はログセクション内に inline 配置

### コピーボタン押下時

クリップボードに以下のスキーマで JSON をコピー:

```json
{
  "page":       "{location.pathname}",
  "url":        "{location.href}",
  "files":      { "html": [], "css": [], "js": [], "backend": [], "other": [] },
  "logs": {
    "limit":   100,
    "level":   "error",
    "entries": [
      { "ts": "ISO8601", "level": "log|info|warn|error|debug", "args": ["..."] }
    ]
  },
  "capturedAt": "ISO8601"
}
```

## JS ログ収集

`console.log / info / warn / error / debug` をラップしてリングバッファに溜める。
`window.onerror` と `unhandledrejection` も自動で取り込む。
バッファ上限は 2000 行(古いものから捨てる)。表示・コピーは設定された行数(デフォルト 100)で絞り込み。

詳細なログ運用規約は `references/common.md` の「ログ規約」セクションを参照。

## 関連ファイルの登録方法

| 方法 | 用途 |
|---|---|
| `data-debug-files='{...}'` 属性 | 画面の HTML 要素に直接宣言。最も簡単 |
| `window.__uidevFiles = {...}` グローバル | JS から動的に追加したい場合 |

両方併用可。`uidev.js` は両方を読み取りマージする。

## ローカル保存される設定(localStorage)

| キー | 用途 | デフォルト |
|---|---|---|
| `uidev.lines` | ログ表示・コピー行数 | 100 |
| `uidev.level` | 出力レベル(error / warn / info / debug) | error |
| `uidev.pos`   | フロートボタン位置 | bottom-right |

## 運用フロー

1. 開発者が開発系画面で挙動異常を確認
2. フロートボタン(または Ctrl+Shift+D)でモーダルを開く
3. 必要ならレベル・行数を調整
4. コピーボタンを押す → JSON がクリップボードへ
5. Claude Code に貼り付けて「これでデバッグして」と依頼
6. Claude が関連ファイルとログから原因を特定
