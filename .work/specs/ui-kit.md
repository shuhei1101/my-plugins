# ui-kit 設計方針

## 対象スコープ

開発支援画面(管理パネル・内部ツール・デバッグページ)向けの UI コンポーネントと規約。

---

## PC 専用方針(PR53 で確定)

**ui-kit は PC 版のみをターゲットとする。**

- モバイル・タブレット向けのレスポンシブ対応は行わない
- スマホからアクセスする場合も PC 表示のまま使う
- ブレイクポイント・メディアクエリは生成しない

### 背景

- モバイル画面対応はバグが多く、見通しが悪い
- 操作性は PC 画面の方が優れている
- 開発支援ツールはデスクトップ環境での利用が前提

---

## 削除済みの概念(PR53)

| 概念 | 削除内容 |
|---|---|
| Responsive セクション | ブレイクポイント定義(< 640px / 640–1024px / ≥ 1024px)を削除 |
| Drawer (Mobile) | モバイル用ハンバーガーメニュー・スライドドロワーを削除 |
| モバイル分岐 | ヘッダー高さ・トースト位置・一覧+詳細の mobile フォールバックを削除 |
| @media クエリ | mock-skeleton.html の `@media (max-width: 640px)` ブロックを削除 |

---

## レイアウト原則

- サイドバーは常時表示(固定)
- 2ペイン(一覧+詳細)は PC の横並び表示のみ
- トースト通知は右下固定
- アクションボタン(一覧画面)はリスト上部右

## debug-fab — clipboard コピー仕様

SSH 経由 HTTP(非セキュアコンテキスト)では `navigator.clipboard` が undefined になる。
`uidev.js` の `copyJSON` は以下の順でコピーを試みる:

1. `navigator.clipboard.writeText()` — HTTPS またはセキュアコンテキストで動作
2. `legacyCopyText()` — `textarea` + `document.execCommand('copy')` フォールバック(HTTP でも動作)

コピー失敗時の動作:
- `alert` でエラーメッセージを表示
- `stop()` を呼ばずピッカーモードを維持 → 選択状態を保ったままリトライ可能

フィードバック表示の仕様:
- FAB 経由のコピー → FAB ボタン自体に "✓ コピーしました" を表示
- トップボタン経由のコピー → トップボタンに "✓ コピーしました" を表示

## mock スキル — 出力先とサーバー起動ルール(PR57)

| 条件 | 出力先 | 起動方法 |
|---|---|---|
| FastAPI / Flask / Django などサーバーあり | サーバーのテンプレートディレクトリ(例: `templates/mocks/`) | すでに起動済みのサーバーポートを使うか、空きポートで起動 |
| サーバーなし / 静的プロジェクト | `tmp/mocks/` | `python -m http.server {空きポート}` を起動 |

- モック生成後は必ずブラウザで即開けるURLをユーザーに通知する(ファイルパスだけを伝えない)
- サーバープロジェクトでモック一覧ルートが未設定の場合は開発用ルート(`/dev/mocks` 等)を新規作成する
