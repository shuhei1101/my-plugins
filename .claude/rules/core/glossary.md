# Glossary

## Plugin System

| Term | Description |
|---|---|
| incidents | A fixed rule file (`.claude/rules/core/incidents.md`) that accumulates incident prevention logs for this project. Two-layer structure: index (always loaded) and detail files (`.claude/references/incidents/`). |
| glossary | A fixed rule file (`.claude/rules/core/glossary.md`) that manages project-specific terminology. Kept concise because it is always loaded. |
| conversation-to-claude | A skill (`/claude-kit:conversation-to-claude`) that analyzes the current session's conversation history and persists knowledge as artifacts such as skills, rules, hooks, CLAUDE.md, incidents, and glossary entries. |
| claude-refactor | A skill (`/claude-kit:claude-refactor`) that audits and reorganizes rules, skills, CLAUDE.md, and hooks under `.claude/`. Detects duplication, proposes file-type migrations and folder restructuring, then executes after confirmation. |
| 判定知識 | A block embedded in a skill's own References section — without loading external files — that contains the criteria and rules the skill needs for proposals and decisions. Introduced for token efficiency (PR68). |
| リンクルール | One of two rule types (file-linkage type). Bundles related files under `paths:` to enforce "if you edit one, check the others" coordination. |
| コンテキストルール | One of two rule types (load-trigger type). Auto-loads required knowledge/specs when a specific work area is touched. |
| ユースケース指向 | Design principle for `paths:`. Start from "when do I want this rule to be read?" and work backwards to identify the trigger files to list under `paths:`. |
| notes/ | The `.work/notes/` folder managed by the work plugin. A place for temporary design notes and discussion memos related to a PR. Treated as informal working notes rather than official specs because AI does not auto-load it. Formerly `specs/` (renamed in PR88). |
| notes-to-claude | A work plugin skill (`/work:notes-to-claude`) that promotes temporary memos in `.work/notes/` to rules, CLAUDE.md, or references. Runs fully automatically without a confirmation phase. Uses creator skills from the claude-kit plugin internally (added in PR90). |
| 1行参照パターン | A pattern where only the single line `"Read and follow: /path/to/file.md"` is output in a hook's `reason`/stdout instead of embedding the full file content. Claude reads the file itself, preventing long-text injection into the conversation session. Introduced for the Stop hook (PR89); unified across all hooks in hook-creator v3.20.0 (PR104). |
| pr-handoff | A skill (`/work:pr-handoff`) that reserves the next PR using the same flow as work-start, based on the "Next PR candidates" recorded in the current PR's TODO.md. Records background context in TODO.md to improve handoff quality (added in PR91). Serial-dependency support introduced in PR95. |
| 実施条件 | A concept with two uses. ① The 3rd column of the `## 次PR候補` table in TODO.md (dependency for each candidate: `即時実施可` / `「{other candidate}」が完了したら`) (PR95). ② The `### 実施条件` sub-section under `## 概要` in TODO.md — records the prerequisite conditions for starting this PR itself (PR101/102). |
| creator-dispatch フック | A former `PreToolUse(Edit/Write)` [[セッションフラグ型ブロック]] hook (`plugins/claude-kit/hooks/creator_dispatch.py`) that matched the edited file path and told Claude to run the corresponding creator skill (skill / rule / claude / hook / plugin) before editing. History: UserPromptSubmit keyword detection (PR103) → PreToolUse file-path matching → config-driven `RULES` script (PR153). **Removed in PR159**: the creator skills were migrated to [[claude-kit ref-inject 移行]] (reference auto-injection), so the creator-dispatch rules were dropped; the non-creator `j2-stamp-check` rule was kept (extracted into `j2_stamp_check.py`). **PR161**: `j2-stamp-check` and the PostToolUse `jp-mirror-check` (`jp_mirror_check.py`) were also removed — claude-kit now ships only the injection hook + `PreCompact`. JP-mirror sync by the `*-jp-mirror-sync` rules. |
| claude-kit ref-inject 移行 | PR159. claude-kit's creator skills (skill / rule / hook / claude / plugin-creator) were converted from step-format procedures into **self-contained authoring guides under `references/`**, auto-injected by the ref-inject hook (`inject_references.py` + `injection_rules.yaml`) when the matching file is edited (SKILL.md → skills.md, rule → rules.md, CLAUDE.md → claude-md.md, hooks.json → hooks.md, plugin.json → plugin-structure.md; glossary/incidents files → their format guides). The creator skills remain as **thin wrappers** (kept for explicit invocation and for callers like conversation-to-claude / notes-to-claude). The old [[creator-dispatch フック]] was removed. claude-kit thereby joins py-kit / next-kit under [[kit-hooks-index-sync]]. |
| 関連PR | The `### 関連PR` sub-section under `## 概要` in TODO.md. Records PRs directly related to this one (predecessor, split-sibling, follow-up, etc.) in a table of PR number and summary (added in PR102). |
| 直列依存 | A dependency where a follow-up PR can only be implemented after a preceding PR is merged. pr-handoff does not reserve serially-dependent candidates at once; instead it transcribes them into the preceding PR's `## 次PR候補` to carry the chain forward (introduced in PR95). |
| 即時予約対象 | A classification in pr-handoff Step 1. Candidates whose prerequisites are empty/即時実施可, or depend only on already-merged PRs. These are actually reserved by `/work:start` in the current pr-handoff run (introduced in PR95). |
| 依存後続候補 | A classification in pr-handoff Step 1. Candidates that depend on another candidate in the same table. Not reserved immediately; instead transcribed into the new TODO.md of the dependency target (即時予約対象) under `## 次PR候補` (introduced in PR95). |
| master 適合確認 | Step 3 of the merge skill. When master has progressed since the branch diverged, examines direct and indirect related changes and adapts autonomously according to tiebreaker priority order (added in PR92). |
| 間接依存 | The detection target in merge Step 3. Occurs when the master has changed code that calls or imports something this PR modified. Cannot be detected by direct file-name matching with `git diff --name-only` — requires contextual judgment. |
| タイブレーク順位 | Priority order when judgment is tied in merge Step 3: recency → blast radius → PR purpose → safer side (take master) (defined in PR92). |
| 出自メタデータ | An HTML/Python comment embedded at the top of files created by generator skills, in the format `<!-- Generated by {plugin}/{skill} v{version} -->`. Used as an identifier to detect outdated generated artifacts when a plugin version is bumped (introduced in PR94). **Removed in PR165** — the stamp system and all existing markers were deleted. |
| mark-generated | A claude-kit skill (`/claude-kit:mark-generated`) that returned the provenance metadata comment string for a target file type. Added PR94. PR161: demoted to a thin wrapper over `provenance.md`. **Removed in PR165** along with `provenance.md` and all provenance stamps. |
| provenance.md | `plugins/claude-kit/references/provenance.md`(+jp). Was the single source of truth for the provenance stamp. Introduced PR161. **Removed in PR165** along with the `mark-generated` skill and all provenance stamps. |
| environment.md | `plugins/claude-kit/references/environment.md`(+jp). The guide for making a plugin's **executable code (hooks/scripts)** configurable via environment variables: set in `settings.json`'s `env` block (user/project/local scopes), read with `os.environ` (with defaults/validation), the `{PREFIX}_INJECTION_TTL` / `{PREFIX}_INJECTION_LANG` example, naming/documentation conventions, and the env-vs-path-variable distinction. Key point: **only executable code can read env** — Markdown artifacts (CLAUDE.md / rule / SKILL.md) only *document* env vars. Injected full-body on `hooks.json` / `settings.json` edits and as an optional pointer on every other claude artifact. Introduced PR162. |
| version-sync | A claude-kit skill (`/claude-kit:version-sync {plugin}`) that detected files generated by an older plugin version using embedded provenance metadata. Added in PR94. **Removed in PR170** because provenance stamps were removed in PR165, leaving nothing for the skill to grep against. |
| 着手可能 (🟢) | One of the PR statuses presented by pr-show. A reserved branch where `git log master..{branch} --oneline` shows 1 or fewer commits — just reserved by pr-handoff with no implementation started yet (introduced in PR99). |
| 進行中 (🟡) | One of the PR statuses presented by pr-show. A reserved branch with 2 or more commits from master — considered to be actively worked on in another Claude Code session; best not to touch in the current session (introduced in PR99). |
| 条件あり (🔴) | One of the PR statuses presented by pr-show. A [[依存後続候補]] in TODO.md's `## 次PR候補` whose prerequisites depend on another candidate. Not yet reserved by pr-handoff; becomes a reservation target only after the preceding PR is merged (introduced in PR99). |
| pr-show | A skill (`/work:pr-show`) that lists the status of reserved PRs in 3 categories (ready / in-progress in another session / condition pending). Extracted as a standalone skill from merge Step 12 (added in PR109). Can also be invoked directly outside of merge. |
| disable-model-invocation | A frontmatter flag for Claude Code skills. When set to `true`, prevents the model from autonomously invoking the skill — it only fires when the user explicitly calls `/plugin:skill`. Skills with this flag do not need "no autonomous invocation" prohibitions (redundant). Only a same-recent-message call check is needed (consolidated in PR113). |
| セッションフラグ型ブロック | A design pattern where a PreToolUse hook uses a per-session flag file (`/tmp/{hook-name}-{session_id}`) to return `decision:block` only on the first call, then passes through subsequent edits in the same session once the user has gone through the creator skill. Originated in dev-kit's `python-skill-dispatch` / `yaml-skill-dispatch` (PR104); applied to all plugins' `skill-creator-dispatch` in PR121. |
| py-kit | A plugin (split from dev-kit in PR129) for Python-specific coding conventions and scaffolding. Originally adopted pure DDD as the standard layout (PR129). **In PR138 the standard was overhauled** to a "feature-folder layout + TypeScript-style + function-first" approach (design only), and **PR140 implemented v2.0.0**: references restructured into 38 files under topic-axis folders (`core/`, `architecture/`, `shared/`, `scripts/`, `testing/`, `concurrency/`, `packaging/`, `performance/`, `llm/`, `fastapi/`), with `references/index.yaml` carrying metadata and `injection_rules` (star chart) for per-edit-path reference auto-injection (the injection hook itself is reserved for follow-up PR `add-py-kit-references-injection-hook`). DB usage is out of scope (Web is delegated to next-kit). |
| 機能フォルダ型レイアウト | py-kit (PR138 onward) の標準レイアウト。`src/{pkg}/{shared,features,integrations,runtime,server}/` の構成で、機能（feature）単位でフォルダを切る方式。純DDD（domain/application/infrastructure/interface）の対義。`features/` 配下は自由に追加可能、`shared/` と `main.py` のみ必須、他は任意。AITuber 構造と Next.js (next-kit) の機能フォルダ思想を統合した結果。 |
| TypeScript 風 Python | py-kit (PR138 onward) の標準スタイル。Python 3.12+ の PEP 695（`type` 文・PEP 695 ジェネリクス）、`Callable[...]` 型エイリアス、`Protocol`（構造的型付け）、`@overload`、`Literal` + `match` + `assert_never`、Pydantic v2 / @dataclass / TypedDict を組み合わせて TypeScript の主要機能（type 文・interface・関数型 alias・ジェネリクス・discriminated union・関数オーバーロード）を Python で再現する。 |
| 関数ファースト | py-kit (PR138 onward) の標準スタイル。クラス（メンバー + 振る舞いを束ねたもの）ではなく **DTO（@dataclass / BaseModel）+ モジュールレベルの関数** で実装する設計方針。クラスを使うのは ① DTO（不変データコンテナ）、② ライブラリが強要する場合（FastAPI Middleware、Pydantic BaseModel 継承、CLI Command クラス等）、③ 長期保持のランタイム状態（接続プール等）に限定。 |
| ハンドラーデコレータ | py-kit (PR138 で採用方針確定) の例外ハンドリングパターン。例外キャッチや横断関心事を `@catch_and_log(level="warning")`, `@catch_and_map(SomeError, to=DomainError)`, `@with_retry(times=3)`, `@with_timeout(60)` 等のデコレータで束ねる。クラスベース AOP の代わりに関数デコレータで横断関心事を吸収する軽量パターン。 |
| 結合テスト + スモークテスト方針 | py-kit (PR138 で採用方針確定) のテスト方針。**単体テストは書かない**（AI 駆動開発前提、ソースコードが一次仕様）。代わりに ① **結合テスト**: ユースケースごとに、ルート → サービス → 条件分岐 → 結果まで通す。外部依存（LLM・TTS 等）は Mock 化。② **スモークテスト**: 外部サービスへの実接続確認。お金がかかるためユーザー手動実行のみ。AI 自動実行は禁止、`--run-smoke` 等の明示フラグでガード。 |
| 注入星取り表 (injection rules) | py-kit (PR138 で設計確定) の `references/index.yaml` に書く、編集対象ファイルパスのパターン → 注入する reference の組（`required` / `optional`）のマッピング表。次 PR の自動注入フック（PreToolUse）が編集対象ファイルに対応する reference を `decision: block` で注入する際の判断材料となる。 |

| ref-inject | A plugin (`/ref-inject:apply`) that **attaches the reference auto-injection mechanism to a target plugin** (new or existing) — the `*-kit` style hook used by py-kit / next-kit. Copies the injection files from `plugins/ref-inject/templates/` (hooks + references skeleton only). **Scoped to the injection part only**: it does NOT own `plugin.json`, the plugin's root `CLAUDE.md`, or `marketplace.json` (those are plugin-creator's job). **No generator script** — the `apply` skill has Claude read each template and write the destination file itself, substituting placeholders (`__PLUGIN_NAME__` / `__ENV_PREFIX__` / `__LOG_TAG__` / `__DEFAULT_TTL__`); this keeps the structure in context (decided PR156 — an earlier `scripts/generate.py` was removed). | ref-inject 注入設計 | The injection design baked into the hook ref-inject generates (decided PR156; two-tier cache added PR160). `required` references are injected **full-body**, `optional` as **path + description only**. The token at `~/.claude/tokens/{plugin}/{session_id}.yaml` is a **two-tier YAML map** with two namespaces — `patterns` and `references` — each keyed entry holding `{expires_at: epoch}` (`expires_at = injection time + TTL`). The **`patterns`** tier throttles whether a matched pattern's reference-set is re-injected at all (a still-fresh pattern is skipped entirely). The **`references`** tier throttles whether a `required` reference's **body** is injected: if a reference was already injected this session via any pattern (still fresh), it is shown by **path only** — so a reference bound to multiple patterns is never re-injected as full body (PR160). Skip while `now < expires_at`; re-inject once `now >= expires_at` (TTL default 3600s, shared by both tiers, overridable via `settings.json` `env` `{PREFIX}_INJECTION_TTL`). Storing `expires_at` rather than `injected_at` means a TTL env-var change does not retroactively affect already-written entries (changed PR157). Every hook fire cleans expired entries from both namespaces, deletes emptied token files, and purges stale top-level keys from the old single-tier schema. **No `PreCompact` hook** — after `/compact` the body re-injects once the TTL elapses; a dedicated compact-refresh hook was judged unnecessary overhead (PR156). Supersedes the per-pattern empty-file token ([[注入トークン]], PR150/151) and pointer-only injection ([[injection-hook-full-body-bloat]], PR147) — bodies are back because the TTL token throttles re-injection. |
| worktree-kit 統合 | PR163. The `worktree-kit` plugin was retired and its two skills folded into the work plugin: `work-add` (create a git worktree + branch) and `vscode-workspace-sync` (PostToolUse hooks that sync the VS Code `.code-workspace` `folders` to worktrees). Namespaces changed `worktree-kit:` → `workspace:`. Rationale: the dependency was one-way (work plugin's `start` → worktree-kit), so a separate plugin only added install overhead. Worktree usage is now gated by the [[WORK_USE_WORKTREE]] env var instead of "is worktree-kit installed?". The old `worktree-kit-dependency` rule was renamed to `work-start-worktree-link` (now an intra-workspace interface link). Reverses the PR58 split (`split-work-kit-worktree`). |
