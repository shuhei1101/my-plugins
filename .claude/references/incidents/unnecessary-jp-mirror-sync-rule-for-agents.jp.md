# インシデント: エージェントファイル用に不要な JP ミラー同期ルールを作成してしまった

## 何が起きたか

PR137 で `plugins/{name}/agents/*.md` ファイル向けの JP ミラー同期ルール（`agent-jp-mirror-sync.md`）を作成した。
`skill-jp-mirror-sync.md` や `hook-prompts-jp-mirror-sync.md` のパターンに倣ったもの。
PR141 でユーザーが不要として削除した。

## なぜ作成してしまったか

AI が既存パターンを過度に一般化した。SKILL.md とフックプロンプトにそれぞれ同期ルールがあるため、
PR133 でエージェントファイルも JP ミラーを持つようになった後、同様のルールが必要と判断してしまった。

## なぜ不要だったか

1. **警告コメントで十分**: すべての `*.jp.md` に `<!-- This file is a Japanese mirror... -->` が既に含まれており、編集者に両ファイルの更新を促している。
2. **エージェントファイルはほとんど編集されない**: SKILL.md（スキル更新のたびに編集）やフックプロンプト（フック動作変更時に編集）と異なり、エージェント定義ファイルは構造的なもので滅多に変更されない。同期ルールを正当化する「高頻度編集」の前提が成立しない。
3. **自然なパストリガーがない**: 有用な同期ルールはファイルが*読まれる*ときに自動ロードされる。エージェントファイルは SKILL.md や CLAUDE.md ほど頻繁に読まれない。

## 教訓

JP ミラー同期ルールが正当化されるのは、**頻繁に編集され、乖離リスクが高い**ファイル型のみ:

| ファイル型 | 同期ルール必要？ | 理由 |
|---|---|---|
| `SKILL.md` | 必要 | スキル更新のたびに編集; JP ミラーの同期が重要 |
| `hooks/prompts/*.md` | 必要 | フック動作変更時に編集; コンテキストに直接注入される |
| `CLAUDE.md` | 必要 | 頻繁に編集; JP ミラーの乖離が混乱を招く |
| `agents/*.md` | **不要** | ほとんど編集されない; 警告コメントで十分 |
| `*.jp.md` ミラー全般 | 不要 | 警告コメントがカバーしている |

## 正しいアプローチ

JP ミラーを持つすべてのファイル型に対して同期ルールを作成しない。
作成するのは以下の条件がすべて満たされる場合のみ:
- そのファイル型が頻繁に編集される
- JP ミラーの更新漏れが実際の混乱やバグを引き起こす
- 警告コメントだけでは不十分
