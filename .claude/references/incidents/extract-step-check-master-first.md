# Incident: スキルのステップ切り出し前に master の変更を確認する

## 発生日

2026-05-24 (PR109)

## 何が起きたか

merge スキルの Step 12（予約済みPR状況表示）を `pr-show` という独立スキルに切り出す PR109 を作業中、master に同じステップを変更する PR が2件（PR107、PR111）すでにマージされた。
PR109 のブランチ分岐後に master が進んでいたため、実装後に2回 master 取り込みが必要になり、そのたびに pr-show の実装を修正した。

## 根本原因

PR109 作業開始前に、切り出し対象のファイル（`merge/SKILL.md`）への直近のコミット履歴を確認しなかった。
master が並行して変更されていることに気づかず実装を進めた。

## 修正内容

1回目: PR107 の変更（絵文字なし・テーブル形式）を取り込み、pr-show のフォーマットを更新
2回目: PR111 の変更（全ブランチ列挙 → TODO.md テーブル起点）を取り込み、pr-show のロジックを全面改定

## 再発防止策

**既存スキルのステップを独立スキルに切り出す前に必ず確認する:**

```bash
git log --oneline master -- plugins/{plugin}/skills/{skill}/SKILL.md
```

最近のコミットがある場合は、その変更内容を読んでから実装を始める。
切り出すステップの内容が master で変更される予定があれば、先に master をマージしてから作業する。

## 補足

PR111 の変更はデータソースの設計自体を変えるものだった（全ブランチ列挙 → 特定 TODO.md テーブル起点）。
これにより pr-show の Step 2 が全面的に書き直しとなった。
設計変更を含む master の変更がある場合は特に注意が必要。
