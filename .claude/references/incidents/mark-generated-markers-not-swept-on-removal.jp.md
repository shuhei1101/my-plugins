# インシデント: mark-generated マーカー、スキル削除時に未掃除のまま残存

## 概要

`mark-generated` スキルが claude-kit v3.34.0（PR165）で廃止・削除された際、
それまでスタンプしていた `<!-- Generated by ... -->` / `# Generated by ...` コメントが
リポジトリから除去されずに残存した。その後のセッションで ref-inject の注入コメントと混同され、
フォローアップ PR（PR192）で一括削除が必要になった。

## 経緯

- **PR165**（claude-kit v3.34.0）: `mark-generated` スキルと `references/provenance.md` を削除。
- スキルが生成した _出力物_（テンプレートファイル・フック `.py`・SKILL.md・注入 `.j2` テンプレート
  内のマーカーコメント）はその時点で掃除されなかった。
- 後のセッションで、ref-inject の注入コメント（`<!-- Generated by ref-inject/apply ... -->`）が
  旧マーカーシステムと混同され混乱が発生。調査で多数の残存マーカーが発見された。
- **PR192** で全ファイルを一括削除: `uidev.css`, `uidev.js`, `example.html`,
  `mock-skeleton.html`, `ts_check.py`, `workspace/config/SKILL.md+jp.md`, `naming.md+jp.md`、
  および claude-kit・dev-kit・ref-inject の `inject_references.py` / `injection.*.j2` 全ファイル。

## 根本原因

PR165 がスキルコードと参照ファイルの削除に集中し、すでにマーカーが付与されたファイルの
grep スイープを含まなかった。

## 正しい対応

コード生成システム（スキル・フック・スクリプト等）を削除する際は:

1. そのシステムが生成した出力物を grep で検索する（スタンプパターンで）。
2. スイープを **同じ PR に含める** か、明示的なフォローアップタスクを作成する。
3. PR クローズ前に `grep -r "Generated by <system>" --include="*.md" --include="*.py" ...`
   で確認する。

## 再発防止

- マーカーを生成するツールを削除するときは、必ず先にマーカーパターンを grep で検索する。
- 削除 PR のチェックリストに「このツールが生成した出力物をすべて削除する」を追加する。
