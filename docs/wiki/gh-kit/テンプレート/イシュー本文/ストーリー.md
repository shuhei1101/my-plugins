# gh-kit テンプレート: ストーリー

`layer:story` が付いた Issue の本文書式。
1 ユースケース（1 シナリオ）を扱う親 Issue で使う。

story は **「何のユースケースを扱うか」を要件レベルで明示** するのが役割。
シナリオの詳細（正常系フロー / 異常系 / 前提条件）は Issue 本文には書かず、**docs 更新 PR で `docs/wiki/設計図/シナリオ/単一ユースケース/{機能名}.md` に書く**。
1 story = 1 シナリオファイル = 1 E2E テストファイル に 1:1 対応する。

## 担当セクション一覧

| No | セクション              | サブセクション | 必須or条件 | 担当                                                    |
| -- | ----------------------- | -------------- | ---------- | ------------------------------------------------------- |
| 1  | `## 前提条件`           | -              | 必須       | issue-triage                                            |
| 2  | `## 概要`               | -              | 必須       | issue-triage                                            |
| 3  | `## 背景`               | -              | 〃         | 〃                                                      |

## `## 前提条件`

### 記述例

```markdown
## 前提条件

| No | 種類    | 対象                                | 状態   | 補足                          |
| -- | ------- | ----------------------------------- | ------ | ----------------------------- |
| 1  | Issue   | #90（親エピック）                   | 進行中 | 親 epic が進行中である前提    |
| 2  | Issue   | #92（兄弟 story: 認証機能）         | 完了   | 認証ユースケース完了後に着手  |
```

### 補足

- **依存する Issue / PR がない場合も本セクションは残し、本文に「なし」と記載する**
- 親エピックは常に前提条件に含める（明示化のため）
- 兄弟 story との順序（例: 認証 → プロフィール編集）もここで示す

## `## 概要`

### 記述例

```markdown
## 概要

ログイン中ユーザーが自身のプロフィール項目（氏名・自己紹介・アバター画像）を編集・保存する。
```

### 補足

- 1 ユースケースを 1〜2 行でまとめる
- 「{アクター} が {何をする}」で書く
- 親 epic の `## ユーザー視点要件` の 1 行と対応する

## `## 背景`

### 記述例

```markdown
## 背景

親 epic「プロフィール自己管理機能」のシナリオ No.2「プロフィールを編集して保存する」に対応。
既存の閲覧機能（`/profile/view`）に対して編集動線を追加する必要がある。
```

### 補足

- 親 epic のどの要件に対応するかを明示（epic の `## ユーザー視点要件` の No を参照）
- なぜこの story を切り出したか（epic をなぜこの粒度で分けたか）を書く
