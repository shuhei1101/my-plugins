# テスト方針

単体・結合・外部疎通・E2E の 4 種類を書く。
テストの対応関係は設計書（モジュール構成 / 結合 / シナリオ）のテスト表が SoT で、テストは表と 1:1 で実装する。

| 種類           | 目的                                                                                   | 実行                                                     |
| -------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 単体テスト     | 関数 / メソッド単位のロジック（分岐・変換・組み立て）を確認                            | CI / 開発時に自動                                        |
| 結合テスト     | ユースケース 1 単位（入力 → サービス → 分岐 → 結果）を通しで確認。外部依存は Mock 注入 | CI / 開発時に自動                                        |
| 外部疎通テスト | 外部サービスへの実接続確認（実際に使うパラメータ値の網羅）                             | ユーザー手動のみ。CI / AI 自動実行禁止（課金・副作用が発生する） |
| E2E テスト     | シナリオ設計書どおりの業務フローを実環境で確認                                         | 手動 or 明示実行のみ                                     |

## 単体テスト

- 単体の単位 = 1 ファイル。
  同一ファイル内のヘルパーは実物のまま、ファイル外 / プロセス外の依存は Mock する（Sociable）
- データ引数（DTO / 設定値）は Mock ではなく fixture で値を与える
- 分岐（if / フラグ / バリデーション / フォールバック）ごとに 1 テスト以上置き、分岐カバレッジを極力 100% にする
- 自関数で raise する例外は異常系としてテストし、素通しで伝播する例外は代表 1 関数だけ確認する

## 結合テスト

- 1 ファイル 1 ユースケース、条件分岐ごとに `test_*` 関数を並べる
- 外部依存（`chat` 等）は Mock 関数を引数注入
- セットアップは conftest の fixture に集約
- カバレッジ率を目標数値で縛らない（重要ユースケースが通っているかを定性判断）

## ファイル配置

```
tests/
├── conftest.py       # 共通 fixtures
├── unit/             # 単体（src をミラー・1 テストファイル = 1 実装ファイル）
├── integration/      # 結合（1 テストファイル = 1 ユースケース）
├── external/         # 外部疎通（--run-external ガード）
└── e2e/              # シナリオ E2E（実環境で実行）
```

- 実行: `uv run pytest`（external / e2e はガードで skip され、単体 + 結合だけが走る）
- e2e の起動方法・対象環境はプロジェクト固有（各プロジェクトのテスト実行方法ページに従う）

## 外部疎通テスト

- `tests/external/conftest.py` で `--run-external` オプションを定義し、なければ全 skip
- 実行は `uv run pytest tests/external/ --run-external`（ユーザーが明示したときだけ）
- 内容は「実際に使うパラメータ値ごとに実接続が成立して期待形式のレスポンスが返る」の 1 回きり網羅確認。
  業務ロジック検証は結合テスト側
- env キーがなければ `pytest.skip`
