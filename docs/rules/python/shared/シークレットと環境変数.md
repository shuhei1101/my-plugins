# シークレット / 環境 / 構造 / アセットの分離

シークレットは git 管理下のファイルに絶対に書かない。
置き場所そのものは問わない（`.env` でも `settings.yaml` でもよい）が、そのファイルが gitignore されていることが条件。

| 種別                                                 | 保管先                                           | git |
| ---------------------------------------------------- | ------------------------------------------------ | --- |
| シークレット（API キー / DB パスワード）             | `.env` または gitignore 済みの `settings.yaml`   | ❌  |
| 個人環境固有（ローカルパス / ポート / 既定モデル名） | `config/settings.yaml`                           | ❌  |
| 構造定義（スキーマ / 選択肢 / カテゴリ）             | コード（`constants.py` / `Literal` / `StrEnum`） | ✅  |
| アセット定義（プロンプト / カタログ）                | `prompts/index.yaml` 等                          | ✅  |
| ランタイム状態（履歴・キャッシュ）                   | `data/`                                          | ❌  |

- 秘匿値を持つファイルには必ずサンプル（`.env.sample` / `settings.yaml.sample`）を対で置き、そちらを git 管理する。
  必要なキーとプレースホルダだけを書き、実値は入れない
- シークレットと個人環境固有の値を 1 ファイルにまとめてよい。
  分けるほど設定の所在が散るので、gitignore 済みなら 1 箇所に集約したほうが扱いやすい

## 環境変数の命名

- `UPPER_SNAKE_CASE`、外部サービス系は `{SERVICE}_{NAME}`（`OPENAI_API_KEY`）
- ネストは `env_nested_delimiter="__"` で `DB__HOST` → `Settings.db.host`

SecretStr の扱いは `shared/設定.md`。
