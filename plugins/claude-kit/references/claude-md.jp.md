# CLAUDE.md 設計ガイド

`CLAUDE.md` とその JP ミラー `CLAUDE.jp.md` の設計・作成・評価に使う知識をまとめたドキュメント。

---

## 読み込みタイミング

| 配置場所 | 読み込みタイミング |
|---|---|
| プロジェクトルート | セッション開始時に**必ず**読み込まれる |
| サブフォルダ | そのフォルダ内のファイルを Claude が読み込んだとき（遅延ロード） |

---

## 重要: 極力薄く保つ

ルートの CLAUDE.md は**毎回必ずロードされる**ため、内容が増えるほどコンテキストを圧迫する。

### 外出し先の判断

| 内容の性質 | 外出し先 |
|---|---|
| 特定ファイル編集時にのみ必要 | `.claude/rules/` に移す |
| 複数ステップのワークフロー | `.claude/skills/` に移す |
| 特定フォルダだけに関係 | そのサブフォルダの `CLAUDE.md` に移す |
| 詳細説明・参考資料（たまに読めばよい） | `.claude/references/` に移し、CLAUDE.md にはパスだけ書く |
| プロジェクト内に既にある仕様書 | パスだけ書き、内容は書かない |

---

## `.claude/references/` について

CLAUDE.md に書きたいが毎回読む必要はない内容（詳細仕様・補足説明・参考資料）を置く場所。
CLAUDE.md には「詳細は `.claude/references/xxx.md` を参照」とパスだけ書き、
Claude が必要なときに読む形にする。

---

## 必須セクション

| セクション | 内容 | 必須/推奨 |
|---|---|---|
| タイトル | H1 見出し | 必須 |
| `## 概要` | プロジェクト/フォルダの説明 | 必須 |
| `## フォルダ構成` | パスと概要の対応表 | 推奨 |
| `## 制約` | Claude が常に守るルール・禁止事項 | 推奨 |

---

## 構造例

```markdown
# Project Name

## 概要
このプロジェクト/フォルダの説明

## フォルダ構成

| パス | 概要 |
|------|------|
| `src/` | 実装コード |
| `docs/specs/` | 仕様書 |
| `.claude/` | Claude Code 設定 |

## 制約

- コミット前に必ず `npm test` を実行する
- `main` ブランチへの直接プッシュ禁止
```

---

## サブフォルダ CLAUDE.md と rules の使い分け

| 優先したいこと | 選択 |
|---|---|
| **コードに隣接してルールを置きたい**（co-location 重視） | サブフォルダ `CLAUDE.md` |
| **全ルールを一箇所で把握したい**（監査・一覧性重視） | `.claude/rules/<name>.md` |

複数の異なるフォルダをまたぐリンクは常に `.claude/rules/` に書く。

---

## 行数の目安

- ルートの CLAUDE.md は 200行以内を目安とする
- 超える場合は `.claude/rules/` にドメイン固有内容を切り出す
