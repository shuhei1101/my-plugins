# Claude 成果物内の環境変数記法

スキル・ルール・CLAUDE.md・フックプロンプト・リファレンスなど、Claude が読む成果物に
環境変数名を一貫して記述・ドキュメント化する方法。

---

## 記法ルール: 常に `${VAR_NAME}` を使う

Claude が読むドキュメント（SKILL.md、ルール、CLAUDE.md、プロンプトファイル、リファレンス）内で
環境変数名を**参照する場合は必ず** `${VAR_NAME}` の形式で書く:

```markdown
このスキルは `${WORK_BASE_BRANCH}` を読んでチェックアウト先ブランチを決定する。
`${MY_KIT_INJECTION_TTL}` を設定してキャッシュ有効期間を制御する。
```

**`${...}` を使う理由（裸の `VAR_NAME` ではなく）**:
- 視覚的に明確 — 読み手が一目で環境変数だと認識できる。
- シェル構文と一致 — Claude がそのまま Bash コマンドにコピーできる。
- 曖昧さがない — `${}` なしの `WORK_BASE_BRANCH` は変数参照ではなく文字列リテラルに読める。

> Markdown ファイルは実行されずコンテキストに読み込まれるだけ — テキスト内の `${VAR_NAME}` は
> **表記法のみ**。実際の値は `settings.json` で設定し、フック / スクリプトが `os.environ` で読む。

---

## 命名規約

| ルール | 例 |
|--------|----|
| ALL_CAPS_SNAKE_CASE | `WORK_BASE_BRANCH`、`DEV_KIT_INJECTION_TTL` |
| プラグイン名をプレフィックスにする（大文字化、英数字以外 → `_`） | `dev-kit` → `DEV_KIT_*`、`work` → `WORK_*` |
| サフィックスは制御する挙動を表す | `_TTL`、`_LANG`、`_BASE_BRANCH` |

プレフィックスにより、プラグイン間での変数名衝突を防ぐ。

---

## CLAUDE.md / スキル内でのドキュメント化

プラグインやスキルが環境変数による設定をサポートする場合、テーブルで一覧する:

```markdown
## 環境変数

| 変数 | 効果 | デフォルト |
|------|------|-----------|
| `${WORK_BASE_BRANCH}` | ワークツリー作成時のベースブランチ | `master` |
| `${MY_KIT_INJECTION_TTL}` | リファレンスを再注入するまでの秒数 | `3600` |
```

テーブル内でも `${}` 表記を使う — 値は外部から設定するものであり、ハードコードしないことを示す。

---

## 実行コード（フック / スクリプト）内

`${...}` 表記はシェルと Python に直接対応する:

**Bash**
```bash
base="${WORK_BASE_BRANCH:-master}"   # $VAR_NAME でも ${VAR_NAME} でも有効
```

**Python**
```python
base = os.environ.get("WORK_BASE_BRANCH", "master")   # $ や {} なし — プレーン文字列キー
```

コード内では変数名はプレーン文字列（`"WORK_BASE_BRANCH"`）。`${}` 表記は人間が読む指示文書専用。

---

## まとめ

| 場面 | 書き方 |
|------|--------|
| 指示文書（SKILL.md・ルール・CLAUDE.md・プロンプト） | `` `${VAR_NAME}` `` |
| Bash コマンド | `${VAR_NAME}` または `$VAR_NAME` |
| Python `os.environ.get` | `"VAR_NAME"`（プレーン文字列） |
| テーブルの見出し / カラム値 | `` `${VAR_NAME}` `` |
