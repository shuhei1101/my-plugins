# Environment Variable Notation in Claude Artifacts

How to write and document environment variable names consistently in Claude-read artifacts
(skills, rules, CLAUDE.md, hooks/prompts, references).
Japanese mirror: `references/common/環境変数記法.jp.md`

---

## Notation rule: always use `${VAR_NAME}`

When referring to an environment variable **by name** anywhere in a Claude-read document
(SKILL.md, rules, CLAUDE.md, prompt files, references), always write it as `${VAR_NAME}`:

```markdown
The skill reads `${WORK_BASE_BRANCH}` to determine which branch to check out.
Set `${MY_KIT_INJECTION_TTL}` to control the cache duration.
```

**Why `${...}` and not bare `VAR_NAME`**:
- Visually distinct — the reader immediately recognises it as an env var.
- Consistent with shell syntax — Claude can copy the name directly into a Bash command.
- Unambiguous — `WORK_BASE_BRANCH` without `${}` reads as a string literal, not a variable reference.

> Markdown files are loaded into context, not executed — `${VAR_NAME}` in text is **notation only**.
> The actual value is set in `settings.json` and read by hooks/scripts via `os.environ`.

---

## Naming convention

| Rule | Example |
|------|---------|
| ALL_CAPS_SNAKE_CASE | `WORK_BASE_BRANCH`, `DEV_KIT_INJECTION_TTL` |
| Prefix with the plugin name (upper-cased, non-alphanumeric → `_`) | `dev-kit` → `DEV_KIT_*`, `work` → `WORK_*` |
| Suffix describes the controlled behaviour | `_TTL`, `_LANG`, `_BASE_BRANCH` |

The prefix keeps variables namespaced so different plugins don't collide.

---

## Documenting in CLAUDE.md / skills

When a plugin or skill supports configuration via env vars, list them in a table:

```markdown
## Environment Variables

| Variable | Effect | Default |
|----------|--------|---------|
| `${WORK_BASE_BRANCH}` | Base branch used when creating worktrees | `master` |
| `${MY_KIT_INJECTION_TTL}` | Seconds before a reference is re-injected | `3600` |
```

Include the `${}` notation in the table — it signals that the value must be set externally,
not hard-coded.

---

## In executable code (hooks / scripts)

The `${...}` notation maps directly to shell and Python:

**Bash**
```bash
base="${WORK_BASE_BRANCH:-master}"   # $VAR_NAME and ${VAR_NAME} are both valid
```

**Python**
```python
base = os.environ.get("WORK_BASE_BRANCH", "master")   # no $ or {} — plain string key
```

In code, the variable name is a plain string (`"WORK_BASE_BRANCH"`); `${}` notation is only
for human-readable instruction text.

---

## Summary

| Context | Write as |
|---------|----------|
| Instruction text (SKILL.md, rules, CLAUDE.md, prompts) | `` `${VAR_NAME}` `` |
| Bash command | `${VAR_NAME}` or `$VAR_NAME` |
| Python `os.environ.get` | `"VAR_NAME"` (plain string) |
| Table header / column label | `` `${VAR_NAME}` `` |
