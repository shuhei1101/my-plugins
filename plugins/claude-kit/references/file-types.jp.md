# Claude Code ファイルタイプ使い分けガイド

`.claude/` 配下で使えるファイルタイプ（CLAUDE.md / rules / skills / hooks / references）の
使い分けを定義する。各 creator スキルおよび claude-refactor の共通参照ドキュメント。

---

## 一覧表：いつ何を使うか

| ファイルタイプ | いつ読まれるか | 何を書くか |
|---|---|---|
| `CLAUDE.md`（ルート） | セッション開始時・必ず | プロジェクト全体の規約・ワークフロー。**極力薄く保つ** |
| `CLAUDE.md`（サブフォルダ） | そのフォルダにアクセスしたとき | フォルダの説明・ローカル規約（co-location 重視） |
| `.claude/rules/<name>.md` | `paths:` に一致するファイルを読んだとき | クロスパスリンク・更新漏れ防止。単一フォルダも可（一覧性重視） |
| `.claude/skills/<name>/SKILL.md` | 呼び出されたとき | 複数ステップのワークフロー・手順 |
| `.claude/hooks/` + `settings.json` | 特定イベント発火時（自動） | 自動チェック・通知・プロンプト注入 |
| `.claude/references/<name>.md` | 必要なときに手動で読む | CLAUDE.md に書きたいが毎回読む必要のない詳細説明・参考資料 |

---

## CLAUDE.md

### 読み込みタイミング

| 配置場所 | 読み込みタイミング |
|---|---|
| プロジェクトルート | セッション開始時に**必ず**読み込まれる |
| サブフォルダ | そのフォルダ内のファイルを Claude が読み込んだとき（遅延ロード） |

サブフォルダの CLAUDE.md はセッション開始時には読み込まれない。
そのフォルダに Claude がアクセスした瞬間にロードされる。

### 用途

- フォルダ配下の全体的な説明・役割・規約
- そのフォルダで守るべき一般的な作業ルール

### 重要: 極力薄く保つ

ルートの CLAUDE.md は**毎回必ずロードされる**ため、内容が増えるほどコンテキストを圧迫する。
以下の原則で薄く保つ:

| 内容の性質 | 対処 |
|---|---|
| 特定ファイル編集時にのみ必要 | `.claude/rules/` に移す |
| 複数ステップのワークフロー | `.claude/skills/` に移す |
| 特定フォルダだけに関係 | そのサブフォルダの `CLAUDE.md` に移す |
| 詳細説明・参考資料（たまに読めばよい） | `.claude/references/` に移し、CLAUDE.md にはパスだけ書く |
| プロジェクト内に既にある仕様書 | パスだけ書き、内容は書かない |

### NG

- フォルダの説明・規約でなく、多ステップのワークフロー → `.claude/skills/` が適切
- 毎回読む必要のない詳細説明 → `.claude/references/` に外出し

## `.claude/rules/`（パススコープルール）

### 読み込みタイミング

`paths:` パターンに一致するファイルを Claude が**読み込んだとき**にロードされる。

- ✅ ファイルを読む → ロードされる
- ✅ ファイルを編集する（編集前に読むため） → ロードされる
- ❌ `mv` / `rm` 等のシェルコマンドのみ → ロードされない
- ❌ ファイルを参照せず別の作業をする → ロードされない

### ルールの2種類

ルールには目的の異なる2種類がある:

#### ① リンクルール（ファイル連携型）

関連するファイル群を束ねて「1つを編集したら他も確認する」という連携を強制するルール。

- `paths:` に連携させたいファイル群すべてを列挙する
- 例: 抽象クラス・インターフェース・子クラス・親クラスをまとめて1つのルールに
- 例: 設定ファイル・仕様書・テストケース・実装コードを紐づける
- **効果**: どれか1つを編集したとき、Claude が全体像を把握した状態で作業できる

#### ② コンテキストルール（読み込みトリガー型）

特定の作業エリアを触ったときに、必要な知識・仕様書・ガイドラインを自動ロードするルール。

- `paths:` に「このファイルを触ったとき読ませたいルールと紐づくファイル」を設定する
- 例: `config/` フォルダを触ったとき → 設定仕様書のルールが読み込まれる
- 例: `src/` 配下を触ったとき → コーディング規約ルールが読み込まれる

### ユースケース思考で `paths:` を設計する

**「いつ読まれたいか」を起点に考える。**

1. **ユースケースを特定する** — このルールが役に立つのはどんな作業をしているとき？
2. **トリガーとなるファイル/フォルダを特定する** — その作業では必ずどのファイルを触るか？
3. **そのファイルを `paths:` に設定する** — 触るたびにルールが読み込まれる

**例 — 設定仕様書のコンテキストルール**:
- ユースケース: 設定ファイルを触るとき、対応する仕様書を読んでほしい
- トリガー: `config/` フォルダを編集するとき
- `paths:` に `config/**` を設定 → 設定ファイルを触るたびに仕様書ルールがロードされる

**例 — 常時読み込みが必要なルール**:
- ユースケース: どんな作業中も守ってほしいルール（コーディング規約など）
- トリガー: 任意のソースコードを触るとき
- `paths:` に `src/**` や `**/*.ts` など広いパターンを設定

### 用途

**更新漏れを防ぐための横断リンク**が主目的（リンクルール）、
または特定作業エリアへの知識注入（コンテキストルール）。

### 統合・分離の注意点

- **統合**: 同じドメインを扱う重複ルールは統合してよい
- **分離**: 無関係なドメインを1つのルールにまとめてはいけない
  - `paths:` が無関係なフォルダを含む → 触れるたびに不要なコンテキストが読み込まれる
  - 1ドメイン = 1ルールファイルを原則とする

### 単一フォルダ内容の置き場：`.claude/rules/` vs サブフォルダ `CLAUDE.md`

| 優先したいこと | 選択 |
|---|---|
| **全ルールを一箇所で把握したい**（監査・一覧性重視） | `.claude/rules/<name>.md` |
| **コードに隣接してルールを置きたい**（co-location 重視） | サブフォルダ `CLAUDE.md` |

複数の異なるフォルダをまたぐリンク（「X を変えたら別フォルダの Y も更新」）は常に `.claude/rules/` に書く。

## `.claude/skills/`

### 読み込みタイミング

- `/skill-name` で明示的に呼んだとき
- `description` フロントマターの条件に一致したとき（自動起動）

`disable-model-invocation: true` は基本使わない。
ただし **人間のみが明示的に実行すべきスキル**（マージ・デプロイ・削除など破壊的操作）には付ける。

### 用途

複数ステップから成る作業手順・ワークフローを定義する。

### 使うべき場面

- 3ステップ以上、ユーザー確認ポイントあり、分岐あり → スキル
- PR作成フロー・ドキュメント作成手順・情報収集などのルーティン作業

### NG

- シンプルなルール（1〜2行で書ける内容）→ `CLAUDE.md` か `.claude/rules/`
- ファイル同期リマインダー → `.claude/rules/`

## `.claude/hooks/`（プロンプト注入型フック）

### 読み込みタイミング

`settings.json` に登録したイベントが発火したとき、自動的にプロンプトを Claude のコンテキストへ注入する。

### フックイベントと用途

| イベント | 発火タイミング | 用途 |
|---|---|---|
| `UserPromptSubmit` | ユーザーがプロンプトを送信するたびに | 毎回確認させたいルール・チェックリスト |
| `Stop` | Claude が応答を止めるたびに | 作業完了後のチェック・後処理の強制 |
| `PreToolUse` | ツール実行前 | 危険な操作のブロック・確認 |
| `PostToolUse` | ツール実行後 | 編集後の通知・検証 |
| `SessionStart` | セッション開始時 | 初期コンテキストの注入 |

### hooks 化すべきケース

rules / CLAUDE.md に以下の性質の内容があれば、hooks に移した方が効果的:

- 「プロンプト送信のたびに確認する」「毎回チェックする」 → `UserPromptSubmit`
- 「Claude が止まるたびに〜する」「作業完了後に確認する」 → `Stop`
- 「ツール実行前に確認する」 → `PreToolUse`
- 「ファイル編集後に通知する」 → `PostToolUse`

### NG

- 一度だけ確認すればよい内容 → hooks は毎回発火するため過剰
- 長文プロンプト → `Stop` フックの `reason` はユーザー画面に表示されるため極力短くする

## `.claude/references/`

### 読み込みタイミング

自動ロードなし。Claude が必要なときに手動で読み込む。

### 用途

CLAUDE.md に書きたいが毎回読む必要はない内容（詳細仕様・補足説明・参考資料）を置く場所。
CLAUDE.md には「詳細は `.claude/references/xxx.md` を参照」とパスだけ書き、
Claude が必要なときに読む形にする。

### 使うべき場面

- 詳細な仕様書・設計資料
- 使い方ガイド・チュートリアル
- creator スキルなどの共通参照知識（このファイル自体がその例）

## JP/EN ミラーのルール

すべてのファイルには対応する JP ミラーが必要:

| 英語ファイル（Claude が読む） | JP ミラー（人間向け参照用） |
|---|---|
| `.claude/rules/<name>.md` | `.claude/rules-jp/<name>.md` |
| `.claude/skills/<name>/SKILL.md` | `.claude/skills/<name>/SKILL.jp.md` |
| `CLAUDE.md`（任意のフォルダ） | 同フォルダの `CLAUDE.jp.md` |
| `.claude/references/<name>.md` | `.claude/references/<name>.jp.md` |

**変更手順**: JP ミラーを先に更新し、その後英語版に反映する。
