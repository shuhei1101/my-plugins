# Provenance Stamping Guide

How to stamp a generated/edited file with provenance metadata so
`claude-kit:version-sync` can later detect files produced by an older plugin version.
This guide is self-contained: when it is injected (because you are editing a stampable file),
follow it to write the stamp directly — no skill call needed.
Japanese mirror: `references/provenance.jp.md`

> For files Claude does **not** write via Write/Edit (e.g. helper-script output, or file types not
> covered by the injection hook), the `/claude-kit:mark-generated` thin-wrapper skill applies this
> same spec and returns the stamp string. The spec below is the single source of truth either way.

---

## What to write

A one-line comment at the **top of the file body**, in the notation matching the file extension:

| Extension / pattern | Comment format |
|---|---|
| `*.md` | `<!-- Generated by {plugin}/{skill} v{version} -->` |
| `*.html` | `<!-- Generated by {plugin}/{skill} v{version} -->` |
| `*.py` | `# Generated by {plugin}/{skill} v{version}` |
| `*.sh` | `# Generated by {plugin}/{skill} v{version}` |
| `*.yaml` / `*.yml` | `# Generated by {plugin}/{skill} v{version}` |
| `*.js` | `// Generated by {plugin}/{skill} v{version}` |
| `*.css` | `/* Generated by {plugin}/{skill} v{version} */` |
| `*.j2` | `{# Generated by {plugin}/{skill} v{version} #}` (or, for ref-inject templates, the existing `<!-- Generated by ref-inject/apply -->` HTML marker is acceptable) |
| `*.json` | **none** — JSON disallows comments; skip stamping |

- `{plugin}` / `{skill}` = the plugin and skill (or generating source) that produced the file.
- `{version}` = the `version` field of `plugins/{plugin}/.claude-plugin/plugin.json`. Read it; do not guess.

---

## Where to place it

- If the file has YAML frontmatter (`---` … `---`): insert **immediately after the closing `---`**.
- If the file has no frontmatter: insert at the **very top**.
- **Never** insert before the frontmatter — an HTML comment before `---` breaks Markdown frontmatter
  detection (the `---` renders as a horizontal rule instead of being parsed as frontmatter).
- If a `Generated by …` line of the matching notation already exists at that position, **replace that
  single line** instead of adding a duplicate.

---

## JP mirror files (`*.jp.md`)

In addition to the metadata line, add this warning line directly beneath it (Markdown only):

```
<!-- This file is a Japanese mirror. When updating the English original, update this file too. -->
```

---

## Examples

- `SKILL.jp.md` (claude-kit / skill-creator): two HTML-comment lines — the `Generated by claude-kit/skill-creator v{version}` line, then the JP-mirror warning line — both right after the closing `---`.
- `TODO.md` (work-kit / work-start): single HTML-comment line `Generated by work-kit/work-start v{version}` at the top.
- `stop.py` (claude-kit / hook-creator): single `#`-comment line `Generated by claude-kit/hook-creator v{version}`.

---

## Why

`version-sync` reads these stamps to find artifacts generated by an outdated plugin version and bring
them up to date. A missing or wrong stamp makes an outdated file invisible to that sync.
