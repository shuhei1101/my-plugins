# *-kit リファレンス注入構造の同期

`dev-kit` と `claude-kit` はリファレンス自動注入構造を共有している。片方の構造を変更したら、
**必ず同じコミットで他方も更新すること**。
英語原文: `references/hook/キットフック同期.md`

---

## 共有している構造

両 kit は同一の注入インフラを共有している:

| ファイル | 役割 |
|---|---|
| `plugins/*-kit/hooks/scripts/inject_references.py` | フック本体（ロジックは同じ、env var 名とログタグだけ異なる） |
| `plugins/*-kit/hooks/scripts/_common.py` | 共通ヘルパー（関数は同一、ENV_PREFIX のみ異なる） |
| `plugins/*-kit/hooks/hooks.json` | PreToolUse 登録（同一フォーマット） |
| `plugins/*-kit/hooks/templates/injection.md.j2` | 注入テンプレート英語版（プラグイン名だけ異なる） |
| `plugins/*-kit/hooks/templates/injection.jp.md.j2` | 注入テンプレート日本語版 |
| `plugins/*-kit/references/_index.yaml` | リファレンス一覧（英語）: `references:` 配列 path + description |
| `plugins/*-kit/references/_index.jp.yaml` | リファレンス一覧 JP ミラー |
| `plugins/*-kit/references/_injection_rules.yaml` | pattern → required/optional マッピング |
| `plugins/*-kit/references/CLAUDE.md` | 「_index.yaml を読め」インデックス形式 |
| `plugins/*-kit/references/CLAUDE.jp.md` | CLAUDE.md の JP ミラー |

構造（フォーマット・パース仕様・テンプレート変数・YAML スキーマ）は両 kit で完全に揃っている前提でフックが動く。

## 共有構造を変更するとき

いずれかの kit の注入機構を変更したとき:

- [ ] `inject_references.py` の関数/変数/env var 規約（`{PLUGIN}_INJECTION_*`）が両 kit で一致しているか
- [ ] `hooks.json` の matcher/command 構造が一致しているか
- [ ] テンプレートの変数名（`file_path`, `required`, `optional`, `ref.path`, `ref.description`, `ref.body`）と Jinja2 制御構文が一致しているか
- [ ] `_index.yaml` の YAML スキーマ（`references:` 配列、`path` + `description` キー名）が一致しているか
- [ ] `_injection_rules.yaml` の YAML スキーマ（`rules:` 配列、`pattern` + `required` + `optional` キー名）が一致しているか
- [ ] `references/CLAUDE.md` (+ jp) の管理セクションが一致しているか

**コンテンツのみの変更**（リファレンスエントリ追加、パターン追加）は cross-kit 更新不要。
ただしキー名・型・命名規約が変わる場合は構造変更扱い。

## 禁止事項

- 片方の kit の `inject_references.py` だけ変更してもう片方を放置（フックが壊れるか動作が分裂する）
- `_injection_rules.yaml` のキー名を一方だけリネームする
- 片方の kit の注入フックにだけ便利機能を追加する
