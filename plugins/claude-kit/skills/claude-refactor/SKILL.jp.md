# claude-refactor — Claude 設定全体の監査・整理

`.claude/` 配下の rules / skills / CLAUDE.md / hooks を横断的に監査し、
フォルダ構成の整備・重複の統合・ファイルタイプ間の移管を提案するスキル。

---

## 概要

Claude 設定はプロジェクトが育つにつれて自然に肥大化する。
このスキルは以下をまとめて診断し、整理案をユーザーに提示する:

1. **rules** — フォルダ構成の整備、重複・統合・CLAUDE.md/hook 移管の提案
2. **skills** — 重複・統合・分割の提案
3. **CLAUDE.md** — 肥大化の検出と rules/skills への切り出し提案
4. **hooks** — rules/CLAUDE.md の中でフックに移すべき内容の提案

どのスコープを整理するかはユーザーが選択できる。
全スコープを一括で実行することも、特定スコープのみ実行することも可能。

---

## 作業内容

### ステップ1: スコープを確認する

#### 条件

- 常に — 他の何より先に実行する

#### 処理内容

1. ユーザーが整理したいスコープを確認する:
   - 全スコープ（rules + skills + CLAUDE.md + hooks）
   - rules のみ
   - skills のみ
   - CLAUDE.md のみ
   - 複数を組み合わせ

2. ユーザーが明示しない場合は「全スコープ」を提案する

→ ステップ2へ進む

#### 出力

- 整理対象のスコープ一覧

---

### ステップ2: 対象ファイルを収集する

#### 条件

- ステップ1 完了

#### 処理内容

選択されたスコープに応じて以下を収集する:

| スコープ | 収集対象 |
|---|---|
| rules | `.claude/rules/**/*.md` を glob し、各ファイルの冒頭30行を読む |
| skills | `.claude/skills/**/SKILL.md` を glob し、`name` / `description` フロントマターと概要を読む |
| CLAUDE.md | プロジェクトルートおよびサブフォルダの `CLAUDE.md` を列挙し行数を確認する |
| hooks | `.claude/settings.json` / `.claude/settings.local.json` / `hooks/hooks.json` の hooks セクションを読む |

→ ステップ3へ進む

#### 出力

- 収集済みファイルの一覧と概要サマリー

---

### ステップ3: rules を分析する（rules スコープ選択時）

#### 条件

- ステップ2 完了 かつ rules スコープが選択されている

#### 処理内容

以下の観点で各ルールを分析する:

##### 3-A: フォルダ構成の整備

1. `.claude/rules/` 直下にフラットな `.md` ファイルが多い場合、サブフォルダへの整理を提案する
2. §参考資料 / フォルダ構成の判断基準 に従ってフォルダ候補を決定する

##### 3-B: 重複・統合の検出

1. 複数のルールで同じ `paths:` パターンや同じドメインを扱っているものを特定する
2. 内容が大きく重複しているルールを「統合候補」としてマークする
3. 内容は異なるが同一ドメイン（例: `models` に関する2つのルール）は「まとめ検討」としてマークする

##### 3-C: ファイルタイプの適切性チェック

各ルールについて §参考資料 / ファイルタイプ判断基準 の表で確認する:

- **CLAUDE.md に移すべき**: プロジェクト全体の常時ロードが必要な1〜2行の指示
- **hooks に移すべき**: 「〜したとき自動で実行する」「Claude が止まるたびに確認する」という性質
- **skill に移すべき**: 複数ステップのワークフローが含まれている
- **rules として適切**: 複数フォルダをまたぐファイル同期リンク

→ ステップ4へ進む（または次のスコープへ）

#### 出力

- フォルダ構成案
- 統合候補一覧
- ファイルタイプ移管候補一覧

---

### ステップ4: skills を分析する（skills スコープ選択時）

#### 条件

- ステップ2 完了 かつ skills スコープが選択されている

#### 処理内容

以下の観点で各スキルを分析する:

##### 4-A: 重複・統合の検出

1. `description` フロントマターのトリガー条件が類似しているスキルを特定する
2. ステップ構成が類似しているスキルを「統合候補」としてマークする
3. 統合を提案する場合、どちらをベースにするかも提案する

##### 4-B: 分割の検討

1. 200行超のスキルを「分割検討」としてマークする
2. 1つのスキルが複数の無関係なユースケースをカバーしている場合に分割を提案する

##### 4-C: ファイルタイプの適切性チェック

各スキルについて §参考資料 / ファイルタイプ判断基準 の表で確認する:

- **rule に移すべき**: ワークフローよりファイル同期リンクが主体
- **CLAUDE.md に移すべき**: 1〜2行で表現できるシンプルな指示
- **skill として適切**: 複数ステップ・ユーザー確認・分岐がある

→ ステップ5へ進む（または次のスコープへ）

#### 出力

- 統合候補一覧（どちらがベースか含む）
- 分割候補一覧
- ファイルタイプ移管候補一覧

---

### ステップ5: CLAUDE.md を分析する（CLAUDE.md スコープ選択時）

#### 条件

- ステップ2 完了 かつ CLAUDE.md スコープが選択されている

#### 処理内容

以下の観点で各 CLAUDE.md を分析する:

##### 5-A: 肥大化の検出

1. 200行超の CLAUDE.md を「肥大化」としてマークする
2. 肥大化している場合、切り出し先（rules / skills / サブフォルダ CLAUDE.md）を提案する

##### 5-B: 内容の適切性チェック

各セクションについて §参考資料 / ファイルタイプ判断基準 の表で確認する:

- **rules に移すべき**: 特定ファイル編集時にのみ読み込めばよいクロスパスリンク
- **skill に移すべき**: 複数ステップのワークフロー・手順
- **サブフォルダ CLAUDE.md に移すべき**: 特定ディレクトリにのみ関係する内容
- **CLAUDE.md（ルート）に残すべき**: プロジェクト全体で常に必要なワークフロー・規約

→ ステップ6へ進む（または次のスコープへ）

#### 出力

- 肥大化している CLAUDE.md の一覧と行数
- セクション別の移管提案

---

### ステップ6: hooks を分析する（hooks スコープ選択時）

#### 条件

- ステップ2 完了 かつ hooks スコープが選択されている

#### 処理内容

以下の観点を分析する:

##### 6-A: hooks 化の候補発見

rules / CLAUDE.md の内容をスキャンし、以下の性質を持つものを「hooks 化候補」としてマークする:

| 性質 | フックイベント候補 |
|---|---|
| 「プロンプト送信のたびに確認する」「毎回チェックする」 | `UserPromptSubmit` |
| 「Claude が止まるたびに〜する」「作業完了後に確認する」 | `Stop` |
| 「ツール実行前に確認する」 | `PreToolUse` |
| 「ファイル編集後に通知する」 | `PostToolUse` |

##### 6-B: 既存 hooks の冗長性チェック

1. 同じイベントに複数のフックが登録されている場合、統合を提案する
2. 使われていないフック定義があれば削除を提案する

→ ステップ7へ進む

#### 出力

- hooks 化候補（現在の場所 → 移管先フックイベント）
- 既存 hooks の冗長性レポート

---

### ステップ7: 提案をまとめてユーザーに提示する

#### 条件

- 選択したスコープの分析がすべて完了

#### 処理内容

1. 以下のカテゴリ別に提案を整理する:

   **フォルダ構成の変更**（rules のみ）
   | ファイル（現在） | 移動先 | 理由 |
   |---|---|---|
   | ... | ... | ... |

   **統合・統廃合の提案**
   | 対象 | タイプ | 提案 | 理由 |
   |---|---|---|---|
   | ... | rule/skill | 統合先: `{name}` | ... |

   **ファイルタイプの移管提案**
   | 対象（現在） | 移管先タイプ | 理由 |
   |---|---|---|
   | ... | rule/skill/CLAUDE.md/hook | ... |

   **分割の提案**（skills のみ）
   | 対象スキル | 分割案 | 理由 |
   |---|---|---|
   | ... | `{name-a}` + `{name-b}` | ... |

2. 提案が0件のスコープは「問題なし」と報告する
3. ユーザーに「すべて実行する」「個別に選ぶ」「キャンセル」を確認する

→ ユーザーの確認を待つ

#### 出力

- 全提案の一覧
- ユーザーの実行指示

---

### ステップ8: ユーザーの選択を確認する

#### 条件

- ステップ7 でユーザーに提案済み

#### 処理内容

1. ユーザーが「すべて実行」を選択した場合: 全提案を実行する
2. ユーザーが個別に選択した場合: 選択された提案のみ実行する
3. 各提案についてユーザーが修正を加えた場合は修正を反映する

→ ステップ9へ進む

---

### ステップ9: 実行する

#### 条件

- ステップ8 でユーザーの確認が取れた

#### 処理内容

確定した作業を実行する:

| 作業タイプ | 実行方法 |
|---|---|
| rules フォルダ構成の変更 | `git mv` でファイルを移動し、各フォルダに `_overview.md` を生成する |
| rules の統合 | ベースファイルに内容を統合し、古いファイルを `git rm` する |
| skills の統合 | ベーススキルに内容を統合し、古いフォルダを `git rm` する |
| skills の分割 | 新しいスキルフォルダを作成し、内容を分割する |
| CLAUDE.md の切り出し | 対象セクションを新しい rules/skill ファイルに移し、CLAUDE.md から削除する |
| hooks 化 | `hook-creator` を呼び出してフックを作成し、元の rules/CLAUDE.md から内容を削除する |
| ファイルタイプ変換 | 対応するクリエータースキルを呼び出して変換する |

→ ステップ10へ進む

#### 補足

##### 禁止事項

- `cp` でなく `git mv` を使うこと（git 履歴を保持するため）
- 参照元（他のスキル・ルールからの言及）を更新し忘れないこと

---

### ステップ10: 結果を報告する

#### 条件

- ステップ9 完了

#### 処理内容

1. 変更したファイルの一覧を報告する
2. 生成・削除したファイルの一覧を報告する
3. コミット確認をユーザーに促す

## 参考資料

### フォルダ構成の判断基準

#### 必須フォルダ

| フォルダ | 役割 | 何を入れるか |
|---|---|---|
| `core/` | プロジェクト全体の基礎ルール | コーディング規約・ワークフロー・環境設定・開発プロセス全般 |
| `feature/` | 機能別ドメイン知識 | 機能単位の実装ルール・仕様・設計判断（1機能 = 1ファイル） |

#### 任意フォルダの判断基準

| フォルダ | 追加する目安 |
|---|---|
| `ui/` | `components/`・`pages/`・`views/` などフロントエンドが存在する |
| `api/` | バックエンド API のルールが多い / `routes/`・`handlers/` がある |
| `infra/` | Docker・CI/CD・デプロイ系のルールが多い |

---

### ファイルタイプ判断基準

| 内容の性質 | 最適なファイルタイプ | 理由 |
|---|---|---|
| 複数の異なるフォルダをまたぐファイル同期リンク | **rule** | パスマッチで対象ファイル編集時にのみ自動ロード |
| 単一フォルダ内のファイル一覧・ローカル規約 | rule または サブフォルダ CLAUDE.md | 一覧性重視なら rule、co-location 重視なら CLAUDE.md |
| プロジェクト全体で常に必要な短いワークフロー・禁止事項 | **CLAUDE.md（ルート）** | セッション開始時に必ず読み込まれる |
| 複数ステップ・ユーザー確認・分岐があるワークフロー | **skill** | オンデマンド呼び出し、コンテキストを汚染しない |
| 「〜のたびに自動チェック/通知」という繰り返し処理 | **hook** | イベント発火で自動実行、Claude のコンテキストに注入 |
| 1〜2行のシンプルな指示・注意事項 | CLAUDE.md または rule | スキルにするほど複雑でない |

---

### skills 分析の判断基準

| 条件 | 提案 |
|---|---|
| `description` のトリガーが別のスキルと大きく重複する | 統合候補 — どちらがユースケースを包含しているか確認 |
| ステップ数が2以下で分岐なし | rule または CLAUDE.md への移管候補 |
| 200行超 かつ 複数の無関係なユースケースを含む | 分割候補 — ユースケースごとに別スキルへ |
| 別のスキルの Step N として既に呼ばれている | デリゲート関係を明記し、単独スキルとしての `description` を削除または限定する |

---

### `_overview.md` テンプレート（rules フォルダ用）

```markdown
# {フォルダ名} — {カテゴリの一行説明}

## このフォルダについて

{このカテゴリに含まれるルールの方針を1〜3文で}

## ファイル一覧

| ファイル | 内容 |
|---|---|
| `{file}.md` | {1行説明} |
```
