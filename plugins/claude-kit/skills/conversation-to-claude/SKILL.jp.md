# conversation-capture — 会話履歴からアーティファクトを生成

会話履歴を分析してセッション中に積み上げた知識・手順を最適な形で永続化する。
アーティファクト種別（スキル・ルール・フック・CLAUDE.md）を提案し、
ユーザーが選択したものを対応するクリエイタースキルで実装する。

---

## 概要

実装・調査・設定変更を終えた後「この手順を次も使いたい」「この知識を残したい」と感じる場面は多い。
しかし何の形式で残すべきか迷いやすい。このスキルは会話内容を分析して適切な形式を提案し、
ユーザーが選んだものを自動的に生成する。

---

## タスク

### ステップ 0: クリエイタースキルを事前に読む

#### 条件

- 常時 — 最初に実行（提案前に必ず完了させる）

#### 処理

1. 以下のクリエイタースキルを読み込み、提案に必要な知識を把握しておく:
   - `claude-kit:skill-creator` — スキルの設計方針（トリガー、ステップ構造）
   - `claude-kit:rule-creator` — 良いルールの条件（パス、ファイル依存リンク）
   - `claude-kit:claude-creator` — CLAUDE.md が適切な場面とルールとの使い分け
   - `claude-kit:hook-creator` — 利用可能なフックイベントとできること

→ ステップ 1 へ

#### 出力

- クリエイタースキルの内容をコンテキストに読み込み済み

---

### ステップ 1: 会話履歴を分析する

#### 条件

- ステップ 0 完了

#### 処理

1. セッション**全体**の会話を振り返り、**余すことなくすべての候補**を抽出する。
   網を広く張ること — 多すぎる提案は削れるが、見落としは取り戻せない。

   **A. 繰り返し作業フロー候補**（スキル向け）
   - 3ステップ以上の手順でユーザーとの対話・分岐を含むもの
   - 「他のプロジェクトでも使いたい」と感じるパターン
   - 繰り返し発生しうる調査・セットアップの流れ

   **B. ファイル依存・パス構成の知識**（ルール向け）
   - **主要ユースケース**: 「ファイルXを読んだ/編集したら必ずファイルYも確認する」— ルールは `paths:` に一致するファイルを Claude が読んだ瞬間に自動ロードされるため、セットで確認すべきファイルを常に一緒に提示できる
   - 「設定はここ」「ルーティングはここ」といったパス役割の把握
   - セッション中に発見した「セットで確認すべき」「常に同期を保つべき」パターン
   - 注意: `paths:` はファイルを**読んだ時**に発動し、mv/rm などのシェルコマンドでは発動しない — そのドメインで Claude が実際に開くファイルのパターンを設定する

   **C. 特定イベントへの自動反応**（フック向け）
   - ツール使用前後・セッション開始時に毎回実行したいチェックや処理
   - 「毎回このコマンドの前に確認したい」というパターン
   - 関連するイベントで毎回発火させたいバリデーション・通知

   **D. プロジェクト全体の規約・ガイドライン**（CLAUDE.md向け）
   - 禁止事項・命名規則・設計方針など全ファイルに適用するルール
   - 「これは CLAUDE.md に書いておくべき」という知識
   - 新しいメンバーがミスを避けるために必要な前提知識

   **E. 再発防止の教訓**（`incidents` ルール向け）
   - コマンドや操作を試みたが失敗し、原因・正解が判明したもの
   - 思い込みで進めたが実際は違った、という認識の誤り
   - 「同じミスを繰り返さないために記録したい」と感じる気づき

   **F. プロジェクト固有の用語**（`glossary` ルール向け）
   - ユーザーが会話中に使ったプロジェクト固有の名詞・略語・概念
   - 既存の `glossary.md` に載っていない、または定義があいまいなもの
   - 一般的でないため、知らないと誤解しやすい言葉

→ ステップ 2 へ

#### 出力

- 各カテゴリの抽出結果（内部リスト）— 多めに含めること

---

### ステップ 2: アーティファクト種別を提案する

#### 条件

- ステップ 1 完了

#### 処理

1. 抽出したすべての候補を**余すことなく提案**する — 2〜3件に絞らない。
   絞り込みはユーザーが行う。同じカテゴリに複数の異なる候補がある場合（例: 2つの別々のルール）は、それぞれ個別の提案として列挙する。

   提案フォーマット:
   ```
   今回の会話から以下のアーティファクトを作成できます:

   【提案 A】スキル — {スキル名候補}
   理由: {なぜスキルが適切か}
   生成物: .claude/skills/{name}/SKILL.md

   【提案 B】ルール — {ルール名候補}
   理由: {なぜルールが適切か}
   リンクするファイル: {編集時にセットで確認すべきファイル群}
   paths（読んだ時に発動）: {このルールを自動ロードしたいファイル/ディレクトリのパターン (例: src/**, *.ts, plugins/**)}
   生成物: .claude/rules/{name}.md

   【提案 C】フック — {フック名候補}
   理由: {なぜフックが適切か}
   生成物: settings.json への hooks エントリ

   【再発防止】incidents に追記
   概要: {今回の教訓を1〜2行で}
   生成物: .claude/rules/incidents.md（インデックス）＋ .claude/references/incidents/{slug}.md（詳細）

   【用語集】glossary に以下の用語を追加してよいですか？
   - {term1}: {定義}
   - {term2}: {定義}
   生成物: .claude/rules/glossary.md

   どれを作成しますか？（複数選択可）
   ```

   > **注意**: E（再発防止）は A〜D に当てはまらない教訓のみを対象とする。
   > F（用語集）の提案は、用語候補がある場合のみ表示する。

2. 抽出できるものがない場合:
   - 「今回の会話から永続化できる知識・手順は見つかりませんでした」と報告して終了

→ ユーザーの選択後、ステップ 3 へ

#### 出力

- ユーザーが選択したアーティファクト種別（1つ以上）

#### 参考: 種別の判定基準

| 種別 | 適した内容 |
|---|---|
| スキル | 3ステップ以上の繰り返し作業フロー、ユーザーとの対話を含む手順 |
| ルール | 「ファイルXを読んだらYも確認」— `paths:` に一致するファイルを Claude が読んだ瞬間に自動ロードされるファイルリンクルール |
| フック | 特定イベントへの自動反応（ツール使用前後・セッション開始等） |
| CLAUDE.md | プロジェクト全体に適用する規約・禁止事項・設計方針 |
| incidents | 失敗・誤解・思い込みの修正など再発防止が目的の教訓 |
| glossary | プロジェクト固有の用語・略語・概念 |

---

### ステップ 3: 選択されたアーティファクトを実装する

#### 条件

- ステップ 2 でユーザーが種別を選択

#### 処理

選択された種別ごとに対応するクリエイタースキルを起動し、処理を委譲する:

| 選択種別 | 起動するスキル | 渡す情報 |
|---|---|---|
| スキル | `claude-kit:skill-creator` | スキル名候補・トリガー条件・抽出した作業フロー |
| ルール | `claude-kit:rule-creator` | ドメイン名・ファイルリスト・依存関係の説明 |
| フック | `claude-kit:hook-creator` | フック名・対象イベント・実行したい処理の説明 |
| CLAUDE.md | `claude-kit:claude-creator` | 追記・作成したいガイドライン内容 |
| incidents | （スキルを起動しない） | `.claude/rules/incidents.md` のインデックスに概要を1行追記し、`.claude/references/incidents/{slug}.md`（+ `.jp.md`）に詳細を記録する |
| glossary | （スキルを起動しない） | `.claude/rules/glossary.md` を読み込み、ユーザーが承認した用語を適切なカテゴリ（H2）の用語テーブルに追記する。ファイルが存在しない場合は新規作成する |

複数選択された場合は、選択された順に1つずつ処理する。

→ 全選択が完了したらステップ 4 へ

#### 注意

- 各クリエイタースキルの手順に従って進める
- クリエイタースキルが完了したら次の選択肢の処理に移る
- glossary は常時読み込まれるルールのため、用語の説明は1〜2文以内に収める

---

### ステップ 4: 完了報告

#### 条件

- ステップ 3 完了

#### 処理

1. 作成・更新されたファイル一覧を報告する
2. コミットするか確認する
3. ユーザーが同意したらコミットを実行する

## 参考

### アーティファクト種別の詳細

| 種別 | 生成物 | 主なユースケース |
|---|---|---|
| スキル | `.claude/skills/<name>/SKILL.md` | 複雑な繰り返し手順の自動化 |
| ルール | `.claude/rules/<name>.md` | ファイル間の依存関係・パス構成の永続化 |
| フック | `settings.json` hooks | ツール使用前後の自動チェック・通知 |
| CLAUDE.md | `CLAUDE.md` への追記 | プロジェクト規約・ガイドラインの文書化 |
| incidents | `.claude/rules/incidents.md`（インデックス・常時読み込み）<br>`.claude/references/incidents/{slug}.md`（詳細 en）<br>`.claude/references/incidents/{slug}.jp.md`（詳細 jp） | 失敗・誤解・思い込みの再発防止 |
| glossary | `.claude/rules/glossary.md`（常時読み込み） | プロジェクト固有の用語定義 |
