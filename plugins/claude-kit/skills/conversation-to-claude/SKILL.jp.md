# conversation-to-claude — 会話履歴からアーティファクトを生成

会話履歴を分析し、セッション中に積み上げた知識・手順に適したすべての Claude Code
アーティファクト（スキル・ルール・フック・CLAUDE.md・incidents・glossary）を
確認なしで自動的にすべて実装する。

---

## 概要

実装・調査・設定変更を終えた後「この手順を次も使いたい」「この知識を残したい」と感じる場面は多い。
しかし何の形式で残すべきか迷いやすい。このスキルは会話内容を分析して適切な形式を判断し、
確認なしで全アーティファクトを自動的に生成する。

---

## タスク

### ステップ 1: 会話履歴を分析する

#### 条件

- 常時 — 最初に実行

#### 処理

1. セッション**全体**の会話を振り返り、**余すことなくすべての候補**を抽出する。
   網を広く張ること — 多すぎるアーティファクトは減らせるが、見落としは取り戻せない。

   **A. 繰り返し作業フロー候補**（スキル向け）

   使うべき場面: 3ステップ以上の作業フローで、ユーザーの判断・分岐・対話を含むもの。再利用性が価値の核心。

   - 3ステップ以上の手順でユーザーとの対話・分岐を含むもの
   - 「他のプロジェクトでも使いたい」と感じるパターン
   - 繰り返し発生しうる調査・セットアップの流れ

   スキルにしない: 単一の操作、一度きりの修正、ルールや CLAUDE.md に収まる情報。

   ---

   **B. ファイル依存・パス構成の知識**（ルール向け）

   使うべき場面: 2つ以上のファイルが同期を保つべきことを発見した。ルールは `paths:` に一致するファイルを Claude が**読んだ瞬間**に自動ロードされ、セットのファイルを必ず提示してくれる。

   `paths:` の仕組み:
   - ファイルを Claude が**読んだとき**に発動 — `mv`・`rm`・`cp` などのシェルコマンドでは発動しない
   - そのドメインで Claude が実際に「開く」ファイルのパターンを設定する
   - 例: `paths: ["src/models/**/*.py"]` — モデルファイルを開いたときにロード

   ルールに書くこと: 関連ファイルへのリンク、「Xを編集したらYも確認」。簡潔に。
   ルールに書かないこと: 詳細な説明・ドキュメント、手順書。

   - 「このファイルを変えたら必ずあのファイルも変える」という発見
   - 「設定はここ」「ルーティングはここ」といったパス役割の把握
   - セッション中に発見した「セットで確認すべき」「常に同期を保つべき」パターン

   ---

   **C. 特定イベントへの自動反応**（フック向け）

   使うべき場面: ユーザーがプロンプトを打たなくても、特定のイベント発生時に自動で何かを実行させたい。

   利用可能なイベント: `PreToolUse`（ツール前・ブロック可）/ `PostToolUse` / `Stop`（応答完了）/ `SubagentStop` / `SessionStart` / `SessionEnd` / `UserPromptSubmit` / `PreCompact` / `Notification`

   フックの種類: プロンプト注入型（コンテキストにテキストを注入）またはシェルコマンド型（スクリプトを実行）。

   フックにしない: ユーザーが意識的にトリガーすべきものはスキルを使う。

   - ツール使用前後・セッション開始時に毎回実行したいチェックや処理
   - 「毎回このコマンドの前に確認したい」というパターン
   - 関連するイベントで毎回発火させたいバリデーション・通知

   ---

   **D. プロジェクト全体の規約・ガイドライン**（CLAUDE.md向け）

   使うべき場面: どのファイルを開いていても毎回知っておくべき規約・禁止事項・構造的な知識。CLAUDE.md は常時ロード、ルールはファイルを読んだ時だけロード。

   CLAUDE.md に書くべき内容: 禁止事項、命名規則、フォルダ構成（「仕様書は `.work/specs/` に置く」）、設計方針、オンボーディング情報。

   CLAUDE.md にしない: ファイル固有の同期ルール（ルールを使う）、繰り返し手順（スキルを使う）、イベント自動化（フックを使う）。

   - 禁止事項・命名規則・設計方針など全ファイルに適用するルール
   - フォルダ構成・ファイル格納場所の発見: 「仕様書はここに置く」「生成ファイルはこのフォルダ」「Xの正式な置き場はここ」
   - 新しいメンバーがミスを避けたり正しい置き場所を把握するために必要な前提知識

   ---

   **E. 再発防止の教訓**（`incidents` ルール向け）
   - コマンドや操作を試みたが失敗し、原因・正解が判明したもの
   - 思い込みで進めたが実際は違った、という認識の誤り
   - 「同じミスを繰り返さないために記録したい」と感じる気づき

   **F. プロジェクト固有の用語**（`glossary` ルール向け）
   - ユーザーが会話中に使ったプロジェクト固有の名詞・略語・概念
   - 既存の `glossary.md` に載っていない、または定義があいまいなもの
   - 一般的でないため、知らないと誤解しやすい言葉

→ ステップ 2 へ

#### 出力

- 各カテゴリの抽出結果（内部リスト）— 多めに含めること

---

### ステップ 2: 既存アーティファクトを確認し増殖ガードを適用する

#### 条件

- ステップ 1 完了

#### 処理

1. `${CLAUDE_PLUGIN_ROOT}/references/common.md` を読み込み、**アーティファクト増殖ガード**セクションをこのステップ全体で適用する。

2. ステップ 1 で特定した各候補について、内容が重複・統合できそうな既存アーティファクトをプロジェクト内でスキャンする:

   | 候補種別 | 確認場所 |
   |---|---|
   | スキル | `.claude/skills/`、`plugins/*/skills/` — SKILL.md のファイル名と説明を確認 |
   | ルール | `.claude/rules/` — ファイル名と見出しを確認 |
   | フック | `~/.claude/settings.json`、`.claude/settings.json` — 既存フックエントリを確認 |
   | CLAUDE.md 追記 | `CLAUDE.md`、`plugins/*/CLAUDE.md` — 関連セクションを確認 |
   | incidents | `.claude/rules/incidents.md` — 同一トピックの既存エントリを確認 |
   | glossary | `.claude/rules/glossary.md` — 既存の用語エントリを確認 |

3. 各候補に対し、増殖ガードの判断基準を適用する:
   - **既存に統合**: 同じドメインをカバーする既存アーティファクトがある → そこに追記・編集し、**新規ファイルは作らない**
   - **破棄**: 一時的・今回限りの内容、または特定作業時にしか不要な内容 → `.claude/references/` に置くか、永続化しない
   - **新規作成**: 類似したアーティファクトが存在せず、かつ常時ロードに値する内容である場合のみ

4. 判断結果（新規作成 / `{path}` に統合 / 破棄）をステップ 3 で使う。

→ ステップ 3 へ

#### 出力

- 各候補について: 判断（新規 / 統合 / 破棄）と対象パス

---

### ステップ 3: サブエージェントを使ってアーティファクトを実装する

#### 条件

- ステップ 2 完了

#### 処理

1. 抽出できるものがない場合:
   - 「今回の会話から永続化できる知識・手順は見つかりませんでした」と報告して終了

2. **incidents / glossary** — スキルを使わずメインエージェントが直接処理する:
   - **incidents**: `.claude/rules/incidents.md` のインデックスに概要を1行追記し、`.claude/references/incidents/{slug}.md`（+ `.jp.md`）に詳細を記録する
   - **glossary**: `.claude/rules/glossary.md` を読み込み（なければ作成）、用語を適切なカテゴリ（H2）の用語テーブルに追記する。説明は1〜2文以内に収める。

3. **スキル・ルール・フック・CLAUDE.md** — 候補があるカテゴリごとにサブエージェントを1つ起動する。
   Agent ツール（`isolation: "worktree"`）を使い、**1つのメッセージで全サブエージェントを同時に**送信する（並列実行）。
   全サブエージェントの完了を待ってからステップ 4 へ進む。

   | カテゴリ | サブエージェントが読むスキル | 実装対象 |
   |---|---|---|
   | スキル | `plugins/claude-kit/skills/skill-creator/SKILL.md` | スキル候補すべて |
   | ルール | `plugins/claude-kit/skills/rule-creator/SKILL.md` | ルール候補すべて |
   | フック | `plugins/claude-kit/skills/hook-creator/SKILL.md` | フック候補すべて |
   | CLAUDE.md | `plugins/claude-kit/skills/claude-creator/SKILL.md` | CLAUDE.md 追記候補すべて |

   **サブエージェントへの入力テンプレート**（カテゴリごとに `{…}` を埋めて使う）:

   ```
   あなたは [{カテゴリ}] アーティファクトを作成するサブエージェントです。

   ## 手順
   1. 以下のクリエイタースキルを読み込む:
      {クリエイタースキルのパス}
   2. スキルの手順に従い、下記の作成対象をすべて実装する。確認プロンプトはすべてスキップする。

   ## 作成対象
   {このカテゴリの各候補について:}
   ### {アーティファクト名または説明}
   - トリガー / ドメイン / イベント: {抽出したトリガー・ドメイン・イベント}
   - コンテキスト: {作業フロー手順 / ファイルリスト / フック動作 / ガイドライン内容}
   - ステップ 2 の判断: {新規作成 | {path} に統合 | 破棄}

   ## 補足
   - 複数の候補がある場合は、記載順に1つずつ実装する
   - 各候補のステップ 2 の判断（増殖ガード）に従う
   ```

→ ステップ 4 へ

#### 注意

- 各クリエイタースキル内の確認プロンプトもスキップして進める
- glossary は常時読み込まれるルールのため、用語の説明は1〜2文以内に収める

---

### ステップ 4: サブエージェントの出力を検証する

#### 条件

- ステップ 3 完了

#### 処理

1. 各サブエージェントの結果について以下を確認する:
   - 期待するファイルが正しいパスに作成・更新されているか
   - ファイルの内容が意図したアーティファクトと一致しているか（見出しや主要フィールドを確認）
   - 想定外のディレクトリに不要なファイルが作られていないか

2. 問題が見つかった場合は、サブエージェントを再起動せずメインエージェントが直接修正する。

→ ステップ 5 へ

---

### ステップ 5: コミットして報告する

#### 条件

- ステップ 4 完了

#### 処理

1. 作成・更新されたすべてのファイルをコミットする
2. 作成・更新したファイルの一覧をユーザーに報告する

## 参考

### アーティファクト種別の詳細

| 種別 | 生成物 | 主なユースケース |
|---|---|---|
| スキル | `.claude/skills/<name>/SKILL.md` | 複雑な繰り返し手順の自動化 |
| ルール | `.claude/rules/<name>.md` | ファイル間の依存関係・パス構成の永続化 |
| フック | `settings.json` hooks | ツール使用前後の自動チェック・通知 |
| CLAUDE.md | `CLAUDE.md` への追記 | プロジェクト規約・ガイドラインの文書化 |
| incidents | `.claude/rules/incidents.md`（インデックス・常時読み込み）<br>`.claude/references/incidents/{slug}.md`（詳細 en）<br>`.claude/references/incidents/{slug}.jp.md`（詳細 jp） | 失敗・誤解・思い込みの再発防止 |
| glossary | `.claude/rules/glossary.md`（常時読み込み） | プロジェクト固有の用語定義 |
