# conversation-to-skill — 会話履歴からスキルを生成

現在の会話セッションで実施した作業手順を振り返り、再現可能なスキルとして
`.claude/skills/` 配下に記録する。

---

## 概要

複雑な手順を一度実施した後、「同じことをまた別のプロジェクトでもやりたい」
「この作業フローを自動化したい」という場面が生じる。
このスキルは会話履歴を分析して作業手順を抽出し、`skill-creator` を使って
再利用可能なスキルに落とし込む。

ユーザーとの対話形式で進めることで、自動生成の精度を高める。

---

## 作業内容

### ステップ1: 会話履歴を分析する

#### 条件

- 常時 — 最初に実行する

#### 処理内容

1. 会話全体を振り返り、以下を抽出する：
   - 実施した主な作業（何をやったか）
   - 作業のステップ順序（どういう順番でやったか）
   - 使ったツール・コマンド・参照したファイル
   - 判断が必要だった分岐点（「このときはこうした、ああだったらこうした」）
   - 繰り返し使えそうなパターンがある部分

2. スキル化に適した作業フローがあるか判断する：
   - 3ステップ以上の手順がある → スキル化に適している
   - 1〜2手順の単純操作 → CLAUDE.md やルールの方が適切かもしれない

→ ステップ2へ進む

#### 出力

- 抽出した作業フローの概要

---

### ステップ2: 作業内容をユーザーと確認する

#### 条件

- ステップ1完了

#### 処理内容

以下の質問をユーザーに順番に行う（会話形式で進める）：

**質問1: スキルの対象範囲**
```
今回の会話でやった作業の中で、スキルにしたい部分はどこですか？

候補:
A. {抽出した作業A}（例: DBスキーマ変更 → マイグレーション → テスト更新）
B. {抽出した作業B}
C. 会話全体を1つのスキルにまとめる
```

**質問2: スキルの名前と起動条件**
```
スキルの名前と、どんなときに自動起動してほしいですか？

例:
- 名前: db-migration
- 起動条件: 「DBを変えたい」「マイグレーション作って」と言ったとき
```

**質問3: 必要な前提条件**
```
このスキルを使うには、事前に何かが必要ですか？

例: 「docker が起動している必要がある」「特定のブランチにいる必要がある」など
なければ「なし」でOKです。
```

ユーザーの回答を元に、スキルの仕様を確定する

→ ステップ3へ進む

#### 出力

- スキル名、起動条件、対象作業フロー、前提条件

---

### ステップ3: 作業フローをステップ構造に変換する

#### 条件

- ステップ2完了

#### 処理内容

1. ステップ2で確定した作業フローを、スキルのステップ構造に変換する：
   - 各手順を「条件 → 処理 → 出力」の形式に整理する
   - 分岐があればステップ内の「条件分岐」として表現する
   - コマンドや具体的なファイルパスがあれば明記する

2. 変換結果をユーザーに提示して確認を取る：
   ```
   以下の構成でスキルを作成します。問題なければ「OK」と教えてください。
   修正がある場合は指摘してください。

   スキル名: {name}
   起動条件: {description}

   ステップ1: {title}
     → {処理概要}

   ステップ2: {title}
     → {処理概要}
   ...
   ```

→ ステップ4へ進む（ユーザーが承認した後）

#### 出力

- 確定したスキルのステップ構成

---

### ステップ4: `skill-creator` を起動してスキルを作成する

#### 条件

- ステップ3でユーザーが承認

#### 処理内容

1. `claude-kit:skill-creator` スキルを起動する
2. ステップ3で確定したスキル仕様を入力として渡す：
   - スキル名
   - 起動条件（description フロントマター）
   - ステップ構成（各ステップの条件・処理・出力）
3. skill-creator の手順に従って以下を作成する：
   - `.claude/skills/<name>/SKILL.jp.md`（日本語ミラー・先に作成）
   - `.claude/skills/<name>/SKILL.md`（英語・Claude が読む）

→ ステップ5へ進む

#### 補足

##### 参照

- `claude-kit:skill-creator` スキルの手順に従う

---

### ステップ5: 作業結果を報告してコミットを提案する

#### 条件

- ステップ4完了

#### 処理内容

1. 作成したファイルを列挙して報告する
2. コミットするかをユーザーに確認する
3. ユーザーが同意した場合、変更をコミットする

#### 出力

- 作成ファイルの一覧
- ユーザーへのコミット確認

## 参考資料

### スキル化に適した内容の判断基準

| 内容 | 適切な記録場所 |
|---|---|
| 3ステップ以上の手順・ユーザーとの対話が必要 | ✅ `.claude/skills/` |
| 繰り返し使う定型フロー | ✅ `.claude/skills/` |
| 1〜2手順の単純ルール | ⚠️ CLAUDE.md または `.claude/rules/` |
| ファイル間の依存関係の記録 | ⚠️ `.claude/rules/`（`conversation-to-rule` を使う） |
