### Behavior

When editing any Jinja2 template under `**/hooks/templates/*.j2`, Claude now receives the
`jinja2/templates.md` reference inline. The guide covers three rendering bugs caught in PR201
plus general authoring guidance:

- **Rule 1** — `trim_blocks=True` strips the newline after `{% %}` tags; required blank lines
  must live INSIDE the enclosing Jinja2 block, not after `{% endif %}` / `{% endfor %}`.
- **Rule 2** — `{% endif %}{% if X %}` chains drop all whitespace; when `---` follows, the
  blank line before `---` must be inside the inner `{% if X %}` or the previous line becomes
  a setext heading.
- **Rule 3** — heading/paragraph lines ending in `}}` (a Jinja2 expression) can confuse
  Handlebars-style downstream parsers; terminate them with `<!-- -->`.

Plus a quick checklist for `.md.j2` edits.

### Why

PR201 fixed three concrete rendering bugs in `injection.md.j2` / `injection.jp.md.j2` that
were hard to spot from the template source alone — the interaction between Jinja2 whitespace
stripping and Markdown block-element parsing produced silent corruption (setext headings,
disappearing separators, parser confusion). Encoding these patterns as an auto-injected
reference prevents the same bugs from recurring when any plugin's `.j2` templates are edited.
