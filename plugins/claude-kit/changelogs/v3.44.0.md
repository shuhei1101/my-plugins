# v3.44.0

## feat: add plugin-config reference

Adds `references/plugin-config.md` (+ `.jp.md`) — a design guide for adding a `config` skill to
any Claude Code plugin. Auto-injected when editing `SKILL.md` or `.claude-plugin/plugin.json`.

### Changes

- New: `plugins/claude-kit/references/plugin-config.md` (+ `plugin-config.jp.md`)
- Updated: `references/_index.yaml` (+ `_index.jp.yaml`) — new entry added
- Updated: `references/_injection_rules.yaml` — `plugin-config.md` added as optional reference
  for `**/skills/*/SKILL{.jp,}.md` and `**/.claude-plugin/{plugin,marketplace}.json` patterns
- Bumped `plugin.json` and `.claude-plugin/marketplace.json` from `3.43.1` → `3.44.0`

### Behavior

When editing any `SKILL.md` or `plugin.json`, Claude now receives a pointer to `plugin-config.md`
as an optional reference. The guide covers:

- Why every plugin with user-facing env toggles should have a config skill
- The `AskUserQuestion` 5-step loop pattern (established by `work:config` in PR167)
- The absent = ON / `"false"` = OFF toggle convention
- Scope selection (project vs user `settings.json`)
- A minimal copy-paste `SKILL.md` template
- Release checklist

### Why

PR167 established the config-skill pattern in `work:config`. This PR formalises it as a
claude-kit reference so all future plugins have a clear guide to follow — and Claude receives
a reminder when authoring new skills or plugin manifests.
