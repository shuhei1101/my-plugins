# v3.43.0

## feat: add plugin-update skill

Adds `skills/plugin-update/` (+ `.jp.md`) — satisfies the `plugin-update` mandatory-skill rule defined in `references/plugin-structure.md` (PR168).

### Changes

- New: `plugins/claude-kit/skills/plugin-update/SKILL.md` (+ `SKILL.jp.md`)
- Bumped `plugin.json` and `.claude-plugin/marketplace.json` from `3.40.0` → `3.41.0`

### Behavior

`/claude-kit:plugin-update` walks the project's claude-kit-authored artifacts (skills / rules / CLAUDE.md / hooks / plugin manifests / glossary / incidents) and applies minimal in-place fixes against the current `references/*.md` conventions. Re-applies `~/.claude/settings.json` `statusLine` if claude-kit's signature is detected.

Unlike `dev-kit:plugin-update` / `work:plugin-update` (static template re-copy), claude-kit ships no project templates — its conventions live in `references/*.md` which the `claude-kit-references-injection` hook inlines on Read. The skill leverages that injection as the source of truth instead of restating conventions.

### Why

PR168 made `plugin-update` a hard requirement for every plugin. claude-kit was the rule's author yet did not ship one — this PR closes that gap. The semantic-migration design (rather than file copy) reflects claude-kit's "thin wrapper over references" architecture.
