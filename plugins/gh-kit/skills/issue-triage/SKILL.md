# issue-triage

GitHub Issue を 1 件トリアージし、起票直後の状態から「分かっていることだけを整理した状態」へ持っていく。仕様や実装方針の決定は **しない**（後続の issue-spec 以降に任せる）。

## 入力

| 引数       | 内容    |
| ---------- | ------- |
| Issue 番号 | 例: 42  |

## コメント返信ルール（共通）

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/gh-kit/規約/コメント.md"`

## ステップ 0: 起動時のラベル切り替え

```bash
gh issue edit {N} \
  --remove-label "$GH_KIT_LABEL_CONFIRM_ISSUE_TRIAGE" \
  --add-label "$GH_KIT_LABEL_PROCESSING_ISSUE_TRIAGE"
```


## ステップ 1: Issue 取得

```bash
gh issue view {N} --json number,title,body,labels,comments,assignees
```

## ステップ 2: 本文の整形・骨組み作成

### ステップ 2a: 既存本文の整文・整形

- ユーザー入力の誤字脱字・改行整理・文言修正を行う
- **ユーザーが書いた範囲を超えた内容を加えない**（情報の追加は後続フェーズ）

### ステップ 2b: 後続フェーズのセクション骨組みを作成

下記テンプレートに沿って、欠けているセクションを骨組みとして用意する。
issue-triage が自身で埋めるのは `## 概要` / `## 背景` / `## 現状` のみ。

### Issue 本文テンプレート

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_ISSUE_DOCUMENT}"`


## ステップ 3: タイトル更新

Issue 本文の内容を正確に表すタイトルに更新する。

```bash
gh issue edit {N} --title "{生成タイトル}"
```

| 項目   | 内容                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| 形式   | `{スコープ}: {動詞} — {対象}` を推奨（例: `gh-kit:profile-edit — ユーザープロフィール編集画面を追加`） |
| 長さ   | 60〜80 文字以内                                                                          |
| 言語   | Issue 本文に合わせる（日本語 Issue は日本語タイトル）                                    |


## ステップ 4: タイプ/優先度ラベルを判定・付与

### タイプラベル

| type ラベル                   | 付与条件                                     |
| ----------------------------- | -------------------------------------------- |
| ${GH_KIT_LABEL_TYPE_BUG}      | 既存の動作が仕様または期待と異なる問題の修正 |
| ${GH_KIT_LABEL_TYPE_FEAT}     | 新機能追加・既存機能の有意な拡張             |
| ${GH_KIT_LABEL_TYPE_REFACTOR} | 外部動作を変えずにコードを整理・改善         |
| ${GH_KIT_LABEL_TYPE_DOCS}     | ドキュメント・コメントのみの変更             |
| ${GH_KIT_LABEL_TYPE_CHORE}    | ビルド設定・依存更新・CI/CD など             |
| ${GH_KIT_LABEL_TYPE_TEST}     | テストコードの追加・修正のみ                 |

`type:*` ラベルが既に付与されていればスキップ。なければ判定して 1 つ付与する。

優先度ラベル（`$GH_KIT_LABEL_PRIORITY_URGENT` / `$GH_KIT_LABEL_PRIORITY_LOW`）は **ユーザーが付けるもの** なので AI から付与しない。


## ステップ 5: 現状調査（全てサブエージェント並列起動）

`## 現状` セクションのサブセクション（`### 関連実装コード` / `### 関連テスト` / `### 関連 Issue/PR` / `### 関連ドキュメント` / `### 既存テスト実行結果` / `### 再現手順`）を埋めるための調査を **並列** で実行する。

### ステップ 5a: 領域別コードベース調査

`[サブエージェントで並列実行・完了を待つ]` Issue が言及する領域ごとにサブエージェントを起動する。
プロジェクト配下の領域別カスタムサブエージェント（`agents/*.md`）があれば優先利用、なければ汎用 Agent。
（戻り値: `{ "関連実装コード": [{file, method, summary, note}], "関連テスト": [{category, file, method, summary, note}], "関連ドキュメント": [{category, page, summary, note}] }`）

各サブエージェントに **注入する Wiki ページ**（`docs/wiki/` 配下、相対パス）:
- 該当領域の `設計図/モジュール構成/{分類}.md`
- 該当領域の `設計図/バックエンド結合/{論理名}.md` / `設計図/フロントエンド結合/{論理名}.md`
- 該当領域に絡む `設計図/シナリオ/{論理名}.md`（あれば）
- 該当領域の `設計図/ER図/{分類}.md`

### ステップ 5b: テスト再現調査

`[サブエージェントで並列実行・完了を待つ]` テスト種別ごと（単体 / 結合 / E2E / 外部疎通）に該当があるかを確認し、実行可能なら 1 サブエージェントずつ起動して **実際に走らせる**。
（戻り値: `[{category, file, method, summary, result}]`、`result` は `✅` / `❌`）

各サブエージェントに **注入する Wiki ページ**（`docs/wiki/` 配下、相対パス）:
- `テスト実行方法.md`（各種テストの起動コマンドと前提）
- `テスト一覧.md`（既存テストの網羅状況 — 設計 × 実装の対応表）
- 該当領域の `設計図/バックエンド結合/{論理名}.md` / `設計図/フロントエンド結合/{論理名}.md`（該当エンドポイント / 画面の結合テスト対象）
- 該当領域に絡む `設計図/シナリオ/{論理名}.md`（あれば、該当 E2E ケース）

外部疎通テストは **料金発生のため自動実行禁止**。
実行が必要な場合は本文の `### 再現手順` に「ユーザー手動で `--run-external` 付き実行が必要」と記録するに留める。
