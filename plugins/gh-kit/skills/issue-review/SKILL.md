# issue-review

GitHub Issue を 1 件レビューし、結果を gh CLI でコメント投稿する。

## 入力

| 引数       | 内容   |
| ---------- | ------ |
| Issue 番号 | 例: 42 |

## 重要事項

- 投稿する内容には必ず先頭に「🤖 Generated by issue-reviewer」を記載する


## ステップ 0: 起動・終了ラベルの切り替え

レビュー開始時に **確認ラベルを外して処理中ラベルを付ける**。

```bash
gh issue edit {N} \
  --remove-label "$GH_KIT_LABEL_CONFIRM_ISSUE_REVIEW" \
  --add-label "$GH_KIT_LABEL_PROCESSING_ISSUE_REVIEWER"
```


## ステップ 1: Issue とラベルを取得

```bash
gh issue view {N} --json number,title,body,labels,comments
```

ラベルに !`GH_KIT_LABEL_AI_CODE_SCAN` が含まれるかで起票元を判定する。

| ラベル | 起票元                        | 本文の状態                         |
| ------ | ----------------------------- | ---------------------------------- |
| あり   | claude code（`code-scanner`） | テンプレ準拠で揃っている           |
| なし   | 人間                          | 概要・背景などが欠けている可能性大 |


## ステップ 2: コードベースを読む

Issue が言及する領域・関連ファイルを Read で確認する。Read 時に PreToolUse フックがファイル系ルールを自動注入する。

### ステップ 2a: 公式ドキュメント取得（外部ツール・ライブラリ名がある場合のみ）

Issue タイトルや本文に外部ツール・ライブラリ・フレームワーク・サービス名が含まれる場合:

1. `WebFetch` で Issue に最も関連する公式ドキュメントページを取得する。
2. 取得に失敗した場合は「参照不可（理由）」と記録し、処理を継続する。
3. 取得に成功した各 URL を `{doc_urls}` に記録し、後続のコメントで使用する。

Issue に外部ツール・ライブラリ名が含まれない場合はスキップ。


## ステップ 3: 動作確認

報告された問題が現在のコードベースで実際に発生するかを確認する（新規機能追加の場合はスキップ）。

| Issue の種類                | 確認方法                                                       |
| --------------------------- | -------------------------------------------------------------- |
| スキル / Claude Code の動作 | サブエージェントを起動し、Issue に記載されたシナリオを再現する |
| コードバグ（テストあり）    | 関連テストスイートを実行し、失敗を確認する                     |
| コードバグ（テストなし）    | 手動で動作確認を行う                                           |
| 確認不可                    | 「確認不可（理由）」と記録し、処理を継続する                   |

### 報告テンプレート

#### E2E やユニットテストの実行結果を報告する場合

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_SCRIPT_TEST_REPORT}"`

#### 上記以外の動作確認結果を報告する場合

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_OTHER_TEST_REPORT}"`

### コメント投稿

```bash
gh issue comment {N} --body-file <(cat <<'EOF'
{動作確認結果本文}
EOF
)
```


## ステップ 4: タイトル更新（人間起票のみ）

以下の条件をすべて満たす場合のみ、Issue タイトルを自動生成して更新する。

- !`GH_KIT_LABEL_AI_CODE_SCAN` ラベルが付いていない（人間起票）
- !`GH_KIT_AUTO_TITLE_GENERATE` ラベルが付いている（自動タイトル生成を許可）

Issue の本文・コメントを読んだうえで、内容を正確に表すタイトルを生成して更新する。

```bash
gh issue edit {N} --title "{生成したタイトル}"
```

### タイトル生成ガイドライン

| 項目           | 内容                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 形式           | `{スコープ}: {動詞} — {対象}` を推奨（例: `gh-kit:issue-review — 人間起票 Issue のタイトルを自動更新する責務を追加`） |
| 長さ           | 60〜80 文字以内                                                                                                       |
| 言語           | Issue 本文に合わせる（日本語 Issue は日本語タイトル）                                                                 |
| 元タイトル保持 | 不要。GitHub の変更履歴（Activity）にタイトル変更が記録されるため、別途残す必要はない                                 |


## ステップ 5: 本文補完（必要時のみ）

人間起票で **本文に欠けているセクション** があるときに限り、下記の `イシュー本文テンプレート` に沿って本文を補完した内容で**置き換え**る。
本文が揃っている場合（AI 起票、または人間起票でも完備）はこのステップをスキップ。

```bash
# 元の本文をコメントとして保存
ORIGINAL_BODY=$(gh issue view {N} --json body --jq '.body')
gh issue comment {N} --body "{元の本文}"

# 本文を補完した内容で置き換え
gh issue edit {N} --body-file <(cat <<'EOF'
{イシュー本文テンプレートに沿って補完した本文}
EOF
)
```

### イシュー本文テンプレート

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_ISSUE_DOCUMENT}"`


## ステップ 6: 設計論点をコメント

**design-reviewer** を呼び出して実装箇所の設計上の論点を洗い出し、返ってきた配列の要素ごとに **1 コメント = 1 論点** で投稿する。論点がなければスキップ。

```bash
gh issue comment {N} --body-file <(cat <<'EOF'
{設計論点本文（1 論点分）}
EOF
)
```

### 設計論点コメントテンプレート

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_DESIGN_REVIEW}"`


## ステップ 7: ライブラリ選定論点をコメント

Issue の実装で「どのライブラリを使うか迷う処理」が 1 つ以上ある場合に実行する。迷う処理がなければスキップ。

1. **library-finder** を呼び出し、処理ごとに候補を 3〜5 個探す
2. 各候補を **library-researcher** に並列で渡して調査させる
3. 調査結果をテンプレートに沿ってまとめ、**1 コメント = 1 処理** で投稿する

```bash
gh issue comment {N} --body-file <(cat <<'EOF'
{ライブラリ選定論点本文（1 処理分）}
EOF
)
```

!`python "${CLAUDE_PLUGIN_ROOT}/scripts/gh/read_urls.py" "${WIKI_BASE}/${GH_KIT_TEMPLATE_LIBRARY_SELECTION}"`


## ステップ 8: タイプラベル判定・付与

Issue 本文・タイトル・補完コメント（ステップ 5）の内容から、適切な `type:*` ラベルを判定して付与する。

### 判定基準

| type ラベル     | 変数                          | 付与条件                                     |
| --------------- | ----------------------------- | -------------------------------------------- |
| `type:bug`      | `$GH_KIT_LABEL_TYPE_BUG`      | 既存の動作が仕様または期待と異なる問題の修正 |
| `type:feat`     | `$GH_KIT_LABEL_TYPE_FEAT`     | 新機能追加・既存機能の有意な拡張             |
| `type:refactor` | `$GH_KIT_LABEL_TYPE_REFACTOR` | 外部動作を変えずにコードを整理・改善         |
| `type:docs`     | `$GH_KIT_LABEL_TYPE_DOCS`     | ドキュメント・コメントのみの変更             |
| `type:chore`    | `$GH_KIT_LABEL_TYPE_CHORE`    | ビルド設定・依存更新・CI/CD など             |
| `type:test`     | `$GH_KIT_LABEL_TYPE_TEST`     | テストコードの追加・修正のみ                 |

### 既付与時スキップ + 冪等付与

```bash
# 既に type:* ラベルが付与されている場合はスキップ
EXISTING_TYPE=$(gh issue view {N} --json labels --jq '.labels[].name' | grep '^type:' | head -1)
if [ -n "$EXISTING_TYPE" ]; then
  echo "type ラベル ${EXISTING_TYPE} 付与済みのためスキップ"
else
  # 選んだタイプラベルを変数に設定（例: TYPE_LABEL="$GH_KIT_LABEL_TYPE_BUG"）
  TYPE_LABEL="$GH_KIT_LABEL_TYPE_{判定したタイプ}"

  # ラベルが存在しなければ作成（冪等）
  gh label list --json name --jq '.[].name' | grep -q "^${TYPE_LABEL}$" || \
    gh label create "${TYPE_LABEL}" --color "$GH_KIT_LABEL_COLOR_TYPE" --description "Issue タイプ: ${TYPE_LABEL}"

  # Issue に付与
  gh issue edit {N} --add-label "${TYPE_LABEL}"
fi
```

!`GH_KIT_LABEL_AI_CODE_SCAN` ラベルがある（AI 起票）場合もこのステップを実行する（`code-scanner` が付与済みの場合は `--add-label` が冪等で安全）。


## ステップ 9: レビュー完了後の assignee 追加

レビュー完了後は、**必ず** GH ユーザーを Issue の assignee に追加する。

```bash
GH_LOGIN="$(gh api user --jq '.login')"
gh issue edit {N} --add-assignee "$GH_LOGIN"
```


## ステップ 10: 処理中ラベルを外してユーザー確認を案内

処理中ラベルを外したうえで、ユーザーに確認を促すコメントを投稿する。

```bash
gh issue edit {N} --remove-label "$GH_KIT_LABEL_PROCESSING_ISSUE_REVIEWER"

gh issue comment {N} --body "$(cat <<'EOF'
## レビュー完了 — ユーザー確認をお願いします

Issue のレビューが完了しました。内容をご確認ください。
EOF
)"
```
