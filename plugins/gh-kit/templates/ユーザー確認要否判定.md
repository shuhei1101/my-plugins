# ユーザー確認要否判定基準

下記いずれかに **該当するもの以外** はすべてユーザー確認が必要（`needs_user_review: true`）とみなし、
PR/Issue に `gh {pr|issue} edit --add-assignee "{GH_LOGIN}"` でアサインする。

## 確認不要のもの（ブラックリスト）

- リファクタリング（表面の動作は変わらない変更、type: refactor）
- 命名規則変更
- 例外ハンドル変更（裸 `except:` 改善・ログ追加など）
- ロガー使用箇所の追加・整理
- ラベル / テキスト / コメントなど見た目変更
- dead code 除去
- 分散ロジックの単純な共通化
- タイムアウト追加
- タイムゾーン挙動の明示化
- typo / lint warning 修正

## ユーザー確認が必要な場合の操作

```bash
GH_LOGIN="$(gh api user --jq '.login')"
# Issue の場合
gh issue edit {N} --add-assignee "$GH_LOGIN"
# PR の場合
gh pr edit {N} --add-assignee "$GH_LOGIN"
```

ユーザーが確認済みになったら assignees を手動で外す。外れたら次工程に自動進行する。
