## 入力

- 観点: 何をスキャンするか
- scope ラベル: 観点の短い安定ラベル（例 `folder:src/llm`）
- プロジェクトルート: 作業ディレクトリ

## ステップ1 — 対象ファイルを解決する

観点を実際のファイル一覧に変換する:
- フォルダ → Glob で収集
- grep パターン → Grep で検索
- レイヤー / ファイル種別 → ファイル名パターンで Glob
- 単一ファイル → そのファイルのみ

除外: `.work/` `.git/` `node_modules/` `.venv/` `venv/` `__pycache__/` `dist/` `build/` `.next/` `.turbo/`

0 件なら空リストを返す。

## ステップ2 — ファイルを読む

各対象ファイルを読む（読んだときにClaude Codeのルールが読み込まれる。）
関連ファイル（兄弟・import 先/元・関連レイヤー）も文脈として読み込む

## ステップ3 — 問題を発見する

ルール と照合し、以下を探す:
- 規約違反 — 命名・型・コメント・スタイル
- アーキテクチャ違反 — 依存方向・レイヤー境界
- 改善余地 — DRY 違反・デッドコード・古いパターン
- 保守性の問題 — 重複ロジック・二重管理・共通処理の未抽出
- 横断的な問題 — 他ファイルに再発しそうな問題

イシューは主対象ファイルに対して立てる。独立して対処できる単位ごとに分ける（1 事項 = 1 イシュー）。


## ステップ4.1 - 問題を分析する
以下内容の場合、イシューは作成せず、そのままワークツリーを作成し、実装に進む
- リファクタリング（表面の動作は変わらない変更、type: refactor）
- 命名規則変更
- タイムゾーン挙動
- タイムアウト追加
- 例外ハンドル変更（握り潰し改善など）
- ロガー変更
- ラベル、テキスト変更など、簡易的な見た目変更
- dead codeの除去
- 分散ロジックの共通化

実装する際は以下流れに沿う
1. ブランチ名を決める（`type/kebab-title`
2. `worktree-create`スキルを実行し、ワークツリーを作る
3. `/work-start`スキルを実行し、作業を進める
4. 作業完了後、`/merge`スキルを実行しマージする → 処理を終了する

それ以外の場合、以下ステップに進む

## ステップ4 — イシュー本文を作成する

各発見について Markdown 本文を作成する。今日の日付を取得して `作成日` フィールドに設定する。
本文はルールに従って作成する。


## ステップ5 — JSON で返す

発見を JSON 配列で返す。何も見つからなければ `[]` とスキャンした観点を 1 行添える。

```json
[
  {
    "title": "...",
    "type": "refactor",
    "priority": "medium",
    "tags": ["..."],
    "scope": "src/...",
    "perspective": "{渡された観点}",
    "body": "作成日: 2026-05-31\n\n# ユーザー回答欄\n\n## 意思\n\n- [ ] 対応する\n- [ ] 対応しない\n\n## QA\n\n### QA-1: ...\n\nA) ... / B) ...\n\n推奨: A — ...\n\n- [ ] A\n- [ ] B\n\n---\n\n## 概要\n...\n\n## 現状\n...\n\n## 対応案\n..."
  }
]
```
