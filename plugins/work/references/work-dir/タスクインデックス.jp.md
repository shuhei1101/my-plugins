# タスク索引スキーマ（`index.yaml` / `index.archive.yaml`）

`.work/tasks/` 配下のブランチ索引ファイルのスキーマ。`.work/tasks/index*.yaml` を編集するときに
自動注入される。通常は `index-tool.py`（Bash 経由）と `merge` スキルが管理する — 索引を直接
修正するときだけ手編集する。ブランチ索引は **`branch` をキー**とし、数値 `id` や `last_id` は持たない。
英語原文: `タスクインデックス.md`

---

## `index.yaml` — 進行中ブランチ索引

git 管理外（`.work/tasks/.gitignore` に記載）でメインリポにのみ存在。ブランチ状態の単一の正本。
トップレベルは `branches`（リスト）のみ。

```yaml
branches:
  - branch: refactor/foo      # 識別キー（git ブランチ名）
    created: 2026-05-31        # 作成日。同名ブランチを時系列で識別するサロゲート
    title: 日本語タイトル        # タスクドキュメントの H1
    type: refactor             # feat / fix / refactor / docs / chore / test
    summary: 一行説明           # ファイルを開かずに内容がわかる一行説明
    task: 260531_foo           # タスクフォルダ名（YYMMDD_title）
    completed: false           # false = 進行中、true = マージ済み / 廃止済み
```

- 数値 `id` / トップレベル `last_id` / `tags` は**持たない**（撤廃済み）。
- `created`（`add` 時にシステム日付 `YYYY-MM-DD` を自動設定）は**カウンタではないサロゲート**。
  git は同名ブランチの同時存在を禁止するため active 集合では `branch` は常に一意。`created` は
  archive で同名ブランチが時系列で再登場した場合の識別用（`--created` で明示指定も可）。

## `index.archive.yaml` — アーカイブ済みブランチ

git 管理対象。`index-tool.py archive` がマージ時に `completed: true` のエントリをここへ移動し、
`index.yaml` を小さく保つ。アクティブエントリと同じフィールド（レガシーエントリは `branch` を欠く場合あり）。

---

## `index-tool.py` サブコマンド

| # | サブコマンド | 役割 |
|---|---|---|
| 1 | `add --branch B --title T --type TY --summary S --task TASK [--created YYYY-MM-DD]` | 新しい active エントリを追記（`created` 既定=今日） |
| 2 | `list-active` | 未完了を `branch\|title\|type\|task` で出力 |
| 3 | `completed-count` | 完了済み件数を出力 |
| 4 | `set-completed --branch B` | 指定 branch を `completed: true` に |
| 5 | `archive [index] [archive]` | 完了済みを archive へ移動（件数出力） |

`next-id` は撤廃（採番不要）。識別は常に `branch`。

---

## 規約

- `task` フォルダのプレフィックスは 6 桁 `YYMMDD`（例: `260531`）。8 桁形式は使わない。
- `index.yaml` は git 管理外 — コミットしない。`index.archive.yaml` は git 追跡。
- 手編集より `index-tool.py` を優先する。
- `.work/issues/` の issue インデックス（`issue-tool.py`）は独自の `id` / `tags` を持つ別系統
  （`イシュー.md` 参照）— 本スキーマの対象外。
