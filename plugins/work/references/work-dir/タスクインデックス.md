# Task Index Schema (`index.yaml` / `index.archive.yaml`)

Schema for the branch index files under `.work/tasks/`. Auto-injected when you edit
`.work/tasks/index*.yaml`. These files are normally maintained by `index-tool.py` (via Bash) and
the `merge` skill — hand-edit only when fixing the index directly. The branch index is **keyed by
`branch`**; there is no numeric `id` or `last_id`.
Japanese mirror: `タスクインデックス.jp.md`

---

## `index.yaml` — active branch index

Git-ignored (listed in `.work/tasks/.gitignore`); exists only in the main repo. The single source
of truth for branch status. Top level is just `branches` (a list).

```yaml
branches:
  - branch: refactor/foo      # identity key (git branch name)
    created: 2026-05-31        # creation date; surrogate to disambiguate same-named branches over time
    title: 日本語タイトル        # the branch document H1
    type: refactor             # feat / fix / refactor / docs / chore / test
    summary: 一行説明           # one-line summary readable without opening the doc
    task: 260531_foo           # task folder name (YYMMDD_title)
    completed: false           # false = in progress, true = merged / abandoned
```

- No numeric `id`, no top-level `last_id`, no `tags` (all removed).
- `created` (auto-set to today's `YYYY-MM-DD` on `add`) is a **non-counter surrogate**. Git forbids
  two branches of the same name at once, so `branch` is unique within the active set; `created`
  disambiguates a same-named branch that reappears over time in the archive (override with `--created`).

## `index.archive.yaml` — archived branches

Committed to git. `index-tool.py archive` moves `completed: true` entries here on merge, keeping
`index.yaml` small. Same fields as an active entry (legacy entries may omit `branch`).

---

## `index-tool.py` subcommands

| # | Subcommand | Role |
|---|---|---|
| 1 | `add --branch B --title T --type TY --summary S --task TASK [--created YYYY-MM-DD]` | Append a new active entry (`created` defaults to today) |
| 2 | `list-active` | Print in-progress entries as `branch\|title\|type\|task` |
| 3 | `completed-count` | Print the number of completed entries |
| 4 | `set-completed --branch B` | Mark the given branch `completed: true` |
| 5 | `archive [index] [archive]` | Move completed entries to the archive (prints the count) |

`next-id` was removed (no numbering) — the identity is always `branch`.

---

## Conventions

- Use a 6-digit `YYMMDD` (e.g. `260531`) for the `task` folder prefix, not the 8-digit form.
- `index.yaml` is git-ignored — never commit it; `index.archive.yaml` is git-tracked.
- Prefer `index-tool.py` over hand-editing.
- The `.work/issues/` index (`issue-tool.py`) is a separate system with its own `id` / `tags`
  (see `イシュー.md`) — not covered by this schema.
