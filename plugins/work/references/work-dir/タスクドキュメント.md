# Branch Document Template & Fill-in Guide

The branch document is the single source of truth for one branch — its plan, progress, QA, and
references all in one file. This reference is auto-injected when you create or edit a
`.work/tasks/**/*.branch.md` file. Author the document directly from the template below.
Japanese mirror: `references/work-dir/タスクドキュメント.md` の JP ミラーは `タスクドキュメント.jp.md`。

---

## Location & file name

```
.work/tasks/{YYMMDD}_{日本語タイトル}/{YYMMDD}-{日本語タイトル}.branch.md
```

- One task **folder** per task (`{YYMMDD}_{日本語タイトル}`). A folder may hold several branch documents
  (when multiple branches share a task area) plus **any user-authored files** — the task folder
  doubles as a general-purpose work area.
- The branch document itself always carries the **`.branch.md`** extension so it is unambiguously
  distinguishable from user files. Glob `*.branch.md` to find branch documents.
- The file-name stem is `{YYMMDD}-{日本語タイトル}` (6-digit date + the Japanese H1 title).
- The git branch name is **not** in the file name — it is recorded in the `> ブランチ:` header line.

---

## Template

Create the file with exactly this structure, then replace the `{...}` placeholders with the real
plan. The H1 title is the Japanese title; the `> ブランチ:` line is the full git branch name.

```markdown
# {日本語タイトル}

> ブランチ: `{branch-name}`

## 概要

{このブランチの目的・背景を書く}

### 実施条件

{例: 即時実施可 / 「{他ブランチ名}」が完了してから}

## 作業内容

| # | 完了 | 作業内容 |
|---|---|---|
| 1 | - | 未解決事項を `## QA` に記録する |
| 2 | - | {実装タスク（ブランチ固有の作業に書き換える）} |
| 3 | - | `.work/notes/` の関連ノートを更新する |

## 変更内容

実装したファイル（テスト以外）。コミットに積まれる全ファイルを列挙する。

| # | ファイル名 | 新規/編集 | 内容 | 補足 |
|---|---|---|---|---|
| 1 | `{file/path}` | 新規 | {このファイルで何を実装したか} | {補足あれば} |

## テスト

手動テスト・動作確認の実施記録。

| # | 確認内容 | 実測結果 | 判定 |
|---|---|---|---|
| 1 | {確認内容} | (未実施) | - |

## QA

このブランチのスコープの未決定事項を QA-XXX として記録する。決定後は本文の該当箇所に反映する。

### QA-001: {タイトル}

**背景**: {なぜこれを判断する必要があるか}

| # | 案 | 内容 |
|---|---|---|
| 1 | A | {案 A の説明} |
| 2 | B | {案 B の説明} |

**推奨方式**: {A/B のどちらか + 理由を 1〜2 行。「後で決める」は禁止}

**状態**: 未解決

**決定したら反映先**: {ドキュメントの該当セクション}

## 参考ドキュメント

- `{path/to/note.md}`: {何の資料か}

## 関連イシュー

このブランチが解決する `.work/issues/` のイシュー一覧。merge 実行時に自動でクローズされる。
イシューがない場合は表ごと削除してよい。

| # | ID | 概要 | resolution |
|---|---|---|---|
| 1 | ISSUE-{N} | {イシューのタイトル} | resolved |

## 関連ブランチ

直接関連するブランチ（先行・分割兄弟・後続）を列挙する。

| # | ブランチ | 概要 |
|---|---|---|
| 1 | {type/title} | {概要} |

## 次ブランチ候補

| # | タイトル | 概要 | 実施条件 |
|---|---|---|---|
| 1 | {次にやること} | {背景・目的} | {例: 即時実施可 / 「{他候補タイトル}」が完了したら} |
```

## Section rules

| Section | Rule |
|---|---|
| `# {日本語タイトル}` | H1 = the Japanese title (also the file-name stem). Do not overwrite once set |
| `> ブランチ:` | Full git branch name (e.g. `refactor/work-templates-to-ref-inject`) |
| `## 概要` | Goal / background. Includes `### 実施条件` (when this branch may start) |
| `## 作業内容` | Task checklist. Rows 1 (record QA) and 3 (update note) are **mandatory** — never remove them. Mark each finished row's `完了` column with `済`. **All rows must be `済` before merging** |
| `## 変更内容` | Every implementation file added/modified (excluding tests). Fill in as you implement |
| `## テスト` | Manual / smoke-test log: scenario, actual result, verdict (OK / NG). One placeholder row if none |
| `## QA` | Open questions as `QA-XXX`. **Resolve all before merging**; reflect decisions in the relevant doc/note |
| `## 参考ドキュメント` | Links to related notes. Added in the final commit |
| `## 関連イシュー` | `.work/issues/ISSUE-{N}` entries this branch resolves. **Delete the whole heading + table if none** |
| `## 関連ブランチ` | Predecessor / split-sibling / follow-up branches. Keep the placeholder row if none |
| `## 次ブランチ候補` | Follow-up branches mentioned this session (`#` / title / summary / 実施条件). `即時実施可` or `「{other}」が完了したら` |

## Sync note

This template is the **single source of truth** for the branch-document structure. `work:start`
Step 6 only points here — it carries no duplicate template. When the structure changes, edit this
reference; if the `## 次ブランチ候補` columns change, also update `branch-reserve` SKILL.md Step 1
(it reads that section).
