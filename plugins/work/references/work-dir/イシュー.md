# Issue File Format & Index Schema (`.work/issues/`)

Structure for issue files and their indexes under `.work/issues/`. Auto-injected when you create
or edit a file under `.work/issues/`. `issue-save` / `issue-scan` / `issue-create` author issue
files from the template below; `merge` and `issue-tool.py` close them.
Japanese mirror: `イシュー.md` の JP ミラーは `イシュー.jp.md`。

---

## Issue file — `.work/issues/ISSUE-{N}.md`

`{N}` is zero-padded to 3 digits (e.g. `ISSUE-007`). Create with this structure (omit the marked
lines/sections when the data is absent):

```markdown
# {ISSUE-N}: {title}

**Type**: {type}
**Priority**: {priority}
**Created**: {YYYY-MM-DD}
**Tags**: [{tags}]
**Scan scope**: {scope}   ← omit this line if no scope was provided

## Problem

{problem description}

## User's words

{user's words}   ← omit this section if not provided

## Suggested fix

{suggested fix}   ← omit this section if not provided
```

| Field | Values |
|---|---|
| `Type` | `refactor` / `rule-violation` / `ui` / `backend` |
| `Priority` | `high` / `medium` / `low` |
| `Tags` | free-form keywords (e.g. `frontend`, `settings`) |
| `Scan scope` | file/layer that was scanned (provided by `issue-scan`); omit otherwise |

---

## `_index.yaml` — active issue index

Git-ignored (listed in `.work/issues/.gitignore`). Maintained by `issue-save` / `issue-scan`.

```yaml
# Managed by issue-scan / issue-create. Git-ignored (do not commit).
last_id: 0
issues: []
```

### Issue entry

```yaml
- id: ISSUE-007
  title: "{title}"
  created: {YYYY-MM-DD}
  type: {type}
  scan_scope:
    - "{scope}"        # scan_scope: [] if none
  priority: {priority}
  tags: [{tags}]
```

---

## `_index.archive.yaml` — closed-issue / scan record

Committed to git. `merge` and `issue-tool.py close` append here.

```yaml
# Managed by issue-scan / issue-create / merge. Committed to git.
closed_issues: []
scan_records: []
```

---

## Conventions

- Issue IDs are sequential and zero-padded to 3 digits (`ISSUE-001`, `ISSUE-002`, …).
- `_index.yaml` is git-ignored — never commit it.
- A branch's `## 関連イシュー` table lists the issues it resolves; `merge` closes them automatically.
- Do not hand-edit closed-issue records — let `merge` / `issue-tool.py` manage `_index.archive.yaml`.
