# イシューファイル構成と索引スキーマ（`.work/issues/`）

`.work/issues/` 配下のイシューファイルと索引の構成。`.work/issues/` 配下のファイルを作成・編集
するときに自動注入される。`issue-save` / `issue-scan` / `issue-create` が下のテンプレートから
イシューファイルを作成し、`merge` と `issue-tool.py` がクローズする。
英語原文: `イシュー.md`

---

## イシューファイル — `.work/issues/ISSUE-{N}.md`

`{N}` は 3 桁ゼロ埋め（例: `ISSUE-007`）。以下の構成で作成する（データがない行・節は省略）:

```markdown
# {ISSUE-N}: {title}

**Type**: {type}
**Priority**: {priority}
**Created**: {YYYY-MM-DD}
**Tags**: [{tags}]
**Scan scope**: {scope}   ← scope がなければこの行を省略

## Problem

{問題の説明}

## User's words

{ユーザーの発言}   ← なければこの節を省略

## Suggested fix

{修正方針}   ← 不明ならこの節を省略
```

| フィールド | 値 |
|---|---|
| `Type` | `refactor` / `rule-violation` / `ui` / `backend` |
| `Priority` | `high` / `medium` / `low` |
| `Tags` | 自由形式キーワード（例: `frontend`, `settings`） |
| `Scan scope` | スキャン対象のファイル/レイヤ（`issue-scan` が付与）。なければ省略 |

---

## `_index.yaml` — 進行中イシュー索引

git 管理外（`.work/issues/.gitignore` に記載）。`issue-save` / `issue-scan` が管理。

```yaml
# Managed by issue-scan / issue-create. Git-ignored (do not commit).
last_id: 0
issues: []
```

### イシューエントリ

```yaml
- id: ISSUE-007
  title: "{title}"
  created: {YYYY-MM-DD}
  type: {type}
  scan_scope:
    - "{scope}"        # なければ scan_scope: []
  priority: {priority}
  tags: [{tags}]
```

---

## `_index.archive.yaml` — クローズ済みイシュー / スキャン記録

git 管理対象。`merge` と `issue-tool.py close` が追記する。

```yaml
# Managed by issue-scan / issue-create / merge. Committed to git.
closed_issues: []
scan_records: []
```

---

## 規約

- イシュー ID は連番・3 桁ゼロ埋め（`ISSUE-001`, `ISSUE-002`, …）。
- `_index.yaml` は git 管理外 — コミットしない。
- ブランチの `## 関連イシュー` 表に解決するイシューを列挙し、`merge` が自動でクローズする。
- クローズ済み記録は手編集しない — `_index.archive.yaml` は `merge` / `issue-tool.py` に任せる。
