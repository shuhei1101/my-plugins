# イシューファイル構成と索引スキーマ（`.work/issues/`）

`.work/issues/` 配下のイシューファイルと索引の構成。`.work/issues/` 配下のファイルを作成・編集
するときに自動注入される。`issue-scan` / `issue-create` が下のテンプレートから
イシューファイルを作成し、`merge` と `issue-tool.py` がクローズする。
英語原文: `イシュー.md`

---

## イシューファイル — `.work/issues/ISSUE-{N}.md`

`{N}` は 3 桁ゼロ埋め（例: `ISSUE-007`）。以下の構成で作成する

```markdown
# {ISSUE-N}: {タイトル}

**作成日**: {YYYY-MM-DD}

## 概要
何が問題なのかを1〜3文で要約。

## 背景
なぜこのIssueが必要なのか。
関連する仕様・要件・技術的背景。

## 現状
現在の実装状況。

## 問題点
発見された問題の詳細。

### 発生手順

1. {ステップ1}
2. {ステップ2}
3. {ステップ3}

## 原因

なぜこの問題が発生したか。どこでの判断ミス・認識不足・仕様不備が根本原因かを記述する。

## 期待される状態
どうなれば解決と言えるか。

## 修正案

「期待される状態」を達成するための具体的な修正方針を列挙する。
複数案がある場合はすべて列挙し、末尾に **推奨: 案X** を記載する。

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| A | {内容} | {メリット} | {デメリット} |

**推奨: 案A**

### 再発防止

根本原因に遡り、同じ問題が再発しないための対策を列挙する。代表的な切り口:

- 原因となったドキュメント（プラグイン定義・仕様書など）を修正する
- 親クラス・基底クラス・共通モジュールで対策を施す
- `.rules` などのルールファイルに制約を追加して修正漏れを防ぐ

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| A | {内容} | {メリット} | {デメリット} |

## 横展開

今回の修正案の対象範囲を超えて、同様の問題を抱えている可能性がある箇所を列挙する。代表的な切り口:

- 同じ親クラスを継承する他の子クラス
- 他のドメイン・モジュールに存在する類似関数・類似クラス

| No | 対象 | 内容 |
|---|---|---|
| 1 | {対象} | {横展開内容} |

## 関連ドキュメント

| No | ドキュメント | 備考 |
|---|---|---|
| 1 | [{タイトル}]({リンク}) | {備考} |

```

## `_index.yaml` — 進行中イシュー索引

git 管理外（`.work/issues/.gitignore` に記載）。`issue-scan` / `issue-create` が管理。
イシューファイル本文にあえて書かないメタデータ（type / priority / tags / scan scope）はここが持つ。

```yaml
# Managed by issue-scan / issue-create. Git-ignored (do not commit).
last_id: 0
issues: []
```

### イシューエントリ

```yaml
- id: ISSUE-007
  title: "{title}"
  created: {YYYY-MM-DD}
  type: {type}          # refactor / rule-violation / ui / backend
  scan_scope:
    - "{scope}"         # なければ scan_scope: []
  priority: {priority}  # high / medium / low
  tags: [{tags}]
```

---

## `_index.archive.yaml` — クローズ済みイシュー / スキャン記録

git 管理対象。`merge` と `issue-tool.py close` が追記する。

```yaml
# Managed by issue-scan / issue-create / merge. Committed to git.
closed_issues: []
scan_records: []
```

---

## 規約

- イシュー ID は連番・3 桁ゼロ埋め（`ISSUE-001`, `ISSUE-002`, …）。`_index.yaml` の `last_id` が
  最大採番値を保持する。
- `_index.yaml` は git 管理外 — コミットしない。
- ブランチの `## 関連イシュー` 表に解決するイシューを列挙し、`merge` が自動でクローズする。
- クローズ済み記録は手編集しない — `_index.archive.yaml` は `merge` / `issue-tool.py` に任せる。
