# .work/ Directory Guide (Overview)

High-level map of `.work/` — directory structure, the role of each subfolder, and commit
conventions. Auto-injected when you edit any file under `.work/`. For the detailed format of each
subfolder, follow the dedicated reference (auto-injected when you touch that subfolder).
Japanese mirror: `ワークディレクトリ構成.jp.md`

---

## Directory structure

| Path | Purpose | Detailed reference |
|---|---|---|
| `tasks/{folder}/{YYMMDD}-{日本語タイトル}.task.md` | Task document — plan + QA + variations for one branch | `タスクドキュメント.md` |
| `tasks/index.yaml`, `tasks/index.archive.yaml` | Branch index (status / archive) | `タスクインデックス.md` |
| `notes/{category}/{topic}.md` | Snapshot **spec sheet** — the *current* spec/structure of one subject | `ノート記述内容ルール.md` / `ノート命名規則.md` |
| `issues/ISSUE-{N}.md` | Issue files + indexes | `イシュー.md` |

Each subfolder's detailed reference is injected automatically when you create or edit a file under
that path — author the file directly from the injected template.

---

## tasks/

`tasks/index.yaml` is the single source of truth for branch status (`completed: false` = in
progress). Read it at the start of a session to identify the active branch.

A task **folder** (`{YYMMDD}_{title}/`) is a general-purpose work area: it holds one or more task
documents **plus any user-authored files**. The task document always uses the **`.task.md`**
extension so it is distinguishable from user files (glob `*.task.md`).

## notes/

A **snapshot spec sheet** for the project — each note records what one subject *currently is*. Not
auto-loaded by Claude; read on demand and linked from task documents. Notes are stored in
Japanese-named category subfolders (e.g. `フック・自動化/`, `スキル設計/`). `_index.md` catalogs all
notes — always update it in the same commit when you create, rename, or delete a note.

## issues/

Discrete actionable issues, one file per issue. A branch's `## 関連イシュー` table lists the issues
it resolves; `merge` closes them automatically.

---

## Commit conventions

- Mark completed rows in a task document's `## 作業内容` table with `済`; all rows must be `済`
  before merging.
- **Commit `.work/` changes separately from implementation code.** `.work/`-only changes (task
  document updates, notes, etc.) may be bundled together in a single commit.
- `index.yaml` / `_index.yaml` are git-ignored — never commit them.
