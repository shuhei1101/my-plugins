# .work/ ディレクトリガイド（俯瞰）

`.work/` の俯瞰図 — ディレクトリ構成・各サブフォルダの役割・コミット規約。`.work/` 配下の
いずれかのファイルを編集するときに自動注入される。各サブフォルダの詳細フォーマットは、その
サブフォルダを触ったときに自動注入される専用リファレンスを参照する。
英語原文: `ワークディレクトリ構成.md`

---

## ディレクトリ構成

| パス | 役割 | 詳細リファレンス |
|---|---|---|
| `tasks/{folder}/{YYMMDD}-{日本語タイトル}.task.md` | タスクドキュメント — 1 ブランチの計画・QA・変更内容 | `タスクドキュメント.md` |
| `tasks/index.yaml`, `tasks/index.archive.yaml` | ブランチ索引（状態 / アーカイブ） | `タスクインデックス.md` |
| `notes/{カテゴリ}/{topic}.md` | スナップショット**仕様書** — 対象の*現在の*仕様・構成 | `ノート記述内容ルール.md` / `ノート命名規則.md` |
| `issues/ISSUE-{N}.md` | イシューファイル + 索引 | `イシュー.md` |

各サブフォルダの詳細リファレンスは、そのパス配下のファイルを作成・編集するときに自動注入される —
注入されたテンプレートを元にファイルを直接作成する。

---

## tasks/

`tasks/index.yaml` がブランチ状態の単一の正本（`completed: false` = 進行中）。作業開始時に読んで
進行中のブランチを確認する。

タスク**フォルダ**（`{YYMMDD}_{title}/`）は汎用の作業領域 — 1 つ以上のタスクドキュメントに加え、
**ユーザーが任意に作成したファイル**も格納する。タスクドキュメントは必ず **`.task.md`** 拡張子を
持ち、ユーザーファイルと区別する（`*.task.md` で grep）。

## notes/

プロジェクトの**スナップショット仕様書** — 各ノートは 1 つの対象が*今どうなっているか*を記録する。
Claude には自動読み込みされず、必要時に読む／タスクドキュメントからリンクする。ノートは日本語
カテゴリ名のサブフォルダ（例: `フック・自動化/`、`スキル設計/`）に格納する。`_index.md` が全ノートの
カタログ — ノートを新規作成・リネーム・削除したときは必ず同じコミットで更新する。

## issues/

独立した対応可能な課題を 1 ファイル 1 イシューで記録する。ブランチの `## 関連イシュー` 表に解決する
イシューを列挙し、`merge` が自動でクローズする。

---

## コミット規約

- タスクドキュメントの `## 作業内容` で完了した行は `完了` 列を `済` にする。マージ前に全行が `済`
  であること。
- **`.work/` 配下の変更は実装コードのコミットと分ける。** `.work/` 配下の変更同士（タスク
  ドキュメントの更新・ノートなど）はまとめて 1 コミットにしてよい。
- `index.yaml` / `_index.yaml` は git 管理外 — コミットしない。
