# Glossary Authoring Guide

Inclusion bar and file format for registering terms in the project glossary `.claude/rules/glossary.md`.
This reference is auto-injected when you edit the glossary file.
Japanese mirror: `references/conversation/用語集.jp.md`

> Related: for recurrence-prevention logs, see `インシデント.md`.

---

## What the glossary is

A glossary of project-specific nouns, abbreviations, and concepts. It lives at
`.claude/rules/glossary.md` and is treated as an **always-loaded rule**. Because it is always
loaded, every entry costs context on every session — so the bar for adding one is high.

---

## Inclusion bar — register a term only if ALL of these hold

- It is **project-specific**: a coined term, an internal abbreviation, or a word used with a
  non-obvious project-specific meaning.
- Its meaning is **not obvious from its own name** — a reader would genuinely misunderstand or
  fail to understand it without the definition.
- It **recurs** — it is (or will be) referenced repeatedly, not mentioned once in passing.
- The meaning is **not already written anywhere / not self-evident** (see the dedup check below).

When in doubt, do **not** register it. Quality over quantity.

---

## Do NOT register (common low-value entries)

- **"That's already in CLAUDE.md / a rule / a skill description."**
  Those files are the source of truth; duplicating them in the glossary is pure bloat. Rely on the source.
- **"You can tell that just from the folder / file structure."**
  If opening the repo or reading a file name makes the meaning self-evident
  (e.g. "the `skills/` folder holds skills"), skip it.
- General or industry-standard terms that are not project-specific (git, PR, commit, hook, lint).
- One-off mentions with no reuse value.
- A restatement of something already obvious from reading the relevant file.

---

## Dedup check before registering (mandatory)

Before keeping a term, actively search:

1. grep `CLAUDE.md`, every `plugins/*/CLAUDE.md`, `.claude/rules/`, and skill descriptions for the
   term and its concept.
2. If the meaning is already stated there, or is self-evident from the folder / file structure → **discard**.
3. If the same or an adjacent term already exists in `glossary.md` → extend the existing entry instead
   of adding a new one.

---

## File format

`.claude/rules/glossary.md` holds one term table per H2 category heading.

```markdown
# Glossary

## {Category}

| Term | Description |
|---|---|
| {term} | {1–2 sentence definition} |
```

- Append the term to the table under the appropriate H2 category; create the category if none fits.
- Keep each definition to **1–2 sentences** (it is always loaded — stay concise).
- Create the file if it does not exist.
