# グロッサリー記述ガイド

プロジェクト固有の用語集 `.claude/rules/glossary.md` に用語を登録する際の採用基準とファイル形式。
このリファレンスは glossary ファイルを編集するときに自動注入される。
英語ミラー: `references/conversation/グロッサリー.md`

> 関連: 再発防止ログの記述は `インシデント.md` を参照。

---

## グロッサリーとは

プロジェクト固有の名詞・略語・概念を定義する用語集。`.claude/rules/glossary.md` に置かれ、
**常時ロードされるルール**として扱われる。常時ロードされるため、各エントリは全セッションで
コンテキストを消費する — だから登録の基準は高い。

---

## 採用基準 — 以下の全条件を満たす場合のみ登録する

- **プロジェクト固有**である: 造語、内部略語、またはプロジェクト固有の非自明な意味で使われる語。
- 意味が**名前自体から自明でない**。定義なしでは読み手が本当に誤解する/理解できない。
- **繰り返し出る**。一度きりの言及ではなく、繰り返し参照される（される予定の）語。
- 意味が**まだどこにも書かれていない / 自明でない**（下の重複チェック参照）。

迷ったら**登録しない**。量より質。

---

## 登録しないもの（よくある低価値エントリ）

- **「それは既に CLAUDE.md / ルール / スキルの description にある」**
  それらが真実の源であり、glossary への重複記載は純粋な肥大化。源に頼る。
- **「フォルダ / ファイル構成を見れば分かる」**
  リポジトリを開いたりファイル名を読めば意味が自明なもの（例「`skills/` フォルダにはスキルが入っている」）は登録しない。
- プロジェクト固有でない一般語・業界標準語（git, PR, commit, hook, lint など）。
- 再利用価値のない一度きりの言及。
- 該当ファイルを読めば既に自明なことの言い換え。

---

## 登録前の重複チェック（必須）

用語を残す前に、能動的に検索する:

1. `CLAUDE.md`、各 `plugins/*/CLAUDE.md`、`.claude/rules/`、スキルの description を、その用語と
   概念で grep する。
2. 意味が既にそこに書かれている、またはフォルダ / ファイル構成から自明なら → **破棄**。
3. 既存の `glossary.md` に同じ / 近接する用語が既にあれば → 新規追加せず既存エントリを拡張する。

---

## ファイル形式

`.claude/rules/glossary.md` は H2 カテゴリ見出しごとに用語テーブルを持つ。

```markdown
# Glossary

## {カテゴリ名}

| Term | Description |
|---|---|
| {用語} | {1〜2 文の定義} |
```

- 用語は適切な H2 カテゴリのテーブルに追記する。該当カテゴリがなければ新設する。
- 定義は**1〜2 文**に保つ（常時ロードのため簡潔に）。
- ファイルが無ければ新規作成する。
