# Notes Content Rules

What to write in a `.work/notes/` note, plus the fixed note template.
Japanese mirror: `references/ノート記述内容ルール.jp.md`

> For file naming and `_index.md` management, see `ノート命名規則.md`.

---

## What a note is

A note is a **current spec sheet (snapshot)** for one subject — a plugin, skill, hook, convention, or design. It answers one question: *"how is this right now?"*

- Write **only the current state**.
- Do **not** write history, background, or rationale ("why it became this way") in the body.
- Do **not** keep rejected alternatives or past designs in the body.
- When the subject changes, **overwrite** the stale description — delete it, don't append.
- The single place change is recorded is the `## 変更履歴` table at the bottom.

If you find yourself writing "previously…", "originally…", "the reason we changed…", stop — that belongs in `## 変更履歴` (one line) or nowhere.

---

## Fixed template

```markdown
# {対象名} — {一行サマリ}

## 概要

これは何か。今どういう仕様・構成になっているかを 1〜3 行で。

## {セクション名（自由）}

今の状態だけを箇条書き／表で記述する。経緯・「なぜこうなったか」は書かない。

## 参考ドキュメント

- `path/to/related`: 何の資料か

## 変更履歴

| # | 日付 | 変更内容 | 関連タスク |
|---|---|---|---|
| 1 | 260531 | 新規作成 | 260531_notes-spec-and-ref-inject |
```

## Section rules

| Section | Rule |
|---|---|
| `# {対象名} — {一行サマリ}` | H1. Japanese title (technical identifiers stay as-is). One-line summary after the em dash |
| `## 概要` | 1–3 lines. What this is and its present shape. Always first |
| middle section(s) | Free structure (any heading). Current state only — bullets/tables. Add as many as needed |
| `## 参考ドキュメント` | Links to related docs / skills / files. Second-to-last |
| `## 変更履歴` | Always last. One row per change |

### `## 変更履歴` columns

| Column | Content |
|---|---|
| `#` | Sequential number |
| `日付` | `YYMMDD` (6-digit) |
| `変更内容` | One line — what changed in the spec |
| `関連タスク` | The **task-folder name** that made the change (e.g. `260531_notes-spec-and-ref-inject`), **not** the git branch name |

---

## No frontmatter

Do **not** add YAML frontmatter (`created_at`, `updates`, etc.). Frontmatter is hard to read in the JP mirror and invites history-keeping, which conflicts with the snapshot-spec role. Dates live in the `## 変更履歴` table instead.
