## 作業内容
### ステップ 1: ブランチ名を決定
ブランチ名は `{type}/{title}`（例：`feat/test-update`）

### ステップ 2: index.yaml にエントリを追加（メインリポジトリ）

<!-- もしカレントディレクトリに.workフォルダが存在しない場合、ユーザに/work:setupの実行を促してください。 -->

以下のコマンドを実行して新しいブランチエントリを追加します：

```bash
python /home/shuhei2441/.claude/work-scripts/index-tool.py add .work/tasks/index.yaml \
  --branch "{ブランチ名}" \
  --title "{日本語タイトル}" \
  --type {type} \
  --summary "{概要を入力}" \
  --task "{YYMMDD}_{日本語タイトル}"
```

### ステップ 3: ワークツリーを作成
`/worktree-create` スキルを実行し、ワークツリーを作成する

### ステップ 4: タスクフォルダを決定（ワークツリー内）

2. ワークツリーの `.work/tasks/` 配下から各フォルダ名（`YYMMDD_title` 形式）とこのブランチの目的を比較して決定します
   - 既存フォルダに追加: 既存フォルダが同じ目標または機能エリアをカバーしており、このブランチがそれの一部として自然に適合する
     - 例：機能を複数ブランチに分割、フォローアップ修正、関連リファクタリング
   - 新しいフォルダを作成: 関連する既存フォルダがない、または `.work/tasks/` が空

### ステップ 5: タスクドキュメントを作成・記入（ワークツリー内）

タスクフォルダにタスクドキュメントを作成（ルールは作成時に読み込まれる）

### ステップ 6: 最初のコミット — タスクドキュメントを作成し、実装を開始

1. ワークツリー内のタスクドキュメントのみを作業ブランチにコミットする
2. 作成内容をレポート：ブランチ名、ワークツリーパス、タスクドキュメントパス
3. 実装開始：
   - QA エントリが存在する場合 → 開始前にユーザーの確認を求める
   - QA エントリがない場合 → すぐに実装を開始

### ステップ 7: 最終コミット — ノートとタスクドキュメントを更新（すべての実装作業完了後）

- ワークツリーの `.work/notes/` で関連するノートを確認
   - 見つかった場合 → 現在の状態を反映するよう更新する
   - 見つからない場合 → 新規作成
- タスクドキュメントの `## 参考ドキュメント` セクションにノートへのリンクを追加
- `.work/notes/_index.md` を更新（または作成）する：
   - 新しいノートを適切なカテゴリに追加、または既存エントリを更新する
   - `_index.md` が存在しない場合は、現在のノートを全てカテゴリ別にまとめて新規作成する
- 更新したノート＋タスクドキュメントをまとめてブランチの最終コミットとしてコミットする

### ステップ 8: 作業完了時 — `/merge` を提案

- 以下 3 項目がすべて揃っていれば、ユーザーに `/merge`（対象ブランチ名を添える）の実行を提案する
  -  `## 作業内容` テーブルで作業が完了した行の `完了` 列を `済` にする
  -  同タスクドキュメントの `## QA` セクションに未回答（保留中）のエントリが残っていないことを確認する
  -  今回の作業内容が `.work/notes/` 配下のノートに反映・書き起こされていることを確認する
