# work:issue-scan — コードベーススキャン

毎回ソースファイルをランダムに選んで Read し、ref-inject フックが返してくる reference と
比較して、発見した問題を `/work:issue-save` 経由で `.work/issues/` に記録するスキル。
一時的なスキャンブランチを作成し、全ての発見内容をコミットした上で master に自動マージする。

---

## 概要

**前提条件**:
- `.work/issues/` が存在すること（なければ `/work:setup` を実行）

**環境変数**:
- `ISSUE_SCAN_AGENTS`（デフォルト: `1`）— 1 回の実行でスキャンするファイル数。
  `1` = メインエージェントだけで 1 ファイルをスキャン（サブエージェントなし）。
  `2` 以上 = ファイルごとにサブエージェントを並列起動。

**動作方針**:
- ref-inject フックがファイル種別に応じて reference を自動注入してくれるため、
  本スキルは「対象ファイルを選んで Read する」だけでよい
- フックの session+file-hash トークンにより、同一ファイルは 1 セッション 1 回しか注入されない
- 毎回 `chore/issue-scan-*` という一時ブランチを作成し、発見内容をコミット後、
  `--no-ff` で master にマージする

---

## タスク

### ステップ0: スキャンブランチを初期化する

#### 条件

- 常に — 最初に実行する

#### 処理

1. `ISSUE_SCAN_AGENTS` 環境変数を読む（デフォルト `1`）; `N` として保持する
2. 現在のブランチが `master`（または `main`）であるか確認する:
   ```bash
   git branch --show-current
   ```
   - master/main でない場合 → 自動ブランチ・マージ（ステップ7）をスキップし、
     最後に現在のブランチへ直接コミットする
3. 一時スキャンブランチを作成して切り替える:
   ```bash
   BRANCH="chore/issue-scan-$(date +%Y%m%d-%H%M%S)"
   git checkout -b "$BRANCH"
   ```

→ ステップ1へ進む

#### 出力

- `BRANCH` 名（例: `chore/issue-scan-20260531-143022`）
- `N` = 並列スキャンエージェント数
- `AUTO_MERGE` = master/main から開始した場合は true、それ以外は false

---

### ステップ1: スキャン履歴を読む

#### 条件

- 常に — ステップ0の後に実行する

#### 処理

1. `.work/issues/` が存在するか確認する
   - 存在しない場合 → `/work:setup` を促して停止
2. `_index.archive.yaml` を読み込む（なければ空として扱う）
   - `scan_records` のエントリ（過去にスキャンしたファイル一覧）を把握する
   - `closed_issues` の `resolution: wontfix` の ID を把握する（結果から除外する）

→ ステップ2へ進む

#### 出力

- スキャン済みファイルパスの集合
- wontfix イシュー ID の集合

---

### ステップ2: スキャン対象ファイルを N 個ランダムに選ぶ

#### 条件

- 常に — ステップ1の後に実行する

#### 処理

1. プロジェクトのソースファイルを列挙する
   - `find` や glob で `**/*.py`, `**/*.ts`, `**/*.tsx`, `**/*.html`, `**/*.js` などを対象に
   - `.work/`・`.git/`・`node_modules/`・`.venv/`・`venv/`・`__pycache__/`・`dist/`・`build/`・
     `.next/`・`.turbo/` などは除外する
2. `_index.archive.yaml` の `scan_records[].scope` に既に登場しているファイルを除外する
3. 残ったファイルから `N` 個ランダムに選ぶ（残りが `N` 未満の場合は全件）
4. 残候補が 0 件のとき: ユーザーに「すべてスキャン済みです。再スキャンしますか？」と確認し、
   Yes なら除外を解いて選び直し、No なら停止する（空スキャンブランチはマージして終了）

→ ステップ3へ進む

#### 出力

- 選ばれたファイルパスのリスト（1 〜 N 件）

---

### ステップ3: ファイルと関連ファイルを Read して reference を取得する

#### 条件

- 常に — ステップ2の後に実行する

#### 処理

**N = 1（シングルエージェントモード）の場合:**

1. 選ばれたファイルを Read する（スキャンの主対象）
2. ref-inject の `PreToolUse(Read)` フックが該当する場合、
   `decision: block` の reason に reference 本文が注入されてくる
3. **関連ファイルも追加で Read して文脈を取り込む**:
   - 同フォルダの兄弟ファイル（例: 主対象が `features/chat/service.py` なら `types.py`, `route.py`, `query.py`）
   - 主対象が依存する側 / 主対象を呼び出している側のファイル（imports を辿る）
   - 主対象がレイヤー横断の問題に該当しそうなら関連レイヤー全体
   - 関連ファイルの選定は判断に必要な範囲に絞る（広げすぎない）
   - 関連ファイル自体はスキャンの主対象ではないので `scan_records.scope` には記録しない
4. 注入がなければ「このファイルに該当する ref-inject reference は無い」と扱い、
   ステップ6へ進む（スキャン記録だけ書く）

→ N=1 で注入あり → ステップ4 / N=1 で注入なし → ステップ6

**N ≥ 2（並列サブエージェントモード）の場合:**

1. [subagent: parallel · await all] 選ばれた各ファイルパスに対して、ファイルを読み込み・注入された reference を受け取り・関連ファイルも文脈として読み・主対象を reference と比較するサブエージェントを起動する
   （戻り値: `[{title, type, priority, tags, scope, problem, suggested_fix, horizontal_notes}]` — 問題が無い場合は空リスト）
2. 全サブエージェントの戻り値を 1 つの発見リストに統合する

→ N≥2 → ステップ5

#### 出力

- N=1: 選ばれたファイルの本文 + 関連ファイルの本文 + 注入された reference 本文（無い場合もある）
- N≥2: 全サブエージェントの発見内容を統合したリスト

---

### ステップ4: ファイルを reference と比較してイシューを発見する

#### 条件

- ステップ3（N=1 パス）で reference が注入されたときのみ実行する

#### 処理

1. 注入された各 reference と選ばれたファイル（および必要に応じてステップ3で読んだ関連ファイル）を照合し、以下を探す:
   - 規約違反（命名・型・コメント・スタイル）
   - アーキテクチャ違反（依存方向・レイヤー境界）
   - 改善余地（DRY 違反・冗長コード・古い書き方など、reference に記載された規約に基づくもの）
   - 保守性の問題（重複ロジック・二重管理・設定の非集中化・共通処理の未抽出）
   - 横断的な問題（他のファイルにも同様のパターンが存在しそうな問題 — 水平展開候補として記録）
2. 関連ファイルは判断材料として使うが、イシュー本体は主対象ファイルに対して立てる
   （関連ファイルにも問題がある場合は同じイシュー内で言及するか、別スキャン回に回す）
3. `wontfix` で既にクローズされているイシューと同じ内容は除外する
4. 独立して対処可能な単位ごとに整理する
5. 各発見内容について、同じパターンがコードベース全体に存在しそうかを記録する（水平展開候補）

→ ステップ5へ進む

#### 出力

- 発見した問題の一覧（タイトル / タイプ / 優先度 / 該当箇所 / 修正案 / 水平展開メモ）

---

### ステップ5: イシューを保存する

#### 条件

- ステップ4（または N≥2 パスのステップ3）で問題が見つかったときのみ実行する

#### 処理

1. 発見した各問題について `/work:issue-save` を呼び出す:
   - タイトル / タイプ / 優先度 / タグ / スコープ（= 選ばれたファイルパス）/ 問題の説明 / 修正案 / 水平展開メモ
   - issue-save が返す ISSUE ID を収集する

→ ステップ6へ進む

#### 出力

- 作成したイシュー ID のリスト

---

### ステップ6: スキャン記録を更新する

#### 条件

- 常に — 問題が見つからなくてもスキャンしたファイルごとに必ず実行する

#### 処理

1. スキャンした各ファイルについて、`_index.archive.yaml` の `scan_records` に以下を追記する:
   ```yaml
   scan_records:
     - date: {YYYY-MM-DD}
       skill: issue-scan
       scope: "{選ばれたファイルパス}"
       issues_found: [{ISSUE-N}, ...]   # 0 件なら空リスト
   ```
2. `_index.archive.yaml` が存在しなければ `closed_issues: []` と `scan_records: []` で新規作成する

→ ステップ7へ進む

---

### ステップ7: コミットして master にマージする

#### 条件

- 常に — ステップ6の後に実行する

#### 処理

1. `.work/issues/` 配下の新規・更新ファイルをステージする:
   ```bash
   git add .work/issues/
   ```
2. ステージされた変更があれば、スキャンブランチにコミットする:
   ```bash
   git commit -m "chore: issue-scan — {N} ファイルスキャン, {M} イシュー発見"
   ```
   - ステージするものがなくても、アーカイブ更新分は必ずコミットする
3. `AUTO_MERGE` が true（master/main から開始）の場合:
   ```bash
   git checkout master
   git merge --no-ff {BRANCH} -m "chore: merge issue-scan results from {BRANCH}"
   git branch -d {BRANCH}
   ```
4. `AUTO_MERGE` が false（フィーチャーブランチから実行）の場合:
   スキャンブランチはそのままにし、手動マージが必要な旨をユーザーに通知する

→ ステップ8へ進む

---

### ステップ8: 結果をレポートする

#### 条件

- 常に — 最後に実行する

#### 処理

1. 以下をユーザーに報告する:
   - スキャンしたファイルパス（複数の場合はすべて）
   - 各ファイルで reference が注入されたかどうか（注入されなかった場合は対応する ref-inject フックが無い）
   - 作成したイシュー数とその一覧（ID / タイトル / 優先度）
   - 問題が 0 件の場合はその旨
   - マージ済みのスキャンブランチ名（`AUTO_MERGE` が false の場合はマージ待ちの旨）
2. 修正予定なしの場合は `_index.archive.yaml` の `resolution: wontfix` で閉じられる旨を伝える
