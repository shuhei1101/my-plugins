# work:quick-task — 軽量タスク（ブランチなし）

git ブランチを切るほどでもない作業向け: 純粋な調査・確認、および gitignore 除外・未追跡ファイル
のみの編集。ブランチライフサイクル全体（ワークツリー・`index.yaml` 登録・QA ゲート・merge）を
スキップし、簡単な依頼を簡単なまま処理する。

> `work:start` の軽量版。`work:start` は **追跡ファイルにコミットされる**実装向け。
> `work:quick-task` はコミットされない作業全般向け。

---

## タスク

### Step 1: 軽量タスクであることを確認

#### 条件

- 常に — 最初に実行

#### 処理

1. 依頼が次のいずれか（git ブランチ不要）に該当するか確認する:
   - **調査・確認のみ** — 質問への回答、コード読解、挙動の説明、状態確認。ファイル変更なし。
   - **未追跡ファイルのみの変更** — 編集対象が gitignore 除外・未追跡ファイルだけ（不明なときは
     `git check-ignore -v <path>` / `git status` で確認）。コミットされないためブランチ不要。
2. **追跡ファイルへのコミットを伴う変更が必要な場合** → 中止して `/work:start` を実行する
   （このスキルは入口として誤り）。

→ Step 2 へ

#### 補足

- 追跡ファイルのコミットが必要か不明なときは `/work:start` を優先 — ブランチが安全な既定。

---

### Step 2: 作業を実施

#### 条件

- Step 1 で軽量タスクと確認済み

#### 処理

1. 現在のチェックアウト上で調査または未追跡ファイルの編集を直接行う。
   - ワークツリーも新規ブランチも作らない。
2. 調査結果・実施内容をレスポンスでユーザーに報告する。

→ Step 3 へ

#### 補足

##### 禁止事項

- ワークツリー・git ブランチを作らない
- `.work/tasks/index.yaml` に登録しない
- git 追跡ファイルをコミットしない（必要になったら `/work:start` に切り替える）

---

### Step 3: 必要ならタスクドキュメントを記録

#### 条件

- 調査・結果が記録に値するほど実質的、**または** ユーザーが記録を求めた

#### 処理

1. `.work/tasks/{YYMMDD}_{title}/{YYMMDD}-{日本語タイトル}.task.md` に軽量なタスクドキュメントを
   作成し、依頼と調査結果を記録する。`*.task.md` を書き込むと `タスクドキュメント` リファレンス
   テンプレートが自動注入されるので、それを元に該当セクションのみ記入する（軽量タスクは通常
   `# タイトル`・`## 概要`・短い調査結果だけでよい）。
2. ドキュメントは **コミットしない** — 作業用の記録として残す。残したい場合はユーザーが後で
   コミットするか、将来のブランチに取り込む。`work:quick-task` はコミットしない。

→ 完了。

#### 補足

- 些細な質問では本ステップを丸ごとスキップ — 簡単な回答ごとにドキュメントを作らない。
- 記録は任意 — `quick-task` を軽量に保つ。
