# work:quick-task — 軽量タスク（調査）

**ソースコードをメインに編集しない**作業向け — 調査・確認・リサーチ・挙動の説明。ブランチを切り、
調査結果を記録した軽量なタスクドキュメントを作成してコミットする。ブランチに保存するのが通常で、
ブランチを切ること・コミットすることへの制限はない。

> `work:start` の対。`work:start` は**ソースコード実装**向け、`work:quick-task` は
> **調査・非実装**向け。どちらもブランチ + タスクドキュメントを作るが、quick-task はドキュメントと
> ライフサイクルを軽量に保つ。

---

## タスク

### Step 1: 軽量タスクであることを確認

#### 条件

- 常に — 最初に実行

#### 処理

1. 依頼が **ソースコードをメインに編集しない** — 調査・確認・リサーチ・コード読解・挙動の説明 —
   ことを確認する。
2. **依頼がソースコード実装中心の場合** → 代わりに `/work:start` を実行する。

→ Step 2 へ

#### 補足

- 判定基準は「ソースコードをメインに編集するか」であって、ファイルが変わるか否かではない。
  軽量タスクでもファイルを触ることはある（例: 自身のタスクドキュメントの作成）。

---

### Step 2: ブランチ + 軽量タスクドキュメントを作成

#### 条件

- Step 1 で軽量タスクと確認済み

#### 処理

1. ブランチ名 `{type}/{title}` を決める — 調査作業は通常 `docs/` か `chore/`。`${WORK_BRANCH_AUTHOR}`
   設定時は作者セグメントを挿入（`{type}/{author}/{title}`）。
2. メインリポジトリに index エントリを追加:

   ```bash
   python ${CLAUDE_PLUGIN_ROOT}/scripts/index-tool.py add .work/tasks/index.yaml \
     --branch "{full-branch-name}" \
     --title "{日本語タイトル}" \
     --type {type} \
     --summary "{summary}" \
     --task "{YYMMDD}_{title}"
   ```

3. ブランチ（`${WORK_USE_WORKTREE}` が falsy でなければワークツリーも）を作成:
   `/work:worktree-create {full-branch-name}` を起動。
4. ブランチ内で `.work/tasks/{YYMMDD}_{title}/{YYMMDD}-{日本語タイトル}.task.md` に **軽量な**
   タスクドキュメントを作成する。`*.task.md` を書き込むと `タスクドキュメント` テンプレートが
   自動注入されるので、軽量タスクに必要な分だけ記入する: H1 タイトル・`> ブランチ:`・`## 概要`・
   調査結果セクション。実装/テストのセクションはプレースホルダーのままか削除してよい。

→ Step 3 へ

#### 補足

- `YYMMDD` は 6 桁。`index.yaml` は gitignore されており master へのコミットは不要。

---

### Step 3: 調査・記録・保存

#### 条件

- Step 2 完了

#### 処理

1. ブランチ上で調査を行い、結果をタスクドキュメントの `## 概要` / 調査結果セクションに記録する。
2. タスクドキュメントをブランチにコミットする。
3. quick-task はライフサイクルを軽量に保つ: 「実装前に QA を解決」ゲート **なし**、`.work/notes/`
   更新の必須 **なし**、merge の必須 **なし**。ユーザーがマージを望む場合のみ `/work:merge` を提案。

→ 完了。

#### 補足

- 途中でソースコード実装が必要になったら、本ブランチ上で `work:start` のライフサイクルに従って続行
  する（または `/work:start` を実行）。
