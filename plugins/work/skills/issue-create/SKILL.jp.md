# work:issue-create — ユーザー入力からイシューを登録

ユーザーが入力した困りごとを AI が解釈し、独立した問題に分割して
`/work:issue-save` 経由で `.work/issues/` にイシューとして保存するスキル。

例: 「チャット画面の履歴が見づらいし、設定が次回起動でリセットされる」
→ ISSUE-006: チャット履歴 UI の視認性改善
→ ISSUE-007: 設定の永続化不具合

---

## 概要

**前提条件**:
- `.work/issues/` が存在すること（なければ `/work:setup` を実行）

**分割の考え方**:
- 独立して対処可能な問題は別イシューにする
- 同一原因から生じる複数の症状は 1 つのイシューにまとめる

---

## 作業内容

### ステップ1: 現在のイシュー状況を確認する

#### 条件

- 常に — 最初に実行する

#### 処理内容

1. `.work/issues/` が存在するか確認する:
   - 存在しない場合 → 先に `/work:setup` を実行するよう伝えて停止
2. `_index.yaml` が存在すれば読み込む:
   - 現在の `last_id` を把握する（なければ 0 として扱う）

→ ステップ2へ進む

#### 出力

- 現在の `last_id`

---

### ステップ2: ユーザーの入力を解釈して分割する

#### 条件

- 常に — ステップ1の後に実行する

#### 処理内容

1. ユーザーの入力（引数またはプロンプト内の記述）を読み取る
2. 説明を独立した問題単位に分割する:
   - 別々に修正できる問題は別イシューにする
   - 同一コンポーネント・同一原因なら 1 つにまとめる
3. 各問題について以下の情報を決める:
   - **タイトル**: 問題を端的に表す 1 文（動詞 + 対象）
   - **タイプ**: `refactor` / `rule-violation` / `ui` / `backend` から選ぶ
   - **優先度**: ユーザーの説明から推定する（`high` / `medium` / `low`）
   - **タグ**: 関連するキーワード（例: `frontend`, `settings`, `history`）
4. 分割結果をユーザーに提示して確認を取る:
   - 提示形式: 「この説明を以下の N 件のイシューに分割します。よろしいですか？」
   - 各イシューのタイトル・タイプ・優先度を一覧表示する
5. ユーザーが修正を求めた場合は分割内容を調整してから次へ進む

→ ステップ3へ進む

#### 出力

- 確定したイシューの分割リスト（タイトル・タイプ・優先度・タグ）

---

### ステップ3: イシューを記録する

#### 条件

- 常に — ステップ2の後に実行する

#### 処理内容

1. 確定したイシューごとに以下を呼び出す:
   ```
   /work:issue-save --title "{タイトル}" --type {タイプ} --priority {優先度} --tags {タグ} --problem "{問題の概要}" --user-words "{ユーザーの入力からの引用}" --fix "{修正案（わかれば）}"
   ```
   - `--user-words` はユーザーの入力が明確に引用できる場合のみ使用する
   - 修正案が不明な場合は `--fix` を省略する
   - 次のイシューに進む前に `issue-save` が ISSUE ID を返すまで待つ
2. 返ってきた ISSUE ID をすべて収集する

→ ステップ4へ進む

---

### ステップ4: 結果をレポートする

#### 条件

- 常に — 最後に実行する

#### 処理内容

1. 作成したイシューの一覧をレポートする:
   - 各イシューの ID・タイトル・優先度
2. 優先度を変更したい場合は `_index.yaml` を直接編集するよう伝える

#### 補足

- このスキルでは `git commit` を実行しない — ユーザーが確認した後にコミットする
