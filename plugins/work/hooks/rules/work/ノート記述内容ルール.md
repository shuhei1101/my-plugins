# ノート記述内容ルール

## ノートとは

ノートは 1 つの対象（プラグイン・スキル・フック・規約・設計）の現在の仕様書（スナップショット）。
答えるべき問いはただ 1 つ — *「これは今どうなっているか」*。

- 現在の状態だけを書く。履歴・背景・「なぜこうなったか」という理由、却下案・過去の設計は本文に残さない。
- 対象が変わったら古い記述は上書きして消す（追記しない）。

## 固定テンプレート

```markdown
# {対象名} — {一行サマリ}

## 概要

これは何か。今どういう仕様・構成になっているかを 1〜3 行で。

## {セクション名（自由）}

今の状態だけを箇条書き／表で記述する。経緯・「なぜこうなったか」は書かない。

## 参考リンク

<!-- 参考になるソースコードやドキュメントを記載する -->

- `{path/to/file }`: {何の資料か}

```

## サブフォルダルール

ノートは `.work/notes/` 配下のカテゴリサブフォルダに格納する。
サブフォルダ名は `_index.md` のカテゴリヘッダーと一致する日本語名（例: `フック・自動化/`、`スキル設計/`）。
新規ノートを作成する前に `_index.md` を読み、対象に合ったカテゴリを特定してから配置する。


## ファイル命名

ファイル名と H1 タイトルは日本語で記述する。ツール名・コマンド名・コードシンボルなど技術識別子はそのまま残す。

|             | 例                                                                  |
| ----------- | ------------------------------------------------------------------- |
| ファイル名  | `ノートインデックス同期ルール.md`                                   |
| H1 タイトル | `# ノートインデックス同期ルール — _index.md 自動更新促進の設計メモ` |

トピックそのものが英語識別子の場合は、日英混在名も可

## _index.md 管理

`_index.md` は `.work/notes/` 配下の全ノートのカタログ。ノートを変更したときは必ず同じコミットで `_index.md` も更新する。

| 操作             | `_index.md` に必要な変更                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------- |
| ノートを新規作成 | 適切なカテゴリセクションにエントリを追加（リンクはサブフォルダ相対パスで記述、例: `スキル設計/foo.md`） |
| ノートをリネーム | エントリのファイルリンクとタイトルを更新                                                                |
| ノートを削除     | エントリを削除                                                                                          |

新規作成前に `_index.md` を読む — 重複確認と適切なカテゴリ特定のため。
