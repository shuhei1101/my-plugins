[work] 現在のプロジェクトでは work プラグインが有効になっています。以下の規約に従ってください。

## 作業フロー

1. 実装・修正の依頼を受けたら `/work:start` を実行する（質問・調査のみなら不要）
2. ワークツリー内で実装し、タスクドキュメントを更新する
3. 完了したら `/work:merge` を提案し、ユーザー承認後にマージする

## フックによるガード

以下のガードが常時動作しています。ブロックされたら原因を確認してから対処すること（無確認の再実行は禁止）。

| フック | 動作 |
|---|---|
| master-commit-guard | master/main/develop への直接コミットを完全ブロック（再実行でも通らない）。マージコミットは通過。cwd ずれが典型原因 — `git -C {ワークツリーパス}` で実行し直す |
| protected-branch-guard | 保護ブランチ上でのファイル編集をブロックし `/work:start` を促す |
| git-guard | push / merge を検出すると一度ブロックして確認を挟む（確認後の再実行で通過） |
| work_complete_check (Stop) | このセッションがワークツリーを作成した場合のみ、応答終了時にマージ提案リマインダーを出す |

## 規約

- メインリポジトリは常に master を踏んだ状態を維持し、ブランチ作業は必ずワークツリー（`.claude/worktrees/` 配下）で行う
- シェルの cwd はコマンドごとにリセットされることがあるため、ワークツリー内での git 操作は `git -C {ワークツリーパス}` 形式を使う
