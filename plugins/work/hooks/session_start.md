[work] work プラグイン概要（セッション開始時注入）

## 作業フロー

1. 実装・修正の依頼を受けたら `/work:start` を実行（質問・調査のみなら不要）
2. ワークツリー内で実装し、タスクドキュメントを更新する
3. 完了したら `/work:merge` を提案し、ユーザー承認後にマージする

## work-tools MCP ツール

| ツール | 用途 |
|---|---|
| `worktree_create` | ブランチ + ワークツリー作成（`.claude/worktrees/` 配下）+ セッショントークン作成 |
| `worktree_remove` | ワークツリー + ブランチ削除 + トークン削除 |
| `index_add` | `.work/tasks/index.yaml` にエントリ追加 |
| `index_set_completed` | 同上で完了マーク |
| `index_archive` | 完了エントリをワークツリーの `index.archive.yaml` へ移動 |
| `issue_close` | `.work/issues/` のイシューをクローズ |

## ガード（フック）

- master/main/develop への直接コミットは完全ブロックされる（マージコミットは通る）。ブロックされたら cwd とブランチを確認し、`git -C {ワークツリーパス}` で実行し直すこと
- メインリポジトリは常に master を維持する。ブランチ作業は必ずワークツリーで行う
- Stop 時のマージ提案リマインダーは、このセッションがワークツリーを作成した場合のみ発火する

## 注意

- シェルの cwd はコマンドごとにリセットされることがある。ワークツリー内での git 操作は `git -C {ワークツリーパス}` 形式を使うこと
