# Claude 指示ファイルの記述ルール

このルールは、Claude が指示として読み込むすべてのファイル（`CLAUDE.md`、`SKILL.md`、`.claude/rules/*.md`、スタンドアロンプロンプトファイル等）の作成・編集に適用されます。

## 基本ルール：AIへの指示は英語で書く

Claude Code は指示ファイルを自動読み込みします。これらのファイルの内容は**必ず英語**で書いてください。Claude は翻訳のオーバーヘッドなしに明確・的確な指示を受け取れます。

## バイリンガルファイル規約

すべての指示ファイルには、人間の著者が参照するための日本語ミラーが対になって存在します。**ミラーをどこに置くかは、Claude Code がそのファイルをどう読み込むかによって変わる**：

### ファイル名指定の自動ロード（CLAUDE.md, SKILL.md）

これらは Claude Code が**正確なファイル名**で読み込みます。JP ミラーは同じディレクトリに `<basename>.jp.md` として置く：

| Claude が自動読み込み（英語） | 人間の参照用のみ（日本語） |
|------------------------------|--------------------------|
| `CLAUDE.md` | `CLAUDE.jp.md` |
| `SKILL.md` | `SKILL.jp.md` |

Claude は正確なファイル名にしか反応しないため、`CLAUDE.jp.md` や `SKILL.jp.md` が自動ロードされることはない。

### ディレクトリ再帰スキャンの自動ロード（`.claude/rules/`）

`.claude/rules/` 配下は、サフィックスに関わらず**すべての `.md` ファイル**が再帰的に発見・自動ロードされる。`.jp.md` を `.claude/rules/` 内に置くと、JP 版も自動ロードされてしまう（拡張子による除外はない）。

JP ミラーを自動ロードさせないためには、並列ディレクトリに置く：

| Claude が自動読み込み（英語） | 人間の参照用のみ（日本語） |
|------------------------------|--------------------------|
| `.claude/rules/<name>.md` | `.claude/rules-jp/<name>.md` |

`.claude/rules-jp/` は Claude Code がスキャンするディレクトリではないため、ここに置けば自動的に対象外になる。`claudeMdExcludes` 設定は不要。

## 更新ワークフロー

指示ファイルに変更が必要な場合：

1. **まず JP ミラーを更新する** — 日本語で変更内容を記述し、意図が正しく表現されているか確認する
2. **次に英語本体を更新する** — 同じ変更を権威ある英語ファイルに反映する
3. **両ファイルは常に同期を保つ。** 片方だけ更新してはいけない

ユーザーは日本語で指示を出します。あなたがすべきことは：
- 日本語（JP ミラーまたはユーザーのメッセージ）で意図を受け取る
- 対応する英語の権威ファイルを記述・更新する
- JP ミラーも同期させる

## CLAUDE.md と `.claude/rules/` の使い分け

指示の必要頻度で置き場所を選ぶ：

- **CLAUDE.md** — 毎セッションで Claude が必要とする指示（worktree ワークフロー、コミット規約、サーバー管理、プロジェクト全体のメタルール）。毎セッション読み込まれるので **約200行以下** に保つ
- **`.claude/rules/<name>.md`（`paths:` frontmatter 付き）** — 特定フォルダ・ファイルパターンに固有の指示。マッチするファイルを Claude が読んだときだけロードされる。CLAUDE.md をスリムに保ち、関係ない場面でルールにコンテキストを使わない

`paths:` frontmatter の例：

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "src/api/**/*.tsx"
---

# API rules
- ...
```

`paths:` を持たないルールファイルは、CLAUDE.md と同じく無条件にロードされる。

## ルールをいつ作るか

以下の条件に当てはまるとき、`paths:` 付きの `.claude/rules/<name>.md` を新規作成する：

- 特定のフォルダ・ファイルを編集するときだけ必要な指示である
- 毎セッションのコンテキストに常時入れる必要がない
- プロセス/規約ルール（そのフォルダでどう作業するか）か、ソース↔ドキュメント紐付けルール（このフォルダに対応する仕様書の一覧）のどちらかにあてはまる

以下の場合は **CLAUDE.md** に書く：

- 編集するフォルダに関係なく、毎セッションで Claude が知っておく必要がある
- worktree作成・コミット形式・サーバー管理など、プロジェクトのメタワークフローの一部
- 自然なフォルダスコープを持たないプロジェクト全体のルール

| 指示の種類 | 置き場所 |
|---|---|
| worktree setup / コミット形式 / サーバーポート | CLAUDE.md |
| wiki 編集規約 | `.claude/rules/wiki-work.md`（`paths: wiki/**/*.md`） |
| Python 実装規約 | `.claude/rules/implementation.md`（`paths: src/**/*.py`） |
| あるソースフォルダを支配する仕様書の一覧 | `.claude/rules/<domain>.md`（対応する paths） |
| フォルダスコープを持たないプロジェクト全体のルール | CLAUDE.md |

## path-scoped ルールの2パターン

1. **プロセス／規約ルール** — そのフォルダで作業するときの方法を書く（例：wiki 編集規約、プロンプト記述ルール）。自己完結する
2. **ソース ↔ ドキュメント紐付けルール** — 短いルールで、主目的はそのフォルダを支配する wiki/spec ドキュメントへのリンクを並べること。Claude がそのパスのソースを編集するとき、「関連する仕様は X, Y, Z」と即座に注入され、実装が仕様と乖離しないようにする

## メタルール：ルールファイルを編集するとき

`.claude/rules/` 配下を編集するときは：

1. そのルールに参照されている wiki/docs と内容が整合しているか確認。乖離していれば更新（一つの真実源を守る）
2. 対応する `.claude/rules-jp/<同名>.md` を同じ内容で更新（JP ミラーを同期）

## 実装 ↔ wiki 同期サイクル

「ソース ↔ ドキュメント紐付けルール」が持つ wiki 参照リストは、コード・ルール・wiki の三者を同期させるループを作る：

1. **コードを編集する** → そのパスのルールが自動ロードされ、参照 wiki リストが表示される。仕様と実装が乖離していないか確認し、乖離があれば両方を更新する（wiki に新挙動を反映 / ルールの参照リストに追加・削除が必要なら更新）

2. **ルールファイルを編集する** → 参照 wiki が内容と整合しているか確認する。更新後に `.claude/rules-jp/<同名>.md` ミラーも同期する

3. **wiki を編集する** → そのwikiを参照しているルールが存在するか確認する。ルールの記述が古くなっていれば更新する

このサイクルにより：
- 機能を実装したら wiki 更新が自動的に促される
- ドキュメントを更新してもルールと乖離しない
- ルールのインデックスが正確に保たれる

## ファイル名まとめ

| ファイル | 言語 | Claude が読む？ | 目的 |
|---------|------|-----------------|------|
| `CLAUDE.md` | 英語 | はい（自動） | プロジェクトレベルの指示 |
| `CLAUDE.jp.md` | 日本語 | いいえ | CLAUDE.md の人間向け参照 |
| `SKILL.md` | 英語 | はい（自動） | スキル定義 |
| `SKILL.jp.md` | 日本語 | いいえ | SKILL.md の人間向け参照 |
| `.claude/rules/<name>.md` | 英語 | はい（`paths:` がマッチしたとき。`paths:` 無しなら常時） | フォルダ別/常時のルール |
| `.claude/rules-jp/<name>.md` | 日本語 | いいえ（並列ディレクトリでスキャン対象外） | ルールの人間向け参照 |

## 新しい指示ファイルを作成するとき

ゼロから作成する場合：

1. 日本語版（`*.jp.md` または `.claude/rules-jp/` 配下）を先に下書きして意図を確定させる
2. 英語版を翻訳・記述する
3. 両ファイルを一緒にコミットする

## やってはいけないこと

- `CLAUDE.md` / `SKILL.md` / `.claude/rules/*.md` の中に日本語のコンテンツを書かない — Claude がそのまま読む
- ルールの JP ミラーを `.claude/rules/` 内に置かない（自動ロードされる）。**必ず `.claude/rules-jp/`** に置く
- 英語本体と異なる内容の JP ミラーを作らない
- JP ミラーの作成を省略しない — 著者が将来編集するときに必要
