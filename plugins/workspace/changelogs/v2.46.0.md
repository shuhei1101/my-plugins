# workspace v2.46.0

## refactor: split Stop hook inline python into hooks/scripts/

The Stop hook's inline `python -c "..."` was extracted into a script file alongside the existing `hooks/scripts/*.py` so every hook in workspace follows the same shape: `hooks.json` → `hooks/scripts/{name}.py` → `hooks/scripts/_common.py`.

### Changes

- Added `hooks/scripts/_common.py` — shared helpers (`read_hook_input`, `env_truthy`, `exit_if_stop_loop`, `already_dispatched_this_session`, `emit_block_reason`)
- Added `hooks/scripts/stop.py` — replaces the Stop inline python; reads `WORKSPACE_STOP_REMINDER` / `WORKSPACE_MERGE_PROPOSAL` and emits the appropriate prompt
- `hooks/hooks.json`: Stop entry now points to `hooks/scripts/stop.py` instead of an inline `-c` block

### Behavior

Identical to v2.43.0. Same env toggles (`WORKSPACE_STOP_REMINDER`, `WORKSPACE_MERGE_PROPOSAL`), same prompt files (`stop.md` / `stop-no-merge.md`).

### Why

Inline python in `hooks.json` is fragile under quote nesting (incident `statusline-python-quote-nesting`), kills syntax highlight / lint, and duplicates stdin / env / block-reason boilerplate. The extracted form lets new hooks reuse `_common.py`.
