# .work/ — workspace Task Management Directory

Managed by the workspace plugin. Claude reads and writes files here to track task and PR lifecycle state.

---

## Directory Structure

| Path | Purpose |
|---|---|
| `tasks/index.yaml` | PR index (`completed: false` = in progress). `last_id` tracks the next PR number |
| `tasks/index.archive.yaml` | Archived (`completed: true`) PR entries. Auto-generated by `trim-index.py` on merge |
| `tasks/{YYMMDD}_{title}/{branch-hyphenated}.md` | One Markdown file per PR — TODO + QA + variations all in a single document |
| `notes/{topic-name}.md` | Temporary working notes and memos (not auto-loaded by Claude) |

### tasks/

`tasks/index.yaml` is the single source of truth for PR status. In-progress PRs have `completed: false`; merged ones have `completed: true`. The `last_id` field tracks the highest PR number assigned so far. On each merge, `trim-index.py` moves completed entries to `index.archive.yaml`, keeping `index.yaml` small. Always read index.yaml at the start of a session to identify the active PR.

One folder per task (`{YYMMDD}_{title}/`). Inside the folder, **one Markdown file per PR** — the filename is the PR's branch name with slashes converted to hyphens (e.g. `PR168/refactor/refactor-task-doc-structure` → `PR168-refactor-refactor-task-doc-structure.md`).

The PR document is the single source of truth for what a PR does. Create it before starting implementation and keep it current. It contains the following sections:

- `## 概要` — purpose / background (includes `### 実施条件`)
- `## 作業内容` — task checklist (mark each completed row's `完了` column as `済`; all rows must be `済` before merging)
- `## 変更内容` — list of every implementation file added or modified (excluding tests)
- `## テスト` — test files added or modified alongside the implementation
- `## QA` — unresolved questions scoped to this PR (resolve before merging; reflect decisions in the relevant spec / document)
- `## 参考ドキュメント` — links to related notes / specs
- `## 関連イシュー` — `.work/issues/` entries this PR resolves (auto-closed by merge)
- `## 関連PR` — predecessor / successor / sibling PRs
- `## 次PR候補` — follow-up PRs to reserve via `/work-kit:pr-handoff`

### notes/

**Role**: Temporary working notes at the level of meeting minutes or design memos. **Not auto-loaded by Claude** — treat as informal scratch space, not official documentation.

Flat structure (**no subfolders**). One note per topic. No duplication — use links instead.

**Lifecycle**:
1. Write freely during planning and investigation (throwaway is fine)
2. After work is done, promote valuable content to permanent knowledge via `/workspace:notes-to-claude`:
   - Reusable procedures or file dependencies → rule (`.claude/rules/`)
   - Project-wide conventions or prohibitions → `CLAUDE.md`
   - Detailed reference material → `.claude/references/`
3. Delete notes once promoted

Content that doesn't need promotion (temporary comparisons, scratchpad investigations, rejected ideas) can stay as-is indefinitely.

---

## Conventions

- Mark completed rows in the `## 作業内容` table with `済` in the `完了` column
- Promote valuable notes to permanent knowledge using `/workspace:notes-to-claude`
- Append unresolved questions to the PR document's `## QA` section
- Confirm all rows in the task table are `済` before merging

---

## workspace Skills

| Skill | Purpose |
|---|---|
| `/workspace:setup` | Initialize `.work/` (run once per project) |
| `/workspace:work-start` | Create task folder, PR document, and index.yaml entry |
| `/workspace:merge` | Verify task checklist, merge, update index.yaml, and clean up worktree |
| `/workspace:pr-handoff` | Reserve next PRs from the `## 次PR候補` section using the work-start flow, and record background context in each new PR document |
| `/workspace:notes-to-claude` | Promote `notes/` content to rules, CLAUDE.md, or references |
| `/workspace:plugin-update` | Bring the current project's plugin-generated artifacts (.work/ templates and other plugin static files) in line with the currently installed plugin versions |
