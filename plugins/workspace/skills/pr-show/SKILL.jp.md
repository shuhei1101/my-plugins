# workspace:pr-show — 次ブランチ候補の表示

ブランチドキュメントの `## 次ブランチ候補` テーブルを読み取り、各候補を実施可能、別セッションで進行中、または条件ありの3つのカテゴリに分類します。

> スキル名は互換性の都合上 `pr-show` のままですが、現在はブランチに関する操作をします。

---

## 概要

merge ステップ 13 から抽出されたスタンドアロンスキル。マージ後だけではなく、いつでも呼び出して次のブランチを確認できます。

**データソース**: 指定されたブランチドキュメント内の `## 次ブランチ候補` テーブル。
git ブランチ全体を盲目的にリストアップすることはありません。テーブルに明示的にリストされた候補だけを表示します。

---

## タスク

### ステップ 1: データソースの特定

#### 条件

- 常に実行 — 最初に実行

#### 処理

1. ブランチドキュメントパス引数で呼び出された場合（例：merge ステップ 13 から）、そのファイルを直接使用
2. スタンドアロンで呼び出された場合（引数なし）:
   - `.work/tasks/` 配下のすべてのブランチドキュメントを探す:
     ```bash
     find .work/tasks -type f -name "*.md" -not -name ".*"
     ```
   - アクティブなブランチが1つだけ存在する場合、そのドキュメントを自動的に使用
   - 複数存在する場合、どのブランチを確認するかをユーザーに尋ねる

→ ステップ 2 へ

#### 出力

- ブランチドキュメントパス確認

---

### ステップ 2: `## 次ブランチ候補` テーブルを読み取り

#### 条件

- ステップ 1 完了

#### 処理

1. ブランチドキュメントから `## 次ブランチ候補` セクションを読み取り
2. テーブルにプレースホルダー行のみが含まれている場合（例：`{次にやること}` または単一の `-`）
   → 「次のブランチ候補はありません」と出力して終了

→ ステップ 3 へ

#### 出力

- 候補行のリスト（タイトル、概要、実施条件）

---

### ステップ 3: 各候補を分類

#### 条件

- ステップ 2 完了（テーブルに実データがある）

#### 処理

各候補行について:

**a. 条件がある（条件あり）**:
- 第3列（実施条件）が別の候補を参照している — 例：`「{other}」が完了したら`
- pr-handoff はこれらに意図的にブランチを予約していない
- テーブルから直接リスト — ブランチ検索は不要

**b. 実施可能 または 別セッションで進行中**:
- 第3列が空白または `即時実施可` — pr-handoff がブランチを予約しているはず
- 候補タイトルを検索してブランチを探す:
  ```bash
  git branch --list "*{candidate-title}*"
  ```
- master よりも前にあるコミット数をカウント:
  ```bash
  git log master..{branch} --oneline | wc -l
  ```
- コミット数 ≤ 1 → **実施可能**
- コミット数 ≥ 2 → **別セッションで進行中**
- ブランチが見つからない → pr-handoff が実行されていない。「未予約（pr-handoff が実行されていない）」と記す

→ ステップ 4 へ

#### 出力

- 各候補を3つのカテゴリのいずれかに分類

---

### ステップ 4: テーブルを表示

#### 条件

- ステップ 3 完了

#### 処理

1. テーブルを次の形式で出力:

   ```markdown
   ## 次に実施できるブランチ

   | カテゴリ | ブランチ | 概要 |
   |---|---|---|
   | 実施可能 | {branch} | {title} |
   |  | {branch} | {title} |
   | 別セッションで進行中 | {branch} | {title} ({commit_count} コミット先行) |
   | 条件あり | — | {title} — 条件: `{other-candidate}` が完了したら |
   ```

   - 複数のブランチが同じカテゴリを共有する場合、カテゴリ名は最初の行にのみ記入し、その後のセルは空欄に
   - 項目がゼロのカテゴリ行は省略
   - すべてのカテゴリが空（プレースホルダーテーブルのみ）の場合は「次のブランチ候補はありません」と表示

→ 完了

#### 出力

- ユーザーに提示されたステータスレポートテーブル

## 参考資料

### データソースルール

指定されたブランチドキュメントの `## 次ブランチ候補` テーブルのみを使用 — `git branch --list '*'` を無差別に使用しない。
他のセッションから予約された無関係なブランチは意図的に除外されます。

### 分類知識

| カテゴリ | 詳細 |
|---|---|
| **実施可能** | pr-handoff 予約直後の状態。ブランチは master よりも1コミット（ドキュメント作成コミット）だけ先行。 |
| **別セッションで進行中** | 別の Claude Code セッションがこのブランチに実装コミットを持っている。2コミット以上はユーザーがそこで活発に作業していることを意味する。 |
| **条件あり** | pr-handoff が直列依存アイテムに分類し、ブランチを予約しないことにした候補。先行ブランチがマージされるとすぐに適格になる。 |

### 「進行中」を表示し続ける理由

完全に隠すと「何も残っていない」という印象を与えます。表示することでユーザーは全体的な状態を把握し続けられます。

### 「条件あり」を表示する理由

予約されたブランチとして表示されませんが、ブランチドキュメントの `## 次ブランチ候補` に「次々の」アイテムとして存在します。実施可能なものと並べてリストアップすることで、ユーザーはそれらを見落とさない。
