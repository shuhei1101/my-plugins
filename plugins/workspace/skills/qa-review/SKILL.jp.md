# workspace:qa-review — インタラクティブ QA レビュー

対象 PR の QA.md を読み込み、未解決の各項目を `AskUserQuestion` ツールで最大 4 件ずつまとめて提示する。全質問への回答が完了した後、一括で QA.md に決定内容を反映する。

---

## 作業内容

### ステップ 1: 対象 PR を特定する

#### 条件

- 常に最初に実行

#### 処理内容

1. 現在の会話セッションで作業中の PR がある場合、その QA.md を最優先で使用する
2. 引数に PR 番号が明示されていれば（例: `PR139` または `139`）、それを使って QA.md を探す
3. 上記どちらも該当しない場合:
   - QA.md を検索: `find .work/tasks -name QA.md`
   - 1件のみ見つかった場合は自動選択
   - 複数見つかった場合は `AskUserQuestion` でどの PR をレビューするか尋ねる
4. git ワークツリーも確認する:
   ```bash
   git worktree list
   ```
5. QA.md のパスを確定する（パターン: `.work/tasks/*/PR{N}/QA.md`）

→ ステップ 2 へ

#### 出力

- QA.md のパスが確定している

---

### ステップ 2: 未解決 QA 項目を解析する

#### 条件

- ステップ 1 完了

#### 処理内容

1. QA.md を読み込む
2. `**状態**:` 行に「解決済み」または「却下」が含まれていない `## QA-XXX` セクションを抽出する
3. 未解決項目がない場合 → 「QAに未決定事項はありません」と報告して終了
4. 各項目のID・タイトル・本文サマリーをリスト化する

→ ステップ 3 へ

#### 出力

- 未解決 QA 項目のリスト

---

### ステップ 3: 項目をまとめて提示する

#### 条件

- ステップ 2 完了（未解決項目が 1 件以上ある）

#### 処理内容

`AskUserQuestion` の最大件数（4 件）を上限に、未解決項目をバッチにまとめて提示する:

1. 未解決項目を 4 件ずつのバッチに分割する（4 件未満の場合はそのまま 1 バッチ）
2. 各バッチに対して `AskUserQuestion` ツールを 1 回呼び出す:
   - 各 QA 項目を 1 つの **question** エントリとしてまとめる（最大 4 件）
   - **question**: QA 項目のタイトルと判断に必要な 1〜2 文のサマリー
   - **header**: QA 項目の ID（例: `QA-001`）
   - **options**（各 question で共通）:
     - `解決済み（採用）` — 決定が下された
     - `保留（後で判断）` — 今は保留
     - `却下（対応しない）` — 対応しない
   - **multiSelect**: false
3. 次のバッチがあれば繰り返す。全バッチが終わったらステップ 4 へ

→ ステップ 4 へ

#### 補足

- QA 項目の本文が長い場合は、判断に必要な核心だけを `question` フィールドに要約する
- 各バッチの回答はプロンプト履歴に保持されるため、ステップ 4 での一括反映まで個別更新は不要

---

### ステップ 4: QA.md に全回答を一括反映する

#### 条件

- ステップ 3 完了（全バッチへの回答が揃っている）

#### 処理内容

1. ステップ 3 で収集した全回答をもとに、一括で QA.md を更新する:
   - 「解決済み」: `**状態**: 解決済み — {決定内容または「その他」の自由入力}`
   - 「却下」: `**状態**: 却下 — {理由または「その他」の自由入力}`
   - 「保留」: 該当行をそのまま残す（変更しない）
2. 更新した QA.md を保存する

→ ステップ 5 へ

---

### ステップ 5: 集計レポートを出力する

#### 条件

- ステップ 4 完了

#### 処理内容

1. 集計表を出力する:

   | QA ID | 状態 |
   |---|---|
   | QA-001 | 解決済み |
   | QA-002 | 保留 |

2. 全項目が解決済みの場合 → 「すべての QA が解決しました。実装を進められます。」
3. 未解決の項目が残っている場合 → 残件数を案内する

→ 完了
