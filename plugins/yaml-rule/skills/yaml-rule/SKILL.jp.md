# YAML ファイル管理ルール

このルールは、アセットカタログとプロジェクト設定に使うすべてのYAMLファイルに適用されます。

## 基本原則

物理ファイル（アセット・メディア等）はどのようなフォルダ構成に置いてもよい。プログラムやAIはファイルパスをハードコードせず、**必ずYAML経由でファイルを参照する**。

## YAMLファイルの種類

### index.yaml — アセットカタログ

- カテゴリに属するアセットやファイルを一覧管理する
- プロジェクト初期に1回作成し、ファイルの追加・削除時のみ更新する
- 環境によって値が変わらない（すべての開発者・環境で共通）
- 「何が存在するか」を記述するマニフェスト

### settings.yaml — 環境設定

- `index.yaml` に登録されたアイテムのID別設定値を記述する
- 環境ごとに値が異なる（開発者・デプロイ環境によって変わる）
- `.env` ファイルのようなもの：各環境に専用のコピーが存在する
- **`settings.yaml` はリポジトリにコミットしない。** 代わりに `settings.yaml.sample` をコミットし、各開発者が自分の `settings.yaml` を作成する

### settings.yaml.sample

- `settings.yaml` のテンプレートとしてリポジトリにコミットする
- すべてのキーをプレースホルダー値または初期値で記述する
- 各フィールドの意味をコメントで説明する
- 開発者はこのファイルを `settings.yaml` にコピーして自分の値を入力する

## 開発者ノートブロック

`index.yaml` と `settings.yaml.sample` の先頭には必ず開発者ノートのコメントブロックを設ける。`settings.yaml` 実体にはこのブロックは不要。

このノートブロックは、AI駆動開発における生きたドキュメントとして機能する。管理ルールと変更履歴を記録することで、将来のセッションがgit履歴を遡らなくても完全なコンテキストを持てるようにする。

### フォーマット

```yaml
# =============================================================================
# Developer Note
# =============================================================================
# Purpose:
#   {このファイルが何を管理するか、なぜ存在するか}
#
# Management Rules:
#   - {ルール1例: "各エントリには一意のsnake_case IDを必ず割り当てる"}
#   - {ルール2例: "エントリは削除しない — 非アクティブとしてマークする"}
#
# Change History:
#   - PR{N} ({日付}): {何をなぜ変更したか}
#   - commit {ハッシュ} ({日付}): {何をなぜ変更したか}
# =============================================================================
```

### index.yaml の例

```yaml
# =============================================================================
# Developer Note
# =============================================================================
# Purpose:
#   VTuberアプリの背景画像アセットをすべてカタログ管理する。
#   プログラムはIDで背景を読み込む。物理ファイルパスは自由に変更可能。
#
# Management Rules:
#   - IDはsnake_caseで永続的 — リネーム・再利用禁止
#   - 新しいエントリは末尾に追加して履歴を保持する
#
# Change History:
#   - PR1 (2026-05-01): 背景3件で初期作成
#   - PR4 (2026-05-08): "night_city" 背景を追加
# =============================================================================

backgrounds:
  - id: living_room
    path: assets/backgrounds/living_room.png
    label: リビングルーム
  - id: night_city
    path: assets/backgrounds/night_city.png
    label: 夜の都市
```

### settings.yaml.sample の例

```yaml
# =============================================================================
# Developer Note
# =============================================================================
# Purpose:
#   index.yaml に登録された背景の環境別設定。
#   このファイルを settings.yaml にコピーして自分の環境に合わせて編集する。
#
# Management Rules:
#   - キーはindex.yamlのIDと一致させること
#   - settings.yaml はgitignored — 絶対にコミットしない
#
# Change History:
#   - PR1 (2026-05-01): 初期作成
#   - PR4 (2026-05-08): "night_city" エントリを追加
# =============================================================================

backgrounds:
  living_room:
    enabled: true
    display_order: 1
  night_city:
    enabled: false   # 自分の環境で使う場合はtrueにする
    display_order: 2
```

## ファイル構成パターン

```
{機能名}/
├── index.yaml           # アセットカタログ（コミット対象・環境共通）
├── settings.yaml        # ローカル設定（gitignored・開発者ごと）
└── settings.yaml.sample # テンプレート（コミット対象・開発者ノート付き）
```

`.gitignore` に追加する：

```
settings.yaml
```

## 各ファイルの更新タイミング

| イベント | index.yaml | settings.yaml.sample | settings.yaml |
|---------|------------|----------------------|---------------|
| 新しいアセット追加 | エントリ追加 | キーをプレースホルダーで追加 | キーをローカル値で追加 |
| アセット削除 | 非アクティブ化または削除 | キーを削除 | キーを削除 |
| 新しい設定項目追加 | — | キーとコメントを追加 | キーをローカル値で追加 |
| 構造変更 | 更新＋Change Historyに記録 | 更新＋Change Historyに記録 | 手動で更新 |
