# .work/ — work-kit Task Management Directory

Managed by the work-kit plugin. Claude reads and writes files here to track task and PR lifecycle state.

---

## Directory Structure

| Path | Purpose |
|---|---|
| `tasks/index.yaml` | PR index (`completed: false` = in progress). `last_id` tracks the next PR number |
| `tasks/index.archive.yaml` | Archived (`completed: true`) PR entries. Auto-generated by `trim-index.py` on merge |
| `tasks/{YYYYMMDD}_{title}/PR{N}/TODO.md` | PR task checklist and spec references |
| `tasks/{YYYYMMDD}_{title}/PR{N}/QA.md` | Unresolved questions scoped to this PR |
| `notes/{topic-name}.md` | Temporary working notes and memos (not auto-loaded by Claude) |

### tasks/

`tasks/index.yaml` is the single source of truth for PR status. In-progress PRs have `completed: false`; merged ones have `completed: true`. The `last_id` field tracks the highest PR number assigned so far. On each merge, `trim-index.py` moves completed entries to `index.archive.yaml`, keeping `index.yaml` small. Always read index.yaml at the start of a session to identify the active PR.

One folder per task (`{YYYYMMDD}_{title}/`), containing one or more PR folders (`PR{N}/`).
Each PR folder holds `TODO.md` (task checklist) and `QA.md` (unresolved questions for this PR).

`TODO.md` is the single source of truth for what a PR does. Create it before starting implementation and keep it current. Mark each completed row's Done column as `済`; confirm all rows are `済` before merging.

`QA.md` records unresolved questions scoped to this PR. When the user decides, reflect the decision in the relevant spec or document.

### notes/

**Role**: Temporary working notes at the level of meeting minutes or design memos. **Not auto-loaded by Claude** — treat as informal scratch space, not official documentation.

Flat structure (**no subfolders**). One note per topic. No duplication — use links instead.

**Lifecycle**:
1. Write freely during planning and investigation (throwaway is fine)
2. After work is done, promote valuable content to permanent knowledge via `/work-kit:notes-to-claude`:
   - Reusable procedures or file dependencies → rule (`.claude/rules/`)
   - Project-wide conventions or prohibitions → `CLAUDE.md`
   - Detailed reference material → `.claude/references/`
3. Delete notes once promoted

Content that doesn't need promotion (temporary comparisons, scratchpad investigations, rejected ideas) can stay as-is indefinitely.

---

## Conventions

- Mark completed rows in the TODO.md task table with `済` in the Done column
- Promote valuable notes to permanent knowledge using `/work-kit:notes-to-claude`
- Append unresolved questions to the PR's `QA.md`
- Confirm all rows in the task table are `済` before merging

## work-kit Skills

| Skill | Purpose |
|---|---|
| `/work-kit:setup` | Initialize `.work/` (run once per project) |
| `/work-kit:work-start` | Create task folder, PR folder, TODO.md, QA.md, and index.yaml entry |
| `/work-kit:merge` | Verify TODO, merge, update index.yaml, and clean up worktree |
| `/work-kit:pr-handoff` | Reserve next PRs from the "Next PR candidates" in TODO.md using work-start flow, and record background context in each new TODO.md |
| `/work-kit:notes-to-claude` | Promote `notes/` content to rules, CLAUDE.md, or references |
