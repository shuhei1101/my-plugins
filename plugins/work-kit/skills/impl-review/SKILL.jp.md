# work-kit:impl-review — インタラクティブ実装レビュー

現在の PR ブランチのコミット履歴を分析し、実装内容を `AskUserQuestion` ツールで選択肢形式として 1 件ずつ提示する。ユーザーは「OK / 次へ」か「もっと詳しく」を選びながら変更内容を追うことができる。スマホや SSH 接続など、コードの差分を直接確認しづらい環境で特に有用。

---

## 概要

スキルは最初に内部で「大枠リスト」（変更エリアの一覧）を作成し、そのまま 1 件ずつ対話形式で紹介する（リスト全体のプレビューはユーザーに見せない）。「もっと詳しく」が選ばれると深掘りモードに入り、深掘りが終わると大枠リストの次の項目に戻る。

---

## 作業内容

### ステップ 1: 対象ブランチを特定する

#### 条件

- 常に最初に実行

#### 処理内容

1. 現在の会話セッションで作業中の PR がある場合、そのブランチを最優先で使用する
2. 引数に PR 番号が明示されていれば（例: `PR139`）、それを使って対応するブランチを探す:
   ```bash
   git branch --list "*PR{N}*"
   ```
3. 上記どちらも該当しない場合は現在のブランチを使用する
4. ベースブランチを確認する（デフォルト: `master`）

→ ステップ 2 へ

#### 出力

- 対象ブランチとベースブランチが確定している

---

### ステップ 2: コミットと差分を分析する

#### 条件

- ステップ 1 完了

#### 処理内容

1. コミット履歴を取得する:
   ```bash
   git log {base}..{branch} --oneline
   ```
2. 変更ファイルのサマリーを取得する:
   ```bash
   git diff {base}..{branch} --stat
   ```
3. ベースからのコミットが 0 件の場合 → 「実装コミットがありません」と報告して終了

→ ステップ 3 へ

#### 出力

- コミット一覧と変更ファイルのサマリー

---

### ステップ 3: 大枠リストを内部で作成する

#### 条件

- ステップ 2 完了

#### 処理内容

1. コミットメッセージと変更ファイルを自律的に分析する
2. 関連する変更をグループ化して「変更エリア」（2〜8 件が目安）を作る:
   - 各アイテムは、ファイルタイプではなく目的・機能単位でまとめる（例: 「新スキル qa-review の追加」「plugin.json バージョン更新」）
3. 各エリアについて以下を用意する:
   - 1 行のタイトル（`question` の見出しに使う）
   - 何が変わりなぜそうしたかの 2〜3 文の説明
   - 主な関連ファイル

→ ステップ 4 へ（ユーザーへのプレビュー提示はしない）

#### 出力

- 2〜8 件の変更エリアからなる大枠リスト（内部保持）

#### 補足

- 見せる観点は AI が都度判断する（固定テンプレートなし）
- バックエンド変更: API 変更点・副作用・データモデルへの影響を中心に
- フロントエンド変更: 影響する画面・ユーザーから見える動作の変化を中心に
- 設定・インフラ変更: 有効化/無効化されたものとその影響範囲を中心に
- 変更の大きさに合わせて粒度を調整（1 ファイルの修正なら 1 件、複数機能 PR なら 6〜8 件）

---

### ステップ 4: インタラクティブレビューループ

#### 条件

- ステップ 3 完了

#### 処理内容

大枠リストの各アイテムに対して順番に以下を実行する:

1. `AskUserQuestion` ツールを使って提示する:
   - **question**: そのエリアの 2〜3 文の説明
   - **header**: アイテム番号とタイトル（例: `1/5: qa-review 追加`）
   - **options**:
     - `OK / 次へ` — 理解した。次のアイテムへ
     - `もっと詳しく` — このエリアをさらに詳しく説明してほしい
     - `問題あり` — このエリアに懸念がある。フラグを立てる
   - **multiSelect**: false

2. `OK / 次へ` が選ばれた場合: 次のアイテムへ進む

3. `もっと詳しく` が選ばれた場合（深掘りモード）:
   - そのエリアの詳細情報を提示する（具体的なコード変更・採用理由・リスク等）
   - `AskUserQuestion` を再度呼び出す:
     - **question**: 「さらに深掘りしますか？」
     - **options**: `OK / 終わり` / `別の角度から説明して` / `問題あり`
   - ユーザーが `OK / 終わり` または `問題あり` を選ぶまで続ける
   - 深掘り終了後、大枠リストの次のアイテムへ戻る

4. `問題あり` が選ばれた場合: そのアイテムをフラグ付きで記録し、次のアイテムへ進む

→ ステップ 5 へ

---

### ステップ 5: 完了レポートを出力する

#### 条件

- 全アイテムのレビューが完了（ステップ 4 完了）

#### 処理内容

1. 集計を出力する:
   - レビューしたアイテムの総数
   - フラグが立ったアイテム（あれば）とそのタイトル
2. フラグ付きアイテムがある場合 → 次のアクションを提案する（修正・QA 追記等）
3. フラグなしの場合 → 「すべての実装内容を確認しました。」

→ 完了
