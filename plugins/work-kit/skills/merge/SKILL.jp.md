> 変更する場合は JP ミラーを先に更新し、その後 `SKILL.md` にも反映してください。

---

**スキル名**: merge
**トリガー**: ユーザーが「マージして」「PR をマージしたい」「merge して」と言ったとき（自動起動なし）

---

## 概要

PR のマージフローを実行するスキル。
タスク完了確認・`--no-ff` マージ・ワークツリークリーンアップ・ドキュメント更新を行う。

---

## 作業内容

### ステップ1: マージ対象の PR を特定する

#### 条件

- 常に — 最初に実行する

#### 処理内容

1. `docs/tasks/index.yaml` を読んで進行中の PR（`completed: false`）を確認する
2. 複数ある場合はユーザーにどれをマージするか確認する
3. ブランチ名を特定する: `PR{N}/{type}/{description}`

→ ステップ2へ進む

#### 出力

- マージ対象の PR 番号とブランチ名が確定している

---

### ステップ2: タスクチェックリストを確認する

#### 条件

- ステップ1が完了していること

#### 処理内容

1. `docs/tasks/{task_folder}/PR{N}.md` の `## 作業内容` セクションを読む
2. 未完了（`- [ ]`）のタスクがないか確認する

→ 全て `- [x]` ならステップ3へ進む

#### 出力

- 全タスクが完了済みであることを確認した

#### 補足

##### 条件分岐

- 未完了タスクがある → マージせずユーザーに確認。完了させてから再度実行する

---

### ステップ3: マージを実行する

#### 条件

- 全タスクが完了済みであること

#### 処理内容

1. メインブランチにいることを確認する
2. `--no-ff` でマージする:

```bash
git merge --no-ff -m "{type}({scope}): {description} #PR{N}" PR{N}/{type}/{description}
```

→ ステップ4へ進む

#### 出力

- マージコミットが作成済み

---

### ステップ4: ワークツリーをクリーンアップする

#### 条件

- マージが完了していること

#### 処理内容

1. ワークツリーを削除する:

```bash
git worktree remove ../$(basename $(pwd))-wt-PR{N}
git branch -d PR{N}/{type}/{description}
```

→ ステップ5へ進む

#### 出力

- ワークツリーとブランチが削除済み

#### 補足

##### 禁止事項

- ワークツリーのルートで `Remove-Item -Recurse` や `rm -rf` を実行しない
  （Junction を辿ってメインリポジトリのファイルを破壊する）

---

### ステップ5: ドキュメントを更新する

#### 条件

- ワークツリーが削除済みであること

#### 処理内容

1. `docs/tasks/index.yaml` の該当 PR を `completed: true` に更新する
2. `docs/tasks/qa.md` を確認し、決定済みの事項を `docs/tasks/qa_history.md` に移す
3. 変更があればコミットする:

```bash
git add docs/tasks/
git commit -m "docs: PR{N} マージ後ドキュメント更新"
```

→ ステップ6へ進む

#### 出力

- index.yaml が `completed: true` に更新済み
- qa.md / qa_history.md が最新化済み

---

### ステップ6: 完了報告

#### 処理内容

1. マージ完了をユーザーに報告する
2. 次の PR 候補があれば提示する

#### 補足

##### チェックリスト

- [ ] マージコミットが存在する
- [ ] ワークツリーとブランチが削除済み
- [ ] index.yaml が `completed: true`
- [ ] qa.md が更新済み
