**スキル名**: work-start
**トリガー**: ユーザーが「新しい PR を作って」「新しい作業を始めたい」「work-start して」と言ったとき

---

## 概要

新規 PR 作業を開始するスキル。
タスクフォルダ・PR フォルダ・TODO.md を作成し、仕様書と QA を整備してからワークツリーを準備する。

---

## 作業内容

### ステップ1: PR 番号を決定する

#### 条件

- 常に — 最初に実行する

#### 処理内容

1. `docs/tasks/` 配下の全 `PR{N}` フォルダをスキャンして最大 N を求める
2. 次の PR 番号 = 最大 N + 1（フォルダが存在しない場合は 1）

→ ステップ2へ進む

#### 出力

- 次の PR 番号が確定している

---

### ステップ2: 依頼内容を整理する

#### 条件

- ステップ1が完了していること

#### 処理内容

1. ユーザーから以下を確認する:
   - **タイトル**: タスクフォルダ名に使う短い説明（kebab-case）
   - **タイプ**: `feat` / `fix` / `refactor` / `docs` / `chore` / `test`
   - **TODO リスト**: 今回やることのチェックリスト
   - **関連仕様**: 対応する仕様書が `docs/specs/` にあるか、新規作成か
   - **不明点**: 決まっていないことがあれば

→ ステップ3へ進む

#### 出力

- タイトル・タイプ・TODO・仕様情報・不明点が確定している

---

### ステップ3: タスク・PR フォルダと TODO.md を作成する

#### 条件

- ステップ2が完了していること

#### 処理内容

1. タスクフォルダを作成する: `docs/tasks/{YYYYMMDD}_{title}/`
2. PR フォルダを作成する: `docs/tasks/{YYYYMMDD}_{title}/PR{N}/`
3. TODO.md を作成する:

```markdown
# PR{N} — {title}

## 仕様参照

<!-- 関連仕様書へのリンク -->
<!-- 例: [機能名](../../../specs/{spec-name}.md) -->

## TODO

{各タスクを - [ ] で列挙}

## 変更ファイル

<!-- コミット後に追記 -->
```

→ ステップ4へ進む

#### 出力

- `docs/tasks/{YYYYMMDD}_{title}/PR{N}/TODO.md` 作成済み

---

### ステップ4: 仕様書を整備する

#### 条件

- ステップ3が完了していること

#### 処理内容

1. `docs/specs/` を確認する
2. 関連する仕様書が存在する場合 → 今回の変更に関わる箇所を更新する
3. 存在しない場合 → 新規仕様書を作成する:

```markdown
# {機能名} 仕様

## 概要

{概要}

## 詳細

{詳細仕様}
```

4. TODO.md の「仕様参照」セクションに仕様書へのリンクを追記する

→ ステップ5へ進む

#### 出力

- 仕様書が存在し、TODO.md からリンクされている

---

### ステップ5: 不明点を QA.md に記録する

#### 条件

- ステップ4が完了していること

#### 処理内容

1. ステップ2で確認した不明点を `docs/QA.md` の「進行中」セクションに追記する
2. 不明点がない場合はスキップする

→ ステップ6へ進む

---

### ステップ6: ワークツリーとブランチを作成する

#### 条件

- ステップ5が完了していること

#### 処理内容

1. ワークツリーを作成する:

```bash
git worktree add -b PR{N}/{type}/{title} ../$(basename $(pwd))-wt-PR{N}
```

→ ステップ7へ進む

#### 出力

- ワークツリーが `../repo-wt-PR{N}` に作成済み

#### 補足

##### 禁止事項

- メインブランチ（master/main）に直接コミットしない

---

### ステップ7: ユーザーに報告して承認を待つ

#### 処理内容

1. 作成した内容を報告する:
   - ブランチ名・ワークツリーパス・TODO.md パス・仕様書パス
2. ユーザーの承認を待ってから実装を開始する

#### 補足

##### 禁止事項

- ユーザーの明示的な承認なしに実装を開始しない
