# ref-inject v1.2.0

## 変更

生成されるフックの注入キャッシュを **二層化**した（パターン単位 + リファレンスファイル単位）。

- `templates/hooks/inject_references.py`:
  - トークン schema を単一マップ（pattern をトップレベルキー）から `patterns` / `references` の **2 名前空間**を持つマップへ変更（`TOKEN_NAMESPACES`）
  - `patterns` 層: 従来通り、マッチしたパターンが期限内ならそのパターンを丸ごとスキップ
  - `references` 層: 各 `required` リファレンスについて、本セッションに（どのパターン経由であれ）既に本文注入済みなら **パスのみ**出力し本文は流さない。未キャッシュなら本文全量を注入してリファレンスをキャッシュ
  - 本文注入したリファレンスのみ `references` に `expires_at`（= now + TTL）を記録
  - `_cleanup_expired`: 両名前空間を走査して期限切れを削除。旧 single-tier schema のトップレベルキーも除去
- `templates/hooks/templates/injection.md.j2` / `injection.jp.md.j2`:
  - `required` の各エントリに `cached` フラグを追加。`cached` ならパス + description のみ（本文の代わりに「セッション内で注入済み、必要なら再 Read」の案内）を表示
- `templates/references/CLAUDE.md` / `CLAUDE.jp.md`、ルート `CLAUDE.md` / `CLAUDE.jp.md`、`skills/apply/SKILL.md` / `SKILL.jp.md`: 二層キャッシュの記述に更新
- TTL の env var（`{PREFIX}_INJECTION_TTL`）は両層共通

## 背景

同じリファレンスファイルが複数の `injection_rules` パターンに `required` として紐づいている場合、
旧方式（パターン単位 TTL のみ）では別パターンにマッチするファイルを編集するたびに同じドキュメント
本文が再注入されていた。リファレンスファイル単位のキャッシュ層を追加し、セッション中は同一本文を
1 回だけ注入するようにして二重注入を防ぐ（PR160）。
