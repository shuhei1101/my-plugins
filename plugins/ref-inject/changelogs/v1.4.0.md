# ref-inject v1.4.0

## refactor: emit hook scripts under hooks/scripts/

Aligned the `templates/` skeleton with the `hooks/scripts/` layout adopted across all plugins in PR180. New plugins scaffolded via `/ref-inject:apply` now start with the proper layout.

### Changes

- Moved `templates/hooks/inject_references.py` → `templates/hooks/scripts/inject_references.py`
- Added `templates/hooks/scripts/_common.py` — starter template with shared helpers (`read_hook_input`, `env_truthy`, `exit_if_stop_loop`, `already_dispatched_this_session`, `emit_block_reason`); carries `__ENV_PREFIX__` placeholder
- `templates/hooks/hooks.json`: paths point at `hooks/scripts/inject_references.py`
- `templates/hooks/scripts/inject_references.py`: `_plugin_root` fallback now uses `parents[2]`
- `skills/apply/SKILL.md` (+ jp): template → destination table extended with the new `hooks/scripts/_common.py` row
- `CLAUDE.md` (+ jp) structure tree updated to show `hooks/scripts/`

### Behavior

For target plugins that already received the previous layout, `/ref-inject:apply` writes the new files to the new locations on re-apply; the previous `hooks/inject_references.py` should be deleted manually (or the plugin maintainer can move it).

### Why

See PR180 / glossary entry `split-hook-inline-python-to-scripts`.
