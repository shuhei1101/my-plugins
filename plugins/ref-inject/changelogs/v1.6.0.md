# ref-inject v1.6.0

## feat: references-edit-guard PreToolUse hook

`references/` 配下のリファレンスファイルを **編集／作成しようとする直前** に、対応する `_index.yaml` / `_index.jp.yaml` / `_injection_rules.yaml` への登録漏れをリマインドする PreToolUse フックを追加。

### 動機

PR199（dev-kit yaml サブフォルダ化）のマージ間際に、`yaml/yaml.md` が dev-kit の `_index.yaml` / `_injection_rules.yaml` に未登録だったことが判明。同種の登録漏れは構造変更時に頻発しうるため、自動検知の仕組みを設けた。

### 変更内容

- 新規: `templates/hooks/scripts/references_edit_guard.py` — `{plugin_root}/references/` 配下の .md 編集を検知（JP ミラーは除外、`.yaml` / `_index.yaml` 自体は除外）
- 新規: `templates/hooks/prompts/references-edit-guard.md` (+ `.jp.md`) — リマインダープロンプト本文
- 編集: `templates/hooks/hooks.json` — 既存の PreToolUse(Edit/Write/MultiEdit) matcher 配下に `references_edit_guard.py` の hook 呼び出しを追加
- 編集: `skills/apply/SKILL.md` (+ `.jp.md`) — 新ファイルのコピー手順を追記

### 既存 ref-inject 利用先への波及

PR206 では本フックを既存利用先（dev-kit / claude-kit）の `hooks/hooks.json` にも併せて反映済み。
これらのプラグインも MINOR バンプ（dev-kit 4.6.0 → 4.7.0、claude-kit 3.43.1 → 3.44.0）。

### 仕様

- イベント: `PreToolUse` で `Edit` / `Write` / `MultiEdit` を捕捉（編集実行前に発火）
- スコープ: `{plugin_root}/references/` 配下の `.md` のみ（`.jp.md` は EN 原本で発火するため除外）
- dedup: `_common.already_dispatched_this_session` でセッション 1 回のみ
- 注入内容: `_index.yaml` / `_injection_rules.yaml` への登録漏れチェックリスト

### Why

リファレンスファイルの追加・移動と、その登録ファイル（`_index.yaml` / `_injection_rules.yaml`）の更新は一対だが、後者を忘れやすい。事故ベース（PR199 ヒヤリハット）で自動検知ガードを設けた。
