# py-kit v2.3.0

## 加わったもの

`references/core/comments.md`（および JP ミラー `comments.jp.md`）に、高レイヤー / オーケストレーション関数向けのコメント方針を追記（PR154）。

aituber のリファクタリング中に「サービス的なオーケストレーションクラスはユーザがよく見るのでコメント多めに欲しい。マーカーは見やすいが中身にもコメントが欲しくなる」という指摘が出たのが発端。

### 追記内容

- **レイヤー別コメント濃度** — サービス / ユースケースのオーケストレーション関数は「濃い」（マーカー + 各ステップの意図 + 分岐ごとのラベル）、機能内部ヘルパーは「中」、純粋な末端ユーティリティは「薄い」
- **オーケストレーション関数の中身にもコメント** — ブロックマーカーのラベルだけでなく、各ステップが何をしてなぜそうするのかを一言添える
- **条件分岐パターン** — `if` / `elif` / `else` の各分岐に「条件の意味 + 何をするか」をインラインコメント。コメントだけで判断ツリーを追えるようにする
- **ログ出力のみの行はコメント不要** — `logger.*` は自明なので説明コメントを付けない（「書いてはいけないもの」に例を追加）
- 必須 / 推奨マトリクスと制約まとめに上記の行を追加
- `handle_personal_chat` を例にした、上記方針を満たすサービス関数のサンプルを追加
