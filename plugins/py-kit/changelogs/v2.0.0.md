# py-kit v2.0.0

## 破壊的変更

py-kit プラグインの設計方針を全面刷新（PR138 で方針確定、PR140 で実装）。
旧 v1 系（純 DDD ベース）は完全に廃止。新規プロジェクトは v2 系で書く。

### 採用

- **機能フォルダ型レイアウト** — `src/{pkg}/{shared,features,integrations,runtime,server}/`。`shared/` と `main.py` のみ必須、他は任意
- **関数ファースト** — 振る舞いはモジュールレベル関数で書く。クラスは DTO（`@dataclass` / `BaseModel`）とライブラリ要求のみ
- **TypeScript 風 Python** — Python 3.12+ / PEP 695 `type` 文 / `Protocol` / `Callable[...]` 型エイリアスで TypeScript の interface / type alias / 関数型 / discriminated union を Python で再現
- **関数の型エイリアスで DI** — `type FindUser = Callable[[UserId], User | None]` を引数で受けて差し替え。クラスベース DI コンテナは作らない
- **ハンドラーデコレータ** — `@catch_and_log`、`@catch_and_map`、`@with_retry`、`@with_timeout` で例外横断を表現
- **結合テスト + スモークテストのみ** — 単体テストは書かない（AI 駆動開発前提でソースコードが一次仕様）。スモークはユーザー手動実行限定
- **コメント規約を next-kit と整合** — exported 関数/型に 1 行 docstring 必須、設計上重要フィールドの description 必須
- **references にメタデータ付与** — `references/index.yaml` に各 reference の `description` と編集対象ファイルパスに対する `injection_rules`（star chart）を集約

### 廃止

- **純 DDD レイアウト**（`domain` / `application` / `infrastructure` / `interface` 4 層）
- **DB 関連の reference**（py-kit は DB 対象外。Web 開発は next-kit に委譲）
- **Repository クラス / Provider クラス / Container クラス**（関数 + 関数の型エイリアスに置き換え）
- **SOLID / Strategy / Template Method / Factory / Decorator パターン解説**（関数ファースト方針では不要）
- **Pydantic 強制境界レイヤー**（使い分け表に統合: 外部境界は Pydantic、内部は dataclass、JSON 操作は TypedDict）
- **旧 references 6 ファイル**（`python-{core,architecture,scripts,testing,fastapi,llm}.md`）を解体し、38 ファイルへ分割

### 加わったもの

- `references/index.yaml` — メタデータ + 星取り表
- `references/CLAUDE.md` を「index.yaml を読め」式に簡素化
- 38 ファイル構成への分割（`core/`、`architecture/`、`shared/`、`scripts/`、`testing/`、`concurrency/`、`packaging/`、`performance/`、`llm/`、`fastapi/`）
- `plugins/py-kit/CLAUDE.md` 新設（プラグイン全体ガイド）

## 移行ガイド

v1 プロジェクトから v2 への自動移行はサポートしない。
新規プロジェクトでは v2 規約で書き、既存 v1 プロジェクトは延命するか、機を見て手動で再構成する。
