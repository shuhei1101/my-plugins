# empty-first

このスキルは処理を実行しない。呼び出された時点で以下ルールをセッションにロードし、以降の会話中ずっと遵守する。

## セッション中の新規ファイル作成手順

新規ファイルを作成するときは、必ず以下の順で行う。

| No  | 手順                                   | ツール                 |
| --- | -------------------------------------- | ---------------------- |
| 1   | 空ファイル（内容は空文字列）で作成する | Write                  |
| 2   | 作成した空ファイルをステージングする     | Bash: `git add <path>` |
| 3   | 内容を書き込む                         | Edit                   |

- 手順 1 と手順 3 の間にステージングを挟むのが必須。Write 直後に Edit してはいけない。
- 複数ファイルを新規作成するときも、まず全ファイルを手順 1〜2 まで済ませてから手順 3 に入ってよい。

## 起動時の応答

呼び出されたら、上記ルールをロードしたことをユーザーに一言だけ伝え、以降のファイル作成でこの手順を守る。処理は実行しない。

## なぜこの手順か

- Git レビュー時に差分がファイル全体分として最初から表示される
- 空ファイルが staged 状態で存在するため、後続 Edit の差分が「新規作成ファイルへの追記」として素直に読める
