# agent-delegate

メインエージェントがサブエージェントに処理を委譲するルールをコンテキストに注入するスキル。
このスキルを有効化すると、メインエージェントは以下のルールに従って動作する。

---

## 基本方針

**メインエージェントは作業を自分で処理しない。** 実装・調査・Web 検索などの具体的な作業はすべてサブエージェントに委譲する。
メインエージェントの役割は「指示・調整・統合」のみ。

---

## 委譲するタイミング

以下のいずれかに該当する場合、サブエージェントに委譲する:

| タイミング | 例 |
|---|---|
| 実装 | コードの新規作成・修正・リファクタリング |
| 調査 | ファイル構造の把握・既存コードの解析・仕様確認 |
| Web 検索 | 外部ドキュメント・ライブラリ情報の収集 |
| テスト実行 | テストコードの作成・実行・結果確認 |
| ファイル操作 | 複数ファイルの読み取り・書き込み |

---

## Agent ID の管理（コンテキスト節約）

サブエージェントには一意の Agent ID が割り振られる。
同種の依頼を繰り返す場合は `SendMessage` で同じ Agent ID に再接続し、コンテキストを継続させる。

### Agent ID 管理ルール

```
# メインエージェントがコンテキスト内で保持する変数（例）
RESEARCH_AGENT_ID=""   # 調査担当
IMPL_AGENT_ID=""       # 実装担当
SEARCH_AGENT_ID=""     # Web 検索担当
```

- Agent ID が空 → `Agent` ツールで新規起動し、返ってきた Agent ID を変数に保存する
- Agent ID が非空 → `SendMessage` ツールで `to: {Agent_ID}` を指定して既存エージェントを再利用する

### 例: 調査依頼の流れ

```
# 1回目: 新規起動
RESEARCH_AGENT_ID = Agent(subagent_type="Explore", prompt="...")
# → 返ってきた ID を RESEARCH_AGENT_ID に保存

# 2回目以降: 再利用
SendMessage(to=RESEARCH_AGENT_ID, message="追加で〇〇も調べてください")
```

---

## カスタムサブエージェントの優先利用

プロジェクト内にカスタムエージェント定義（`.claude/agents/` 配下など）が存在する場合は、
汎用エージェントより**カスタムエージェントを優先**して使用する。

カスタムエージェントを確認する方法:
```bash
ls .claude/agents/ 2>/dev/null || echo "カスタムエージェントなし"
```

---

## サブエージェントへの依頼形式

サブエージェントに依頼するときは、以下の情報を必ず伝える:

1. **目的**: 何を達成したいか
2. **コンテキスト**: これまでの調査結果・前提知識
3. **スコープ**: どこまでやってほしいか（やってほしくないことも明記）
4. **返却形式**: 後述の「サブエージェント必須返却情報」に従って返すよう指示する

---

## サブエージェントが返す必須情報

サブエージェントは作業完了時に、以下の情報を**必ず**返却する:

| No | 項目 | 内容 |
|---|---|---|
| 1 | 参照・調査したファイルパス一覧 | 作業中に読み取り・参照したファイルの絶対パス（または相対パス）を列挙する |

返却例:
```
## 参照・調査したファイルパス一覧
- /path/to/project/src/main.py
- /path/to/project/tests/test_main.py
- /path/to/project/README.md
```

---

## メインエージェントの禁止事項

| No | 禁止 |
|---|---|
| 1 | サブエージェントを介さずに自分でコードを書く |
| 2 | サブエージェントを介さずにファイルを大量に読む |
| 3 | 同じ調査を別の Agent ID で何度も起動する（コンテキスト浪費） |
| 4 | Agent ID を保存せずに捨てる |
