# dump

現在の会話履歴を要約したハンドオフ Markdown を生成する

## ステップ 1: 会話履歴を分類する

会話履歴を以下 3 ステータスに振り分ける。当てはまる項目がないステータスは表の行を作らない。

| No  | ステータス | 中身                                                         |
| --- | ---------- | ------------------------------------------------------------ |
| 1   | 完了       | 本セッションで既に完了した作業（コミット・レビュー完了含む） |
| 2   | 進行中     | 着手済みで未完了の作業                                       |
| 3   | 未着手     | ユーザーから依頼を受けたがまだ着手していない作業             |

## ステップ 2: Markdown を書き出す

以下フォーマットで `${HANDOFF_DIR}/{yyyymmddhhmmss}_{session_title}.md` に Write する。

- `## タスク一覧` は全ステータスを 1 つの表に統合
- 全ステータスのタスクは、それぞれ `## {タスク名}` サブセクションを作って詳細を書く
  - 完了タスクは「実際に変更したファイル」「参照した資料」を残す（後続セッションが履歴として参照できるように）
  - 進行中/未着手タスクは「変更予定ファイル」「事前に読むべき資料」を残す
- サブセクションの見出しは表の `タスク名` 列と一字一句一致させる（相互参照のため）
- タスク名だけで何のタスクか分かるように書く
（後続セッションはコンテキストを持たず、タスク名からしかそのタスクを特定できない）。
  - 動詞で終わる（「〜する」「〜追加」「〜修正」）
  - 対象を明示する（機能名・画面名・ファイル名など）
  - 悪い例: 「バリデーション」「リファクタ」「修正」
  - 良い例: 「ログイン画面のメールアドレス形式バリデーションを追加する」「auth ミドルウェアの JWT 検証を jose ライブラリへ差し替える」

````markdown
---
created_at: {yyyy-mm-dd hh:mm:ss}
---

# {セッションタイトル}

{セッションの概要を 1〜2 文で}

## タスク一覧

| No  | ステータス | タスク名     | 補足     |
| --- | ---------- | ------------ | -------- |
| 1   | 完了       | {タスク名}   | {補足}   |
| 2   | 〃         | {タスク名}   | {補足}   |
| 3   | 進行中     | {タスク名}   | {補足}   |
| 4   | 〃         | {タスク名}   | {補足}   |
| 5   | 〃         | {タスク名}   | {補足}   |
| 6   | 未着手     | {タスク名}   | {補足}   |

## {完了 / 進行中 / 未着手}
<!-- `## 完了`には完了したタスクを、`## 進行中`には進行中のタスクを、`## 未着手`には未着手のタスクを以下フォーマットでまとめる -->

### タスクNo-{タスクNo}
<!-- 完了 / 進行中 / 未着手すべてのタスクをサブセクションで詳細を記述する -->

**概要:**
<!-- タスクの目的を 1〜2 文で -->

**詳細:**
<!-- 現在の進捗、次のアクション、ハマりポイント・前提など -->

**変更ファイル:**

| No  | 概要   | パス              | 状況   | 補足   |
| --- | ------ | ----------------- | ------ | ------ |
| 1   | {概要} | `{path/to/file}`  | {状況} | {補足} |

<!--
- 完了タスクは実際に変更したファイル、進行中/未着手タスクは変更予定ファイルを記載
- 状況: `未着手` / `着手済み` / `レビュー済み` / `コミット済み` など
- 行がない場合は「なし」と書く
 -->

**関連資料:**

| No  | 必読 | 種別                    | 概要   | パス / URL      | 補足   |
| --- | ---- | ----------------------- | ------ | --------------- | ------ |
| 1   | ✅  | {ファイル / wiki / web} | {概要} | `{path or URL}` | {補足} |

<!--
- タスク実施前に確認すべき資料（Wiki / Web / 既存コード）を列挙する
- 必読: 次セッションで必ず読ませたい資料には `✅`、参考程度なら（空白）
 -->

## 参考資料

<!--
どのタスクにも属さないが、本セッション全体で頻繁に参照した資料 / 今後のセッションでも参照するはずの資料を列挙する。

以下は特に漏らさず含めること:
- 本セッションで何度も編集・参照した Wiki やコード
- 対象領域の CLAUDE.md / README.md / AGENTS.md など常設のガイド
- 判断根拠として繰り返し引用したドキュメント・ADR

必読: 次セッションで必ず読ませたい資料には `✅`、参考程度なら（空白）
 -->

| No  | 必読 | 種別                    | 概要   | パス / URL      | 補足   |
| --- | ---- | ----------------------- | ------ | --------------- | ------ |
| 1   | ✅  | {ファイル / wiki / web} | {概要} | `{path or URL}` | {補足} |


## 補足

タスク一覧に載らない、次セッションでも保持しておきたいコンテキストを箇条書きで残す。
以下カテゴリを目安に、該当するものだけ書く（無ければ項目ごと省略可、このセクション自体が空になるなら見出しごと省略可）。

- ユーザーの好み / 作業スタイル: 命名慣習、コミット粒度、レビュー時のこだわり、口頭で示された嗜好
- 合意した方針・却下した案: 議論の末に決めた設計判断と、他案を採らなかった理由（同じ議論を繰り返させないため）
- 環境・セットアップの前提: ローカル特有の設定、必要な環境変数、起動手順、動作確認手順
- 未解決の疑問・保留事項: タスク化していないが宙に浮いている疑問（次の会話で必ず解消したいもの）
- タスク横断の注意事項: 触ってはいけないファイル・ブランチ、避けるべき操作、依存関係のはまりポイント
- 用語 / 略語: プロジェクト内で独自の意味を持つ言葉
- その他ユーザーとのやり取りで表出した文脈: 会話の温度感、優先度感、ユーザーが強調していた懸念など

````

## ステップ 3: 一週間前以前のハンドオフを削除する

`${HANDOFF_DIR}` 配下の `.md` ファイルのうち、ファイル名先頭 `yyyymmddhhmmss` が今日から 7 日以上前のものを削除する。

- 判定は「ファイル名の日時プレフィックス」で行う（mtime ではない。手動編集で mtime がずれても対象を取りこぼさないため）
- 対象がなければ何もしない

## ステップ 4: 完了報告

以下を出力する。

```bash
生成ファイル: `{絶対パス}`
手動復元: `/handoff:load ${HANDOFF_DIR}/{yyyymmddhhmmss}_{session_title}`
```
