# load

過去のハンドオフを Read で読み込み、続きの作業に取りかかれるようにする。

## 入力

`$handoff_title`: 復元対象の指定（必須）。以下いずれかを受け付ける。

- `${HANDOFF_DIR}` 配下のファイル名から `.md` を除いた文字列（例: `20260703120000_xxx`）
- ハンドオフファイルの絶対パス

## ステップ 1: 引数の有無を確認する

`$handoff_title` が未指定なら、以下を案内してスキルを終了する。

> handoff_title を指定してください。ハンドオフファイルは `$HANDOFF_DIR` 配下に `<handoff_title>.md` の形で保存されています。
> 一覧を確認するには `ls $HANDOFF_DIR` を実行してください。復元したいファイル名から `.md` を除いた文字列が handoff_title です。

## ステップ 2: 対象ファイルパスを確定する

`$handoff_title` の形式で対象パスを決める。

- 絶対パスならそのまま対象パスとする
- それ以外は `${HANDOFF_DIR}/${handoff_title}.md` を対象パスとする

対象パスが存在しなければ「対象ファイルが見つからない」旨をユーザーに報告して終了する。

## ステップ 3: ハンドオフを Read で全文読み込む

- Read ツールでファイル全文を取り込む
- 大きい場合も `limit`/`offset` で分割せず、全文を読む前提（ハンドオフは全体で 1 つのコンテキストを構成するため）

## ステップ 4: 必読資料を事前に読み込む

ハンドオフ内の `関連資料` / `参考資料` 表で `必読` 列に `✅` が入っている行を全て抽出し、対象ファイル / URL を Read（Web の場合は WebFetch）で全て取り込む。

- 抽出は表全体を対象にする（各タスクの関連資料 + トップレベルの参考資料）
- ローカルパス → Read、URL → WebFetch
- チェックが入っていない資料は必要に応じて読み込む

## ステップ 5: サマリを提示して次の一手を促す

- 読み込んだハンドオフの `## タスク一覧` を短く要約してユーザーに提示する
- 続けて何から着手するかをユーザーに確認する（進行中タスクの再開 / 未着手タスクの着手 / 別の指示）
