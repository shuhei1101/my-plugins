# create-researcher

## フロー

1. プロジェクトを走査して縦割り候補（画面・エンドポイント）と横割り候補（ドメイン・機能）を洗い出す
2. 分割案をユーザーへ提案して合意を得る
3. 合意した分割ごとに `agents/{担当領域}-researcher.md` を生成する
   - 構造テンプレ（冒頭の `research-kit:research` 起動指示・ファイル/Wiki/Web 3 表）は埋め込まない
   - 編集・閲覧時に PreToolUse フック（`hooks/inject_rules/rules/researcher/カスタムサブエージェント構造.md`）が自動注入するため、生成直後はファイル/Wiki/Web 表の中身を埋めるだけでよい

## 分割方針

縦割り（画面・エンドポイント単位）

| No | 種別 | 1 エージェントが担当する範囲 |
| --- | --- | --- |
| 1 | フロント縦割り | 1 画面に対応するファイル群（コンポーネント・状態・スタイルなど） |
| 2 | バックエンド縦割り | 1 API エンドポイントから辿れる全ルート（ハンドラ → サービス → リポジトリ） |

横割り（ドメイン・機能単位）

| No | 種別 | 担当領域 |
| --- | --- | --- |
| 1 | 設定 | 環境変数・設定ファイル |
| 2 | データクラス | DTO など純粋なデータ構造 |
| 3 | DB | データベース関連クラス |
| 4 | ドメイン機能 | LLM 等、機能ドメイン単位（プロジェクト固有領域も含む） |
| 5 | 単体テスト | 単体テスト全般 |
| 6 | 結合テスト | 結合テスト全般 |
| 7 | E2E テスト | E2E テスト全般 |
| 8 | スモークテスト | スモークテスト全般 |
| 9 | ログ | ログ出力・収集まわり |

機能の多くはエンドポイント縦割りに吸収されるため、横割りで切り出すのは「エンドポイントに紐づかない共通カテゴリ」を中心にする。プロジェクト固有のドメインや概念があれば検知して横割り案に追加する。
