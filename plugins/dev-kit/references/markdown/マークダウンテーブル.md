# Markdown Table Conventions

Japanese mirror: `references/markdown/マークダウンテーブル.jp.md`

---

## Number column

Add a `No` column as the **leftmost column** of a table when rows need to be referenced in conversation (e.g., "fix item 3").

When present, the `No` column is **always filled** — every row has a sequential number, no exceptions.

**When to include:**
- The leftmost column values are long or complex (file paths, URLs, long names), making them hard to reference verbally.
- There is no other short, obvious identifier in the row.

**When to omit:**
- The leftmost column already acts as a natural, easily spoken primary key — for example, short option labels (`A` / `B` / `C`), single letters, or any value a person can say directly.

**Example — include:**

| No | File | Changes |
|---|---|---|
| 1 | `foo.md` | Added section A |
| 2 | 〃 | Fixed typo in section B |
| 3 | `bar.md` | Removed deprecated note |

**Example — omit (options already serve as the key):**

| Option | Description |
|---|---|
| A | Use the existing helper |
| B | Add a new helper |
| C | Inline the logic |

**Anti-pattern — omitting `No` when values are not easily spoken:**

| File | Changes |
|---|---|
| `foo.md` | Added section A |
| `bar.md` | Removed deprecated note |

## Repeated cell values

When consecutive rows share the same value in a column, write the value **only in the first row** and use `〃` (ditto mark) in subsequent rows.

**Example:**

| No | File | Changes |
|---|---|---|
| 1 | `foo.md` | Added section A |
| 2 | 〃 | Fixed typo in section B |
| 3 | `bar.md` | Removed deprecated note |

**Anti-pattern — do not repeat the full value:**

| No | File | Changes |
|---|---|---|
| 1 | `foo.md` | Added section A |
| 2 | `foo.md` | Fixed typo in section B |
| 3 | `bar.md` | Removed deprecated note |

Apply this rule to any column whose value spans multiple rows: file names, component names, categories, etc.
The `No` column is exempt — it always has a sequential number.
