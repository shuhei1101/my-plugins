# performance/cheatsheet — Performance Cheatsheet

Before you start optimizing, **measure**. "Don't guess, measure."

---

## Measurement tool cheatsheet

| Tool | Use | Granularity | Notes |
|---|---|---|---|
| `time.perf_counter()` | One-shot measurement | Function | For simple hand-written measurements |
| `timeit` module | Microbenchmark | Single function | Runs short code many times and averages |
| `cProfile` | Whole-program profile | Function calls | Standard library. CPU-time based |
| `snakeviz` | Visualize cProfile results | — | `pip install snakeviz` |
| `line_profiler` | Per-line profiling | Single line | `@profile` decorator + `kernprof` |
| `py-spy` | Sampling profiler | Function | Can attach in production, low overhead |
| `scalene` | CPU + memory + GPU | Single line | Per-line + simultaneous CPU/memory measurement, `pip install scalene` |
| `memray` | Memory profiler | Allocation | Leak investigation and heap visualization, `pip install memray` |
| `pytest-benchmark` | Regression benchmarks | Test function | Can be integrated into CI |

---

## When to use which

```
Slow / heavy in production
├── Don't know where it's slow
│   ├── In development → see the whole picture with cProfile + snakeviz
│   └── In production → attach with py-spy
├── Want to look at a specific function in detail → line_profiler / scalene (per-line)
├── Memory issues → memray / scalene
└── Want to parallelize → measure → concurrency/並列処理.md
```

## cProfile + snakeviz

```bash
# Capture profile
uv run python -m cProfile -o profile.out -m mypkg run

# Visualize (opens in browser)
uv run snakeviz profile.out
```

Partial profiling inside a script:

```python
import cProfile, pstats

def hot_section() -> None:
    profiler = cProfile.Profile()
    profiler.enable()

    # 計測対象
    do_heavy_work()

    profiler.disable()
    stats = pstats.Stats(profiler).sort_stats("cumulative")
    stats.print_stats(20)
```

## line_profiler

```python
# 計測したい関数に @profile（インポート不要、kernprof が注入）
@profile
def heavy() -> int:
    total = 0
    for i in range(10**6):
        total += i * i
    return total
```

```bash
uv run kernprof -lv script.py
```

`Time` / `% Time` is printed per line.

---

## scalene

CPU + memory + GPU per line:

```bash
uv run scalene script.py
```

An HTML report opens. The heaviest lines are color-coded for you.

---

## py-spy (attach in production)

```bash
# Attach by process ID (may require root)
sudo py-spy top --pid <PID>

# Flame graph
sudo py-spy record -o flame.svg --pid <PID> --duration 30
```

Low overhead (1-3%), so usable in production.

---

## memray

```bash
uv run memray run -o memray.bin script.py
uv run memray flamegraph memray.bin
```

Visualizes heap allocations. Useful for memory leak investigations.

## pytest-benchmark

```python
# tests/benchmarks/test_calc.py
def test_heavy(benchmark) -> None:
    result = benchmark(heavy_calc, 10**6)
    assert result > 0
```

```bash
uv run pytest tests/benchmarks/ --benchmark-only
```

Integrate as regression tests in CI to detect performance regressions.

## Hot path checklist

Try these in order against the slow spots you found by measuring:

1. **Algorithmic improvements**: O(n²) → O(n log n), etc. Maximum impact.
2. **Remove unnecessary work**: Move functions that don't need to be called every iteration out of the loop.
3. **Choose the right data structure**:
   - `list.in` → `set.in` / `dict.in` (O(n) → O(1))
   - Need sequential access → `collections.deque`
4. **`@functools.cache` / `@cached_property`** to memoize pure functions
5. **String concatenation**: Use `"".join(parts)` instead of `s += ...` in a loop
6. **`list.extend(...)` vs `for x in ...: list.append(x)`**: extend is faster
7. **Comprehension > map > for loop** (CPython optimization benefits)
8. **NumPy / pandas**: For numeric arrays, 10-100x faster than Python loops
9. **`asyncio` / `ThreadPool` / `ProcessPool`**: Parallelization (`concurrency/並列処理.md`)
10. **Cython / numba / Rust extension**: Last resort if you truly need C-level speed

## Memory optimization

| Tool / technique | Effect |
|---|---|
| `@dataclass(slots=True)` | Removes `__dict__` to reduce object size |
| `__slots__ = (...)` | Same as above (when explicit on a class) |
| `array.array` | Memory reduction for numeric arrays |
| `numpy.ndarray` | The definitive answer for numeric arrays |
| Generator expressions (`(...)`) | Iterate without accumulating a list |
| `weakref` | Break circular references |
| `gc.collect()` | Force GC if desired (don't overuse) |

---

## I/O optimization

- Files: tune buffer sizes, use `mmap`
- Network: HTTP/2, connection pooling (`httpx.AsyncClient`), `gzip` / `brotli` compression
- DB: batch INSERT, proper indexes, `EXPLAIN ANALYZE`

---

## What not to do

```python
# ❌ 計測せずに最適化（推測ベース）
# 「ここが遅そう」と思った場所は、9 割の確率で違う

# ❌ 早すぎる最適化
# 「可読性 < ナノ秒の節約」になっていないか

# ❌ マイクロベンチを過信
# 関数 1 つの 10ns 改善が、システム全体の何 % に効くかを考える

# ❌ profile を本番で長時間動かす
# cProfile はオーバーヘッドが大きい。本番なら py-spy
```
