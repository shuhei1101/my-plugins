# performance/cheatsheet — パフォーマンスチート集

> このファイルは `パフォーマンスチートシート.md` の日本語ミラーです。

最適化に着手する前に **計測** する。「推測するな、計測せよ」。

---

## 計測ツール早見表

| ツール | 用途 | 粒度 | 備考 |
|---|---|---|---|
| `time.perf_counter()` | 単発計測 | 関数 | 簡単な手書き計測に |
| `timeit` モジュール | マイクロベンチ | 関数 1 つ | 短い処理を多数回実行して平均 |
| `cProfile` | 全体プロファイル | 関数呼び出し | 標準ライブラリ。CPU 時間ベース |
| `snakeviz` | cProfile 結果の可視化 | — | `pip install snakeviz` |
| `line_profiler` | 行単位プロファイル | 1 行 | `@profile` デコレータ + `kernprof` |
| `py-spy` | サンプリングプロファイラ | 関数 | 本番に attach 可能、低オーバーヘッド |
| `scalene` | CPU + メモリ + GPU | 1 行 | 行単位 + CPU/メモリ同時計測、`pip install scalene` |
| `memray` | メモリプロファイラ | アロケーション | リーク調査・ヒープ可視化、`pip install memray` |
| `pytest-benchmark` | 回帰ベンチ | テスト関数 | CI に組み込める |

## 使い分けフロー

```
本番で遅い／重い
├── どこが遅いかわからない
│   ├── 開発中 → cProfile + snakeviz で全体を見る
│   └── 本番 → py-spy で attach
├── 特定の関数を細かく見たい → line_profiler / scalene（行単位）
├── メモリ問題 → memray / scalene
└── 並列化したい → 計測 → concurrency/並列処理.md
```

## cProfile + snakeviz

```bash
# プロファイル取得
uv run python -m cProfile -o profile.out -m mypkg run

# 可視化（ブラウザで開く）
uv run snakeviz profile.out
```

スクリプト内で部分的にプロファイル:

```python
import cProfile, pstats

def hot_section() -> None:
    profiler = cProfile.Profile()
    profiler.enable()

    # 計測対象
    do_heavy_work()

    profiler.disable()
    stats = pstats.Stats(profiler).sort_stats("cumulative")
    stats.print_stats(20)
```

## line_profiler

```python
# 計測したい関数に @profile（インポート不要、kernprof が注入）
@profile
def heavy() -> int:
    total = 0
    for i in range(10**6):
        total += i * i
    return total
```

```bash
uv run kernprof -lv script.py
```

行ごとに `Time` / `% Time` が出る。

## py-spy（本番 attach）

```bash
# プロセス ID から attach（root 権限が要る場合あり）
sudo py-spy top --pid <PID>

# フレームグラフ
sudo py-spy record -o flame.svg --pid <PID> --duration 30
```

低オーバーヘッド (1-3%) なので本番でも使える。

## ホットパスのチェックリスト

計測で見つけた遅い箇所に対して試す順:

1. **アルゴリズム改善**: O(n²) → O(n log n) など。最大効果
2. **不要な処理を消す**: ループ内で毎回呼ばなくていい関数を外へ
3. **データ構造の選択**:
   - `list.in` → `set.in` / `dict.in`（O(n) → O(1)）
   - 連続アクセスが必要 → `collections.deque`
4. **`@functools.cache` / `@cached_property`** で純粋関数のメモ化
5. **文字列結合**: ループ内 `s += ...` ではなく `"".join(parts)`
6. **`list.extend(...)` vs `for x in ...: list.append(x)`**: extend が速い
7. **comprehension > map > for ループ**（CPython の最適化恩恵）
8. **NumPy / pandas**: 数値配列なら Python ループの 10-100 倍速
9. **`asyncio` / `ThreadPool` / `ProcessPool`**: 並列化（`concurrency/並列処理.md`）
10. **Cython / numba / Rust 拡張**: 真の C 速度が必要なら最終手段

## メモリ最適化

| ツール / テクニック | 効果 |
|---|---|
| `@dataclass(slots=True)` | `__dict__` をなくしてオブジェクトサイズ削減 |
| `__slots__ = (...)` | 上と同じ（クラスで明示する場合） |
| `array.array` | 数値配列のメモリ削減 |
| `numpy.ndarray` | 数値配列の決定版 |
| ジェネレータ式 (`(...)`) | リストを溜め込まずに iterate |
| `weakref` | 循環参照を切る |
| `gc.collect()` | 任意で強制 GC（多用しない） |

---

## I/O 最適化

- ファイル: バッファサイズ調整、`mmap` の活用
- ネットワーク: HTTP/2、コネクションプール（`httpx.AsyncClient`）、`gzip` / `brotli` 圧縮
- DB: バッチ INSERT、適切なインデックス、`EXPLAIN ANALYZE`

