# settings — Configuration management via pydantic-settings

Load `.env` files and environment variables with `pydantic-settings` to produce a type-safe `Settings` object.

---

## Standard implementation

```python
# src/{pkg}/shared/settings.py
from __future__ import annotations
from pathlib import Path
from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """環境変数 + .env を読み込む設定。"""

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        env_nested_delimiter="__",
        extra="ignore",
    )

    # ----- 一般 -----
    env: str = Field(default="local", description="実行環境（local / staging / production）")
    log_level: str = Field(default="INFO", description="logger の最低レベル")

    # ----- OpenAI -----
    openai_api_key: SecretStr = Field(description="OpenAI API キー（必須）")
    openai_model: str = Field(default="gpt-4o-mini", description="既定モデル")

    # ----- Anthropic -----
    anthropic_api_key: SecretStr = Field(description="Anthropic API キー（必須）")
    anthropic_model: str = Field(default="claude-haiku-4-5-20251001", description="既定モデル")

    # ----- パス（計算済み・env からは読まない） -----
    project_root: Path = Field(default_factory=lambda: Path(__file__).resolve().parents[2])

    @property
    def log_dir(self) -> Path:
        return self.project_root / "log"
```

Key points:
- Inherit from `BaseSettings` (not the regular Pydantic `BaseModel`)
- Enable `.env` loading via `model_config = SettingsConfigDict(...)`
- Wrap API keys in `SecretStr` (they will not appear in logs)
- Use `extra="ignore"` to ignore unknown env vars (avoids polluting CI etc. with unrelated env vars)

## Always include `.env.sample`

`.env` itself goes in `.gitignore` (secret).
Manage **`.env.sample`** in git as the template for required env vars.

```bash
# .env.sample
ENV=local
LOG_LEVEL=INFO

OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-haiku-4-5-20251001
```

`.gitignore`:

```
.env
```

A new developer copies `.env.sample` to `.env` and fills in the values.

## Nested settings

For complex cases, nest `BaseModel` and read using `env_nested_delimiter`:

```python
class DatabaseSettings(BaseModel):
    host: str = "localhost"
    port: int = 5432
    user: str
    password: SecretStr

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_nested_delimiter="__")
    db: DatabaseSettings
```

`.env`:

```
DB__HOST=db.example.com
DB__PORT=5432
DB__USER=admin
DB__PASSWORD=secret
```

## Using SecretStr

```python
api_key: SecretStr = Field(description="...")
```

Safe in log output:

```python
print(settings.openai_api_key)   # SecretStr('**********')
print(settings.openai_api_key.get_secret_value())   # 実際の値（明示的に取り出す時のみ）
```

Only call `get_secret_value()` when passing the key to an external API client.

## Usage from main.py

```python
# src/{pkg}/main.py
from {pkg}.shared.settings import Settings
from {pkg}.shared.logger import get_logger
import logging

def main() -> None:
    settings = Settings()  # .env + 環境変数を自動読み込み
    logging.getLogger().setLevel(settings.log_level.upper())

    logger = get_logger(__name__)
    logger.info("starting", extra={"env": settings.env})

    handlers = build_handlers(settings)
    ...
```

**Instantiate `Settings()` only once** and bake it into the functions that need it via partial:

```python
chat = partial(
    chat_with_openai,
    api_key=settings.openai_api_key.get_secret_value(),
    model=settings.openai_model,
)
```

## Validation

Leverage Pydantic validation:

```python
from pydantic import field_validator

class Settings(BaseSettings):
    log_level: str = "INFO"

    @field_validator("log_level")
    @classmethod
    def validate_log_level(cls, v: str) -> str:
        valid = {"DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"}
        if v.upper() not in valid:
            raise ValueError(f"log_level must be one of {valid}")
        return v.upper()
```

## When you also want to load config files (YAML / TOML)

Use `model_post_init` inside `Settings` to load them:

```python
import yaml
from pathlib import Path

class Settings(BaseSettings):
    config_path: Path = Path("config.yaml")
    prompts: dict[str, str] = {}

    def model_post_init(self, _: object) -> None:
        if self.config_path.exists():
            data = yaml.safe_load(self.config_path.read_text(encoding="utf-8"))
            self.prompts = data.get("prompts", {})
```

However, for **simple values like API keys and behavior-switch flags**, `.env` is sufficient.
Use YAML for things like "prompt definitions", "structured configuration", or "list-like things".

## What not to do

```python
# ❌ 直接 os.environ を読む
import os
api_key = os.environ["OPENAI_API_KEY"]   # 型チェックも検証もない

# ❌ Settings を関数の中で何度もインスタンス化
def call_llm():
    settings = Settings()   # ← 起動コストがかかる、毎回 .env を読む

# ❌ SecretStr を生文字列のまま logger.info に渡す（マスクされず出る）
logger.info(f"key = {settings.openai_api_key.get_secret_value()}")
```
