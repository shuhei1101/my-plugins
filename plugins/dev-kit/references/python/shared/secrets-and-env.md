# secrets-and-env — Separating secrets / environment / structure / assets

Clearly separate where settings values are stored across **secrets / personal environment / structural definitions / assets / runtime state**.
**Never write secrets in `settings.yaml` or in code.**

---

## What goes where

| Kind | Location | git | Reason |
|---|---|---|---|
| **Secrets** (API keys / OAuth tokens / DB passwords) | `.env` | ❌ ignore | `settings.yaml` carries risks: worktree sharing, accidental backup inclusion, and frequent commit accidents |
| **Personal environment specifics** (Windows paths / local ports / default model names) | `config/settings.yaml` | ❌ ignore | Differs per environment but low confidentiality |
| **Structural definitions** (schemas / choices / categories) | Code (`shared/constants.py` / `Literal` / `StrEnum`) | ✅ committed | Changes are made intentionally via PR |
| **Asset definitions** (prompts / media / catalogs) | `prompts/index.yaml` / `assets/{kind}/index.yaml` | ✅ committed | Treated as code (also becomes LLM input) |
| **Runtime state** (history, cache, session) | `data/` | ❌ ignore | Generated by app execution |

## `.env` operation

```
{project_root}/
├── .env              # 実値（gitignore）
└── .env.sample       # テンプレート（committed）
```

`.gitignore`:

```
.env
```

`.env.sample` lists **the env keys required and their placeholder values**.
A new developer copies `.env.sample` to create their `.env`.

```bash
# .env.sample
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DB_PASSWORD=changeme
```

For details on how to load it, see `shared/settings.md` (`pydantic_settings.BaseSettings`).

---

## Why not write secrets in `settings.yaml`

`settings.yaml` carries the following risks:
- IDE completion makes it visible as a "settings value", so commit accidents happen easily
- It is sometimes shared between worktrees (hardlink / symbolic link)
- It gets pulled into backup / sync tools (OneDrive / iCloud)
- It sneaks into past screenshots / logs / bug reports

**`.env` is dedicated to secrets** and is recognized by the OS / IDE / git all as "do not touch".

## Handling SecretStr

When reading `.env` on the Python side, wrap with `SecretStr` so values don't accidentally appear in logs:

```python
from pydantic import SecretStr
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    openai_api_key: SecretStr
    db_password: SecretStr


settings = Settings()

# ログ
logger.info(f"key = {settings.openai_api_key}")
# → "key = SecretStr('**********')" になる（実値が出ない）

# 実値を取り出すのは外部 API 呼び出し直前のみ
chat = make_openai_chat(api_key=settings.openai_api_key.get_secret_value())
```

Details are in `shared/settings.md`.

## Environment variable naming convention

- **UPPERCASE + underscore-separated**: `OPENAI_API_KEY`, `DB_PASSWORD`
- **Indicate the domain via prefix**: external services use `{SERVICE}_{NAME}` (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`)
- **Nested structure**: using `env_nested_delimiter="__"` of `pydantic_settings` lets `DB__HOST` map to `Settings.db.host`

```python
class DatabaseSettings(BaseModel):
    host: str
    port: int

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_nested_delimiter="__")
    db: DatabaseSettings
```

```
DB__HOST=localhost
DB__PORT=5432
```

## When using YAML as SoT (optional)

If you use YAML for data management in a new domain, a **two-tier structure** of `index.yaml` + `settings.yaml` is recommended:

| File | Role | git |
|---|---|---|
| `{feature}/index.yaml` | **The key body** — environment-independent, structural definitions, the listing | ✅ committed |
| `{feature}/settings.yaml` | Accompanying metadata — updated from the UI / per environment / per person | ❌ ignore |
| `{feature}/settings.yaml.sample` | Committed template for `settings.yaml` | ✅ committed |

Decision on which to put it in:
- **Users change it through UI clicks** → `settings.yaml`
- **Essential keys that grow as files are added** → `index.yaml`
- **Values everyone should share via git** → `index.yaml` or `settings.yaml.sample`

## Things you must not do

```python
# ❌ シークレットを settings.yaml に書く
# config/settings.yaml
# openai_api_key: sk-xxx   ← 絶対 NG、.env に移す

# ❌ シークレットをコードにハードコード
OPENAI_API_KEY = "sk-..."   # 絶対 NG

# ❌ os.environ 直読みで型検証なし
import os
key = os.environ["OPENAI_API_KEY"]   # → pydantic_settings 使う

# ❌ .env をコミット
git add .env   # 絶対 NG

# ❌ SecretStr を str() でログ出力（マスクされずに出る場合あり）
logger.info(f"key = {str(settings.api_key)}")   # → settings.api_key（SecretStr のまま）
```
