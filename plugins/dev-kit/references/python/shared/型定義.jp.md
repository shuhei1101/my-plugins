# shared/types.py — 共通型エイリアス

> このファイルは `型定義.md` の日本語ミラーです。

複数 feature で共有される型エイリアスと識別子型を集約する。

---

## 配置方針

- 横断的に使う識別子型（`UserId`、`OrderId` 等）→ `shared/types.py`
- 特定 feature でしか使わない型 → `features/{feature}/types.py`
- 同じ識別子型が **複数 feature で使われる** ようになったら `shared` に引き上げる

---

## 識別子型のサンプル

```python
# src/{pkg}/shared/types.py
from __future__ import annotations
from typing import NewType

# ----- 軽量エイリアス -----
type UserId = str
type SessionId = str
type RequestId = str

# ----- 厳格に区別したい型は NewType -----
OrderId = NewType("OrderId", str)
ProductId = NewType("ProductId", str)
```

### `type` vs `NewType` の使い分け

| | `type X = str` | `X = NewType("X", str)` |
|---|---|---|
| 性質 | 単なる別名（互換性ゆるい） | 区別される別型 |
| 代入互換性 | `str` をそのまま受け取れる | 明示的キャストが必要 |
| 用途 | 「読み手のため」の識別 | 「型システムで区別」したい時 |
| ランタイムコスト | 0 | 0（実体は変わらず） |

```python
# type 文（軽量）
user_id: UserId = "u-123"   # OK（str がそのまま入る）

# NewType（厳格）
order_id: OrderId = OrderId("o-456")   # 明示キャスト必須
```

**プロジェクト内で統一**（混在しない）。
新規プロジェクトでは `type X = str` の方を推奨（軽量で扱いやすい）。

## 共通の関数型エイリアス

複数 feature で同じ関数シグネチャを使うなら、`shared/types.py` に置く:

```python
# src/{pkg}/shared/types.py
from typing import Callable, Awaitable

# 時刻取得（テスト時に固定値を返す Mock に差し替える）
type NowFn = Callable[[], datetime]

# UUID 生成
type GenerateId = Callable[[], str]

# 同期 HTTP fetch
type HttpFetch = Callable[[str], dict]

# 非同期 HTTP fetch
type AsyncHttpFetch = Callable[[str], Awaitable[dict]]
```

これらは composition root で実装を差し替えられる:

```python
# プロダクション
import uuid
from datetime import datetime, timezone

def now_utc() -> datetime:
    return datetime.now(timezone.utc)

def gen_uuid() -> str:
    return str(uuid.uuid4())

# テスト
def now_fixed() -> datetime:
    return datetime(2026, 1, 1, tzinfo=timezone.utc)

def gen_test_id() -> str:
    return "test-id"
```

## 共通 DTO

複数 feature で共有される DTO（極めて少ないはず）も `shared/types.py` に置ける:

```python
# 共通の Pagination
@dataclass(frozen=True, slots=True, kw_only=True)
class Pagination:
    page: int
    per_page: int

@dataclass(frozen=True, slots=True, kw_only=True)
class Page[T]:
    items: list[T]
    total: int
    page: int
    per_page: int
```

ただし、**ほとんどの DTO は feature 内に閉じるべき**。
複数 feature で共有しないと困るパターンが現れてから移動する（YAGNI）。

## やってはいけないこと

```python
# ❌ User や Product のような業務 DTO を shared に置く
# → feature 間で密結合になる
# {pkg}/features/users/types.py に置くべき
```

```python
# ❌ shared を「何でも置き場」にする
# shared/types.py が肥大化するなら、本当に横断的か再評価する
```

```python
# ❌ Iterable 等は標準ライブラリの型を直接使えるので type 文不要
type ListOfInt = list[int]   # 不要、list[int] でいい
```
