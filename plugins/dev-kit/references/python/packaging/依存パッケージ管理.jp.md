# packaging/dependencies — 依存管理

dev-kit Python プロジェクトでは **`uv`** を標準とする。`pip` / `poetry` は使わない。

---

## uv の利点

- 高速（Rust 製、`pip install` の 10-100 倍）
- venv 管理込み（`uv` だけで完結）
- lockfile (`uv.lock`) で再現性のある依存解決
- Python バージョン管理 (`uv python install`) も統合

---

## セットアップ

```bash
# uv 自体のインストール
curl -LsSf https://astral.sh/uv/install.sh | sh

# プロジェクト初期化
uv init mypkg --package      # src レイアウト + パッケージ化前提
cd mypkg

# Python バージョン固定
uv python pin 3.12
```

`.python-version` ファイルが作られて、以降は自動で 3.12 が使われる。

---

## 依存の追加 / 削除

```bash
# 本番依存
uv add httpx pydantic fastapi

# 特定バージョン
uv add "httpx>=0.27,<1.0"

# dev 依存
uv add --dev pytest pytest-asyncio mypy ruff

# 削除
uv remove httpx
```

`pyproject.toml` の `dependencies` / `optional-dependencies.dev` が自動更新される。

---

## 環境同期

```bash
# pyproject.toml に従って .venv を再構築
uv sync

# dev 依存も含めて
uv sync --all-extras

# 本番のみ（CI でビルドする時など）
uv sync --no-dev
```

`uv sync` を打てば `.venv/` が pyproject.toml と一致した状態になる。

---

## 実行

```bash
# venv を明示的に activate しなくても、uv run で実行できる
uv run pytest
uv run python -m mypkg
uv run uvicorn mypkg.server.app:build_fastapi --factory --reload
```

`uv run` は内部で .venv を見て実行する。CI でも開発でも同じコマンドが使える。

---

## .venv ディレクトリ

```
mypkg/
├── pyproject.toml
├── uv.lock              # ロック（コミット対象）
├── .python-version      # コミット対象
├── .venv/               # .gitignore
└── src/
```

| ファイル | 管理 |
|---|---|
| `pyproject.toml` | Git 管理 |
| `uv.lock` | **Git 管理**（再現性のため必須） |
| `.python-version` | Git 管理 |
| `.venv/` | `.gitignore` |

---

## lockfile (`uv.lock`)

`uv add` / `uv sync` で自動更新される。**手動編集禁止**。

CI では `uv sync --frozen` を使ってロック内容と乖離してないか検証:

```yaml
# .github/workflows/ci.yml
- name: Sync deps
  run: uv sync --frozen

- name: Run tests
  run: uv run pytest
```

## Python バージョンの固定

`.python-version`:

```
3.12
```

`uv python install 3.12` で自動的に必要なバージョンを取得する。
システム Python に依存しないので、開発者間で Python バージョンが揃う。

## グループの分け方

3 つ以上の依存グループに分けたい場合は `[dependency-groups]`（PEP 735）を使う:

```toml
[dependency-groups]
dev = ["pytest", "mypy", "ruff"]
docs = ["sphinx", "myst-parser"]
benchmark = ["pyperf"]
```

```bash
uv sync --group docs
uv sync --group dev --group benchmark
```

`optional-dependencies` は「外部ユーザー向けの追加機能」(`pip install mypkg[redis]` 等)、
`dependency-groups` は「開発者用の作業グループ」と使い分ける。

---

## 既存プロジェクトを uv に移行

`requirements.txt` 派から:

```bash
uv init --package
uv add -r requirements.txt
```

`poetry` 派から: 手動で `pyproject.toml` の `[project]` セクションを書いて `uv sync`。

---

## やってはいけないこと

```bash
# ❌ pip install で venv に突っ込む（uv の状態と乖離する）
pip install requests

# ✅ uv add を使う
uv add requests

# ❌ uv.lock を編集
# 手動で書き換えると整合性が壊れる

# ❌ .venv を Git 管理
# サイズ膨大、OS 依存、再現性なし → .gitignore
```
