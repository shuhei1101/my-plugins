## ログ規約

このセクションは `dev-kit:ui-dev` から参照される。
ランタイムログを出す全ての言語/フレームワーク(フロントエンド JS、バックエンド Python/Node 等)に適用する。

### ルール

1. **必ずロガーを使う** — 非スクリプトコードで `console.log`(JS)や `print`(Python)を
   直接呼ばない。レベル・フォーマットを制御できるロガーオブジェクト経由で出す。
2. **出力形式は JSON Lines** — 1 レコード 1 行の JSON。
   Claude / ログ集約基盤 / `jq` が確実にパースできる唯一の形式。
   ```jsonl
   {"ts":"2026-05-17T12:34:56.789Z","level":"info","msg":"user logged in","userId":"u_42"}
   {"ts":"2026-05-17T12:34:57.001Z","level":"warn","msg":"rate limit nearing","remaining":3}
   ```
3. **操作ログを積極的に出す** — ユーザーアクション・状態遷移・API の入出力・
   分岐判定はそれぞれ1行のログを出す。「今何が起こっているか」がログだけで分かるようにする。
4. **1 行ログは短く** — 大きなオブジェクトを複数行に展開しない。
   `{"items": 1284, "first": "a", "last": "z"}` のように要約する。
   全量が必要なときは参照(パス/ID)だけログに出して、本体は別ファイルに書く。
5. **レベル: `debug` / `info` / `warn` / `error`** — レコードごとに1つ選ぶ。
   - `debug` — 詳細な内部状態、本番ではデフォルト OFF
   - `info`  — 通常運用、ユーザー操作、状態遷移
   - `warn`  — 回復可能な異常、リトライ、フォールバック
   - `error` — 注意が必要な回復不能エラー
6. **本番デフォルトは `error`** — 調査中だけ `debug` に切り替える。
   レベルは実行時に変更可能(環境変数 / 設定ファイル / UI)。
7. **シークレットは絶対ログに出さない** — パスワード・トークン・カード番号フル・
   必要以上の PII。ロガー層でマスクすること。

### 各レコードの必須フィールド

| フィールド | 必須 | 備考 |
|---|---|---|
| `ts`    | 必須 | ISO 8601 UTC、ミリ秒精度 |
| `level` | 必須 | debug/info/warn/error のいずれか |
| `msg`   | 必須 | 人間が読む短い要約(120 文字以下) |
| `...`   | 任意 | 構造化コンテキスト(ID・件数・所要時間)。ネスト2階層を超えない |

### なぜ JSON Lines なのか

- 1 行 1 レコード → tail / grep / `jq` / `jq -s` と相性が良い
- 各行が自己完結 → 部分ログでもパース可能
- pretty-print は人が見るときだけ、ディスクには絶対書かない
