# Next.js App Router — Proxy (旧 Middleware)

> **Next.js 16 で `middleware.ts` は `proxy.ts` にリネーム**された。本リファレンスは Next.js 16 前提。

---

## proxy.ts の役割

リクエストが route handler / page に到達する前に走る処理。以下の用途に使う:

- 認証ガード（未認証ユーザーを `/login` に redirect）
- 権限ガード（`/admin/*` を管理者のみに）
- A/B testing
- ヘッダの書き換え（リクエスト・レスポンス）
- リダイレクト・rewrite
- 国際化 routing

---

## 配置と命名

```
{project-root}/proxy.ts        ← Next.js 16
```

旧 `middleware.ts` から rename。同時にファイルの関数名も `proxy` に:

```ts
// 旧 (Next.js 15 まで)
// middleware.ts
export function middleware(request: NextRequest) { ... }

// 新 (Next.js 16)
// proxy.ts
export function proxy(request: NextRequest) { ... }
```

---

## ランタイム

- **`nodejs` 固定**（edge は不可）
- 設定不可（`runtime` フラグも `experimental.runtime` も無効）
- edge runtime が必要な場合は引き続き `middleware.ts` を使う（共存可能、Next.js 16 でも middleware は維持される）

---

## 基本パターン

```ts
// proxy.ts
import { NextResponse, type NextRequest } from "next/server"

export async function proxy(request: NextRequest) {
  // 認証チェック
  const sessionToken = request.cookies.get("session_token")?.value
  if (!sessionToken && isProtectedPath(request.nextUrl.pathname)) {
    const loginUrl = new URL("/login", request.url)
    loginUrl.searchParams.set("from", request.nextUrl.pathname)
    return NextResponse.redirect(loginUrl)
  }

  return NextResponse.next()
}

const isProtectedPath = (pathname: string) =>
  pathname.startsWith("/home") ||
  pathname.startsWith("/resources") ||
  pathname.startsWith("/settings")

export const config = {
  matcher: [
    // 静的ファイル・API auth・favicon は除外
    "/((?!_next/static|_next/image|favicon.ico|api/v1/auth).*)",
  ],
}
```

---

## matcher

`config.matcher` で proxy を実行するパスを指定。

```ts
export const config = {
  matcher: [
    // すべて（静的アセット除外）
    "/((?!_next|favicon.ico).*)",

    // 特定パスだけ
    "/dashboard/:path*",
    "/api/v1/admin/:path*",
  ],
}
```

negative lookahead `?!` で除外パスを書ける。

## レスポンスを返す方法

| 関数 | 用途 |
|---|---|
| `NextResponse.next()` | そのまま route handler / page に流す |
| `NextResponse.redirect(url)` | リダイレクト |
| `NextResponse.rewrite(url)` | URL を内部的に書き換え（クライアントの URL バーは変更しない） |
| `NextResponse.json(body, { status })` | JSON レスポンスをそのまま返す |
| `new NextResponse(body, { status })` | 任意のレスポンス |

### リクエストヘッダの書き換え

```ts
const headers = new Headers(request.headers)
headers.set("x-user-id", userId)
return NextResponse.next({ request: { headers } })
```

route handler や page で `headers().get("x-user-id")` で読める。

## 認証ガード（実用例）

```ts
// proxy.ts
import { NextResponse, type NextRequest } from "next/server"
import { verifySessionToken } from "@/app/(shared)/auth/session"

const PROTECTED = ["/home", "/resources", "/settings"]
const AUTH_ONLY = ["/login", "/signup"]

export async function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl
  const token = request.cookies.get("session_token")?.value
  const session = token ? await verifySessionToken(token) : null

  // 認証必須エリア
  if (PROTECTED.some((p) => pathname.startsWith(p))) {
    if (!session) {
      const loginUrl = new URL("/login", request.url)
      loginUrl.searchParams.set("from", pathname)
      return NextResponse.redirect(loginUrl)
    }
  }

  // 認証済みなら入れない（ログイン画面など）
  if (AUTH_ONLY.some((p) => pathname.startsWith(p))) {
    if (session) return NextResponse.redirect(new URL("/home", request.url))
  }

  return NextResponse.next()
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|api/v1/auth/webhook).*)"],
}
```

## 権限ベース URL ガード（PR135 で proxy 移行）

`/{feature}/[id]/edit` への直アクセスを編集権限なしユーザーから守る:

```ts
import { NextResponse, type NextRequest } from "next/server"

const EDIT_ROUTE = /^\/(?:resources|posts)\/([0-9a-f-]+)\/edit$/

export async function proxy(request: NextRequest) {
  const session = await verifySession(request)
  if (!session) return NextResponse.redirect(new URL("/login", request.url))

  // /{resource}/[id]/edit へのアクセスを検証
  const match = request.nextUrl.pathname.match(EDIT_ROUTE)
  if (match) {
    const [, id] = match
    const canEdit = await checkEditPermissionInternal(session.userId, id)
    if (!canEdit) {
      // 編集不可 → 同じ ID の view（[id]/page.tsx）に戻す
      return NextResponse.redirect(new URL(`/${request.nextUrl.pathname.split("/")[1]}/${id}`, request.url))
    }
  }

  return NextResponse.next()
}
```

ただし proxy で DB アクセスは重いので、軽い権限チェック（JWT 内に role 情報を入れる）を推奨。重い権限判定は `(authenticated)/{feature}/[id]/edit/page.tsx` の Server Component で `redirect()` する方が良い。

## A/B Testing

```ts
export async function proxy(request: NextRequest) {
  const variantCookie = request.cookies.get("ab_variant")?.value
  if (!variantCookie) {
    const variant = Math.random() < 0.5 ? "A" : "B"
    const response = NextResponse.next()
    response.cookies.set("ab_variant", variant, { maxAge: 60 * 60 * 24 * 30 })
    return response
  }
  return NextResponse.next()
}
```

## proxy で避けるべきこと

- **重い DB クエリ**: 全リクエストで走るため。軽量な JWT 検証だけにする
- **複雑な業務ロジック**: route / page で処理する
- **外部 API 呼び出し**: タイムアウトで全リクエストが詰まる
- **Server Component 内でやるべきことを移動**: 認証フェッチは Server Component で OK

## 共存: middleware（edge）と proxy（nodejs）

`edge` runtime が必要な処理（geo-routing 等）は引き続き `middleware.ts`:

```ts
// middleware.ts (Next.js 16 でも維持)
export const config = {
  runtime: "edge",
  matcher: "/api/v1/edge-only/:path*",
}

export function middleware(request: NextRequest) {
  // ...
}
```

`proxy.ts` と `middleware.ts` は共存可能（マッチャで領域を分ける）。


---

## Constraints

- ファイル名 `proxy.ts`（旧 `middleware.ts` から PR135 で変更）
- export 関数名は `proxy`（旧 `middleware` から）
- runtime は **`nodejs` 固定**（edge は middleware.ts で）
- 重い処理は書かない（軽量な認証 / リダイレクト / ヘッダ書換 のみ）
- 全リクエストで走るので matcher で除外を厳密に
- 権限ベースの細かい判定は Server Component の `redirect()` を優先
- `NextResponse.next() / redirect() / rewrite()` を返す（または `new NextResponse(...)`）
- 共存させたい場合は `middleware.ts` を残す（edge 限定処理用）
