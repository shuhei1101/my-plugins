# app/(shared)/auth/index.ts — getAuthContext()

すべての `route.ts` / Server Action / Server Component が認証を取る統一エントリポイント。

---

## 必須テンプレ

```ts
// app/(shared)/auth/index.ts
import { db } from "@/drizzle/db"
import { ClientAuthError } from "@/app/(shared)/errors/appError"
import { getSession } from "./provider"

/** 認証必須 — 未認証なら ClientAuthError を投げる */
export const getAuthContext = async () => {
  const session = await getSession()
  if (!session) throw new ClientAuthError("認証が必要です", 401, "UNAUTHENTICATED")
  return {
    db,
    userId: session.userId,
    user: session.user,
  }
}

/** 認証任意 — 未認証なら null */
export const getOptionalAuthContext = async () => {
  const session = await getSession()
  if (!session) return null
  return { db, userId: session.userId, user: session.user }
}

/** プロフィール情報込みの拡張版（必要に応じて） */
export const getAuthContextWithProfile = async () => {
  const ctx = await getAuthContext()
  const profile = await db.query.profiles.findFirst({
    where: (p, { eq }) => eq(p.userId, ctx.userId),
  })
  return { ...ctx, profile }
}
```

---

## ルール

- **常にこの 3 関数経由で認証を取る**（`getSession()` を route / Server Action から直接呼ばない）
- DB クライアントもここで返す（呼び出し側で個別 import 不要）
- 認証失敗は **`ClientAuthError`** を投げる（`withRouteErrorHandling` / `handleActionError` が catch）
- プロバイダ差し替え時は **`provider.ts`** だけ書き換える（呼び出し側に影響なし）

## provider.ts の差し替え

```ts
// app/(shared)/auth/provider.ts
import { auth } from "@/lib/auth"
import { headers } from "next/headers"

export const getSession = async () => {
  return await auth.api.getSession({ headers: await headers() })
}
```

詳細セットアップ: `認証セットアップ.md`

## 使い方の例

```ts
// route.ts
const { db, userId } = await getAuthContext()

// Server Action
const { db, userId } = await getAuthContext()

// Server Component
const { db, userId } = await getAuthContext()

// 認証任意（ログイン画面、トップページ等）
const ctx = await getOptionalAuthContext()
if (ctx) redirect("/home")
```

## なぜ抽象化するか

- Supabase Auth / Better Auth / Auth.js / Lucia 等の **プロバイダを後から差し替え可能**
- 認証ロジックを 1 箇所に集約 → セキュリティ監査が容易
- DB と認証が独立（DB は Postgres、認証は別プロバイダの構成も可）

## 禁止

- route / Server Action から `getSession()` を直接呼ぶ（→ `getAuthContext()` を使う）
- 認証情報を `cookies()` / `headers()` から手動でパース
- DB を `db` 引数で渡さず module 直 import で使う（テスタビリティ低下）
- 認証エラーを generic `Error` で投げる（必ず `ClientAuthError`）
