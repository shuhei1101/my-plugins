# テスト方針

単体テストは書かない。結合テストとスモークテストの 2 種類だけ。

| 種類           | 目的                                                                                   | 実行                                                     |
| -------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 結合テスト     | ユースケース 1 単位（入力 → サービス → 分岐 → 結果）を通しで確認。外部依存は Mock 注入 | CI / 開発時に自動                                        |
| スモークテスト | 外部サービスへの実接続確認（実 LLM / TTS）                                             | ユーザー手動のみ。CI / AI 自動実行禁止（課金が発生する） |

## なぜ単体テストを書かないか

- ソースコードが一次仕様として読める設計（関数ファースト + 型エイリアス）を採用している
- 関数 1 つのテストはリファクタで先に壊れ、コストに対する安心感が小さい
- メソッドレベルの正しさは mypy / pyright strict で担保、ユースケースは結合テストで担保

## 結合テスト

- 1 ファイル 1 ユースケース、条件分岐ごとに `test_*` 関数を並べる
- 外部依存（`chat` 等）は Mock 関数を引数注入
- セットアップは conftest の fixture に集約
- 実行: `uv run pytest tests/ --ignore=tests/smoke/`
- カバレッジ率を目標数値で縛らない（重要ユースケースが通っているかを定性判断）

## ファイル配置

```
tests/
├── conftest.py                  # 共通 fixtures
├── features/                    # features/ をミラー
│   └── chat/
│       └── test_generate_response.py
├── server/
│   └── test_chat_route.py       # TestClient での結合テスト
└── smoke/
    ├── conftest.py              # --run-smoke ガード
    └── test_openai_live.py
```

## スモークテスト

- `tests/smoke/conftest.py` で `--run-smoke` オプションを定義し、なければ全 skip
- 実行は `uv run pytest tests/smoke/ --run-smoke`（ユーザーが明示したときだけ）
- 内容は「実接続が成立して文字列が返る」程度。業務ロジック検証は結合テスト側
- env キーがなければ `pytest.skip`
