# Claude 成果物の共通ルール

## 環境変数

Claude が読むドキュメント（SKILL.md、ルール、CLAUDE.md、プロンプトファイル、リファレンス）内では、環境変数名を `${VAR_NAME}` の形式で書く
例:
```markdown
このスキルは `${WORK_BASE_BRANCH}` を読んでチェックアウト先ブランチを決定する。
`${MY_KIT_INJECTION_TTL}` を設定してキャッシュ有効期間を制御する。
```

Claude自身が環境変数を読み込む際は`echo $VAR_NAME`を実行し値を確認するよう指示すること

## 簡潔に書く
SKILL.md・ルール・CLAUDE.md を新規作成・編集するときは最初から簡潔に書く。（Claude が読むコンテキストを無駄にしないため。）
各要点は 1 箇所だけに書き、以下のような冗長パターンを作らないこと:
- 末尾の「まとめ / 制約まとめ / Constraints」のようなセクションを作らない（本文・表の言い換えにしかならない。要点は本文の該当箇所に置く。）
- 同じ説明を繰り返さない（同一ファイル内で 2 回 3 回言い直さず、最も適切な 1 箇所に集約する。）
- 当たり前の禁止事項を書かない（「そもそも普通やらない」レベルや、すでに述べた肯定ルールの裏返しでしかない禁止は書かない。本当に事故りやすい固有の禁止だけ残す。）
