# Next.js App Router — Idempotency

> 対象: 課金・通知送信・在庫減少など、二重実行されると致命的な POST。`Idempotency-Key` ヘッダで冪等性を担保する。
クライアントは UUID 等の一意キーをヘッダで送る:
サーバーはキーを保存。同じキーで再来たら前回のレスポンスを返す（処理は走らせない）。

## どこに適用するか

| ケース                | Idempotency 必要?  |
| --------------------- | ------------------ |
| 課金 / 払い戻し       | ✅ 必須            |
| 通知 / メール送信     | ✅ 必須            |
| 在庫減少 / 予約       | ✅ 必須            |
| 一般的なフォーム POST | △ あると安全       |
| GET / PATCH / DELETE  | ❌ HTTP 仕様で冪等 |

## Stripe との連携

Stripe API は `Idempotency-Key` をネイティブサポート。Stripe SDK で:

```ts
await stripe.charges.create({ amount, currency, source }, { idempotencyKey: key })
```

クライアントから受け取ったキーをそのまま Stripe に渡せば、二重請求が完全に防げる。
