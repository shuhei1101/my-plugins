# Next.js App Router — Deploy

> **方針**: 状況による。ローカル動作のみのプロジェクト（AITuber 等）はデプロイなし、Web サービス（quest-pay 等）は **Vercel** を第一選択。

---

## デプロイ先の選択

| プロジェクト種別 | 推奨 |
|---|---|
| Web サービス（フロント + API） | **Vercel** |
| ローカル動作のみ（AITuber, デスクトップツール） | デプロイなし（`pnpm dev` で起動） |
| セルフホストしたい | Node.js サーバー（`pnpm build && pnpm start`）+ リバースプロキシ |
| 完全静的サイト | Vercel / Cloudflare Pages / Netlify |
| エッジに寄せたい | Cloudflare Workers + OpenNext |

PR135 時点では Vercel を標準とする。

---

## Vercel — 最短手順

1. GitHub と連携（リポジトリを import）
2. ビルドコマンド：自動検出（`pnpm build`）
3. 環境変数：Vercel ダッシュボードで `.env.local` の中身を設定
4. ドメイン：Vercel が自動で `*.vercel.app` を発行、独自ドメインも設定可

### Build & Output 設定

`vercel.json`（必要な場合のみ）:

```json
{
  "buildCommand": "pnpm build",
  "installCommand": "pnpm install",
  "framework": "nextjs",
  "crons": [
    { "path": "/api/v{N}/cron/daily-summary", "schedule": "0 9 * * *" }
  ]
}
```

### 環境変数

| 環境 | 設定方法 |
|---|---|
| dev | `.env.local`（git 除外） |
| Preview（PR） | Vercel ダッシュボード → Preview |
| Production | Vercel ダッシュボード → Production |

`NEXT_PUBLIC_` 付きはクライアントにバンドル、それ以外はサーバー専用（`shared/環境変数.md`）。

### Preview Deployment

PR ごとに自動的に独自 URL でデプロイ。レビューや E2E に活用。

## ローカル開発（AITuber 等）

```bash
pnpm install
pnpm dev      # http://localhost:3000
```

config:

```yaml
# config/settings.yaml
api:
  baseUrl: "http://localhost:8080"  # AITuber Python サーバー
```

ローカル動作なので、デプロイ設定・CI/CD は不要。Vercel の代わりにシンプルに `pnpm dev` で動かす。

---

## Self-host（Node.js サーバー）

```bash
pnpm build          # .next/standalone を生成
pnpm start          # 本番モードで起動
```

PM2 や Docker で常駐化:

```bash
# Dockerfile（簡易）
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
EXPOSE 3000
CMD ["node", "server.js"]
```

Nginx でリバースプロキシ:

```nginx
server {
    listen 80;
    server_name example.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

## DB（Supabase / Neon / 自前 Postgres）

| 候補 | 推奨用途 |
|---|---|
| **Supabase** | Postgres + Auth + Storage + Realtime のオールインワン |
| **Neon** | Serverless Postgres、Vercel と親和 |
| **PlanetScale** | MySQL 互換、ブランチ機能 |
| **自前 Postgres** | フルコントロール、self-host |

`DATABASE_URL` を Vercel ダッシュボードで設定。

---

## Migration の運用

ローカル / Preview / Production の DB それぞれにマイグレーション適用が必要:

```bash
# ローカル
pnpm drizzle-kit generate         # schema 変更後
pnpm drizzle-kit migrate           # 適用

# Production（手動 or CI）
DATABASE_URL=<prod-url> pnpm drizzle-kit migrate
```

CI で自動適用する場合は Production migration job を分離（誤適用を防ぐため明示的トリガー推奨）。

## 環境別の設定

| 値 | dev | staging | prod |
|---|---|---|---|
| `NODE_ENV` | `development` | `production` | `production` |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` | `https://staging.example.com` | `https://example.com` |
| `NEXT_PUBLIC_LOG_LEVEL` | `debug` | `info` | `warn`（強制） |
| `DATABASE_URL` | local | staging-db | prod-db |
| Stripe keys | test | test | live |

## ドメイン・SSL

Vercel が Let's Encrypt の証明書を自動発行。独自ドメインを設定するだけで HTTPS 化。

---

## エッジ機能

`runtime = "edge"` を使うと:
- 起動が高速（cold start なし）
- 世界中のエッジで実行
- ただし Node.js API の一部が使えない（fs, child_process 等）

`proxy.ts` は **`nodejs` 固定**（Next.js 16）。エッジ処理は `middleware.ts` で。
