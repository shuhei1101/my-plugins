# Next.js App Router — Type Definitions

スキーマ field のコメントは `コメント.md`。本ファイルは Next.js / Zod / Drizzle 固有の型定義の **置き場所と表現** に集中する。

汎用 TS（`type` 既定・union・generics・`import type`・型の置き場所の原則）は `html/typescript/型システム.md`（`**/*.{ts,tsx}` に適用され Next でも効く）に集約済み。本ファイルでは重複させない。

---

## Where to put type definitions

| Type | Location | Example |
|---|---|---|
| フォームスキーマ + 型 | `app/(authenticated)/{feature}/form.ts` | `ResourceFormSchema`, `ResourceFormType` |
| 共通スキーマプリミティブ | `app/(shared)/schema.ts` | `DisplayIdSchema`, `BirthdaySchema` |
| API リクエスト型 | `app/api/v{N}/{resource}/route.ts`（export） | `PostResourceRequest`, `PatchResourceRequest` |
| API クエリパラメータ型 + 読み取り戻り値型 | `app/api/v{N}/{resource}/query.ts` | `ResourceFilter`, `ResourceListResult` |
| Server Action 入出力型 | `app/(authenticated)/{feature}/actions.ts` または同 `form.ts` | `ResourceFormType` を再利用 |
| DB row 型 | `drizzle/schema.ts`（`$inferSelect` / `$inferInsert`） | `ResourceSelect`, `ResourceInsert` |
| Component Props | コンポーネントファイル内（export 不要） | `type Props = { ... }` |
| Hook の引数/戻り値型 | hook ファイル内（インライン） | function signature |
| 複数フィーチャで共通の domain 型 | `app/(shared)/types.ts`（3+ ファイルで使うもの） | `SortOrder`, `Pagination` |

> グローバル `types.d.ts` は使わない。型はそれを所有するコードの近くに置く。

## Zod schema → 型推論

スキーマを Zod で定義し、型は **必ず `z.infer<>` で推論**（手書きしない）。

```ts
import { z } from "zod"

export const ResourceFormSchema = z.object({
  name: z.string().min(1).max(20),
  tags: z.array(z.string()).max(10),
  isPublic: z.boolean(),
})

export type ResourceFormType = z.infer<typeof ResourceFormSchema>
```

### Why inference

- スキーマと型が乖離しない
- スキーマを変えれば型も追従
- diff が小さい

### Schema composition

```ts
// Base
export const BaseResourceFormSchema = z.object({
  name: z.string().min(1),
  iconId: z.number(),
})

// Extend
export const PremiumResourceFormSchema = BaseResourceFormSchema.extend({
  planId: z.string(),
})
export type PremiumResourceFormType = z.infer<typeof PremiumResourceFormSchema>
```

### Cross-field validation with `.refine()`

```ts
export const PasswordResetSchema = z.object({
  password: z.string().min(6),
  passwordConfirm: z.string().min(1),
})
.refine((data) => data.password === data.passwordConfirm, {
  message: "パスワードが一致しません。",
  paths: ["passwordConfirm"],
})
```

`paths: ["fieldName"]` でエラーを特定のフィールドに紐付ける（shadcn `<FormMessage>` がそのフィールド下に表示）。

### Reusable refine helper

```ts
/** from < to のバリデーションを追加 */
export const addRangeRefinement = <T extends z.ZodObject<z.ZodRawShape>>(
  schema: T,
  fromKey: string,
  toKey: string,
) => schema.refine(
  (data) => data[fromKey] == null || data[toKey] == null || data[fromKey] < data[toKey],
  { message: "開始は終了より小さい必要があります", paths: [fromKey] }
)
```

## Drizzle types

```ts
// drizzle/schema.ts
export const resources = pgTable("resources", {
  id: uuid("id").primaryKey().defaultRandom(),
  name: text("name").notNull(),
  displayId: text("display_id").notNull(),
})

export type ResourceSelect = typeof resources.$inferSelect
export type ResourceInsert = Omit<typeof resources.$inferInsert, "id" | "createdAt" | "updatedAt">
export type ResourceUpdate = Partial<ResourceInsert>
```

### Common derivations

```ts
// 自動管理カラムを除外
export type ResourceInsert = Omit<typeof resources.$inferInsert, "id" | "createdAt" | "updatedAt">

// 不変フィールドを除外
export type ResourceUpdate = Omit<Partial<ResourceInsert>, "type">

// 複合戻り値型
export type ResourceWithChildren = {
  resource: ResourceSelect
  children: ResourceChildSelect[]
  tags:     ResourceTagSelect[]
}
```

設計上重要なカラムは `/** ... */` を付ける（`コメント.md`）。

## API リクエスト / レスポンス型

### リクエスト型（`route.ts` で定義）

```ts
// app/api/v{N}/resources/route.ts
import { z } from "zod"
import { ResourceFormSchema } from "@/app/(authenticated)/resources/form"

export const PostResourceRequestSchema = z.object({
  form: ResourceFormSchema,
})
export type PostResourceRequest = z.infer<typeof PostResourceRequestSchema>
```

### クライアント側は型をインポート

```ts
// app/api/v{N}/resources/client.ts
import type { PostResourceRequest } from "./route"

export const postResource = async (req: PostResourceRequest) => { /* ... */ }
```

### レスポンス型 — `Awaited<ReturnType<...>>` パターン

クライアント側のレスポンス型は内部関数の戻り値から導出する。

```ts
// app/api/v{N}/resources/[id]/query.ts
export const fetchResource = async ({ db, id }: { db: Db; id: string }) => {
  // 複雑な join を含む select
  return await db.select(...).from(resources)...
}

export type ResourceDetail = Awaited<ReturnType<typeof fetchResource>>
```

```ts
// app/api/v{N}/resources/[id]/route.ts
export async function GET(_: NextRequest, { params }: RouteContext<'/api/v{N}/resources/[id]'>) {
  const { id } = await params
  const result = await fetchResource({ db, id })
  return NextResponse.json({ data: result })
}
```

```ts
// app/api/v{N}/resources/[id]/client.ts
import type { ResourceDetail } from "./query"

export const getResource = async ({ resourceId }: { resourceId: string }): Promise<ResourceDetail> => {
  const res = await fetch(`/api/v{N}/resources/${resourceId}`)
  const json = await res.json()
  return json.data
}
```

**型崩れ検知**: 内部関数の signature 変更で client.ts の型が壊れる場合は、CI / pre-commit で `tsc --noEmit` を走らせて検知する。詳細: `devtools/リントとフォーマット.md`

## RouteContext / PageProps / LayoutProps（Next.js 16）

Next.js 16 では `params` / `searchParams` が完全に `Promise` 化された。`next typegen` で生成される型ヘルパーを使う:

```tsx
// app/(authenticated)/resources/[id]/page.tsx
export default async function Page(props: PageProps<'/resources/[id]'>) {
  const { id } = await props.params
  return <ResourceViewScreen resourceId={id} />
}
```

```tsx
// app/api/v{N}/resources/[id]/route.ts
export async function GET(request: NextRequest, context: RouteContext<'/api/v{N}/resources/[id]'>) {
  const { id } = await context.params
  // ...
}
```

`PageProps<...>` `LayoutProps<...>` `RouteContext<...>` を使うと `params` / `searchParams` の型が自動推論される。

  resourceId, isLoading, onSubmit, tabs,
