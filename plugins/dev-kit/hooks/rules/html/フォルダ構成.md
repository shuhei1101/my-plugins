# フォルダ構成

各画面のファイル（`index.html` / `screen.ts` / `screen.css`）の作り方は `html/pages/` を参照（`画面の作り方.md` + ファイル別ルール）。本ルールは配置（どこに何を置くか）を扱う。著作は `.ts`、ブラウザ配信は `tsc` 生成の `.js`（`html/tooling/tsc運用.md`）。

`frontend/` 配下は以下の構成に従う。
```
frontend/
├── shared/                     全画面横断の共有資産（言語混在 OK・拡張子で区別）
│   ├── css/                    コンポーネントに属さない基盤スタイル
│   │   ├── layers.css          @layer 順序宣言 + @import で集約（エントリポイント）
│   │   ├── reset.css
│   │   ├── tokens.css          デザイントークン（:root 変数・@property）
│   │   ├── base.css            要素デフォルト・タイポグラフィ
│   │   ├── layout.css          ページ骨格・グリッド
│   │   └── utilities.css       単一目的ユーティリティ・バッジ等
│   ├── components/             共通 Custom Elements（.ts + .css をセットで配置）
│   │   ├── app-shell.ts
│   │   ├── app-shell.css
│   │   ├── button.css
│   │   └── ...
│   ├── core/                   定数・環境・ルーティング等のコアユーティリティ
│   │   ├── env.ts
│   │   └── constants.ts
│   ├── lib/                    汎用ユーティリティ（fmt・logger・WebSocket 等）
│   │   ├── fmt.ts
│   │   ├── logger.ts
│   │   └── ws/
│   │       └── WsClient.ts
│   ├── api/                    fetch ラッパー + 生成型（.d.ts）
│   │   └── apiFetch.ts
│   └── vendor/                 外部依存の vendoring（mermaid 等）
├── pages/                      画面（ドメイン別に階層化）
│   └── {domain}/               ドメインフォルダ
│       ├── _shared/            このドメイン内だけで使う部品（_ 接頭辞）
│       ├── index.html          画面テンプレート（Jinja2 で _layout.html を継承）
│       ├── screen.ts           画面ロジック（著作。tsc が screen.js を生成）
│       └── screen.css          画面固有スタイル（あれば）
└── templates/                  Jinja2 共通 partial
    └── _layout.html            head・importmap・app-shell の骨格
```

## ドメイン階層（フラット slug 禁止）

`pages/` 配下はドメインでフォルダ分割する。フラットなハイフン連結 slug（`mode-youtube-settings/` のような 1 階層）は使わず、概念の区切りごとにフォルダを切る。

- ⭕ `pages/modes/youtube/settings/` / `pages/llm/context/` / `pages/streaming/control/`
- ❌ `pages/mode-youtube-settings/` / `pages/llm-context/` / `pages/streaming-control/`

URL もフォルダ構成にそのまま対応する（`pages/modes/youtube/settings/` → `/modes/youtube/settings`）。配信側はディレクトリを走査してルートを動的登録するため、フォルダを切るだけで URL も階層化される。

複合語（1 つの概念を表すハイフン語）は割らない。例: `personal-chat` / `live-chat` / `x-post` / `user-dict` / `class-hierarchy`。これらは 1 セグメントとして扱う（`pages/modes/personal-chat/settings/` であって `pages/modes/personal/chat/settings/` ではない）。

中身が 1 画面だけのドメインでも分割してよい（`pages/cost/dashboard/`）。関連画面が増えたとき同じ親に収まる。

## 配置ルール

- `shared/` と `pages/` はどちらも .ts / .css を同じフォルダに混在させてよい。言語ごとにサブフォルダを切らない（生成 .js も同階層に出るが gitignore 対象）。
- `shared/css/` は例外: コンポーネントに属さない基盤スタイルのみを置く。コンポーネント CSS は `shared/components/` に置く。
- 新しいコンポーネントは `shared/components/{name}.ts` + `shared/components/{name}.css` として追加する（セット配置）。
- 使う範囲がいちばん狭い階層に置く。全画面で使うなら `shared/`、ドメイン内のみなら `pages/{domain}/_shared/`、1 画面内のみなら `pages/{domain}/` 直下。

## dev ツール設定の配置

dev 検査ツール（ビルドには使わない）の設定ファイルは repo ルートに置く。`frontend/` の中には入れない。

| ファイル | 役割 |
| --- | --- |
| `package.json` | dev ツールの devDependencies とスクリプト（type: module） |
| `tsconfig.json` | 型チェック用（`tsc --noEmit`）。`frontend/` を include |
| `tsconfig.build.json` | 生成用。`tsconfig.json` を継承し `.ts` → 同階層 `.js` を emit |
| `eslint.config.mjs` | flat config（typescript-eslint。Next/React 無し） |
| `vitest.config.js` | ユニット相当テスト（jsdom） |
| `playwright.config.js` | E2E（FastAPI 1 プロセス起動） |

E2E テストは `frontend/tests/e2e/`、ユニットテストは対象ファイルと同じ階層に `{name}.test.ts` で置く。設定の詳細は `html/tooling/tsc運用.md`。
