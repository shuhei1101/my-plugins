# 画面の作り方（pages/ 共通）

`frontend/pages/{domain}/{screen}/` 配下は全画面が同じファイル構成に統一されている。ファイル名が同じ＝役割が同じ。新規作成も既存編集も、この構成と各ファイルの定型に従う。フォルダ階層・命名は `html/フォルダ構成.md` を参照。

## ファイル構成と役割

| ファイル     | 役割                                                                                                     | 必須 |
| ------------ | -------------------------------------------------------------------------------------------------------- | ---- |
| `index.html` | Jinja2 で `_layout.html` を継承し、`<app-shell>` 内に画面の中身を書く。詳細は `html/pages/index-html.md` | 必須 |
| `screen.ts`  | 画面ロジックのエントリ（UI 層）。DOM・イベント・描画・URL 同期。詳細は `html/pages/screen-ts.md`         | 必須 |
| `screen.css` | 画面固有スタイル。共通で足りるなら作らない。詳細は `html/pages/screen-css.md`                            | 任意 |
| `api.ts`     | 通信層。`apiFetch` ラッパー。複雑画面のみ分離                                                            | 任意 |
| `state.ts`   | 純ロジック層（状態・派生計算・定数）。DOM/API を触らない。複雑画面のみ分離                               | 任意 |

著作は `.ts`。ブラウザが読むのは `tsc` が同階層に生成する `.js`（`index.html` の `<script>` は生成 `.js` を指す。`html/tooling/tsc運用.md`）。

## 単純画面 / 複雑画面の分割基準

| 規模                                   | 構成                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------ |
| 単純（おおむね 500 行以内・API 少数）  | `screen.ts` 単独に詰める。                                               |
| 複雑（複数 API・多段選択・ペイン分割） | `screen.ts`（UI）+ `api.ts`（通信）+ `state.ts`（純ロジック）に 3 分割。 |

レイヤーの呼び出し方向は UI → State → API の一方向（`html/js/レイヤー分離.md`）。

## 旧画面を復元・移植するときの原則

旧 FastAPI 版や Next.js 版から機能を戻すときは、旧コードをそのまま貼らない。今の構成に当てはめて作り直す。

- 旧版の巨大単一ファイル・グローバル関数・`onclick=` は持ち込まない。`screen.ts` + 必要なら `api.ts`/`state.ts` に再構成する。
- トースト・ダイアログ・フォーマッタ等は画面に再実装せず、共通層（`shared/components/` `shared/lib/`）を使う。無ければ共通層に足してから使う（`html/components/先読みカタログ.md`）。
- バックエンド API が現存するなら型は `shared/api/schema.d.ts` から参照する（ハードコードしない）。
- 見た目は現行のシンプルな路線を維持する。機能だけを今の枠組みに載せる。
