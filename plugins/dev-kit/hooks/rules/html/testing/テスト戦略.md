# フロントエンド テスト戦略

2 層で持つ。React Testing Library・MSW・DB は使わない（素 ES modules + FastAPI 同一オリジン配信のため）。

| 層           | ツール          | 見るもの                             | 配置                                                                          |
| ------------ | --------------- | ------------------------------------ | ----------------------------------------------------------------------------- |
| ユニット相当 | vitest（jsdom） | 純関数・状態・派生計算・フォーマッタ | 対象ファイルと同じ階層に `{name}.test.ts`（`html/testing/ユニットテスト.md`） |
| E2E          | playwright      | 画面が組み上がるか・主要操作フロー   | `frontend/tests/e2e/{name}.spec.ts`（`html/testing/e2eテスト.md`）            |

- ピラミッド構造: ユニットで網羅し、E2E は重要フローだけ。E2E でユニットレベルを検証しない。
- テスト名は「何を確認するか」を書く（`describe("対象")` / `it("○○できる")` / `it("○○のときエラー")`）。
- 待ちは `sleep` をハードコードせず `expect(...).toBeVisible()` / `waitFor` を使う（flaky 回避）。
- 実装詳細でなく振る舞いをテストする（リファクタで壊れないように）。
- バックエンド（Python）のテスト方針は別（結合中心 PR430）。プロジェクト側の testing ルールに従う。
