# コメント（汎用 TypeScript）

コメントは日本語で書く（識別子は英語のまま）。「何をしているか」より「なぜこう書くか・どう使うか」を重視する。

## 型注釈は書かない

型は TypeScript のシグネチャが持つ。JSDoc の `@param` `@returns` `@type` `@typedef` は書かない（重複）。宣言には目的だけを 1 行で書く。

```ts
// ❌ TS と重複
/**
 * リソースを取得する
 * @param {string} id - リソース ID
 * @returns {Promise<Detail>}
 */

// ✅ 目的だけ。型はシグネチャに
/** リソースを取得する */
const getResource = async (id: string): Promise<Detail> => { /* ... */ }
```

## 書く場所

| 対象 | コメント |
| --- | --- |
| export する関数・型 | 直上に `/** ... */` 1 行で目的を書く |
| 意味が非自明な引数・フィールド | その上に `/** ... */`（IDE tooltip に出る） |
| union リテラルの各値の意味 | 型の上か各行に `/** ... */`（非自明なときだけ） |
| 複雑なロジック | インライン `//` で理由を書く |
| セクション区切り | `// ─── 名前 ───` |
| 自明な行 | 書かない |

```ts
type Props = {
  /** 対象リソースの ID（新規作成時は undefined） */
  resourceId?: string
  /** 編集権限があるか */
  canEdit: boolean
}

// IME 変換中は Enter を無視する（確定キーと競合するため）
if (e.key === "Enter" && !isComposing) submit()
```

## 変更履歴コメント

非自明な変更には PR 番号付きで意図を残す。自明なリネーム・整形には書かない（一次情報は git log）。

```ts
// PR123: ステータスを 200 → 204 に変更（フロントは互換）
return new Response(null, { status: 204 })
```

ファイルに 5 個以上溜まったら冒頭の `// History:` ブロックに集約する。

## TODO / FIXME

`TODO:` = 既知の未完成、`FIXME:` = リリース前に修正必須。

```ts
// TODO(PR140): 複数選択時の UI を追加
// FIXME: from が null のとき NaN になる
```
