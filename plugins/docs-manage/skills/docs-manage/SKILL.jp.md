# docs-manage — プロジェクトドキュメント & Issue 駆動の意思決定管理

プロジェクトの wiki を管理する：構造の初期化・未決定 Issue の追跡・決定の記録・ドキュメント全体で情報の単一ソースを維持する。

---

## 概要

すべてのプロジェクト知識は `wiki/` 配下（フラット配置、サブフォルダなし）に置く：

```
wiki/
├── home.md            ← ナビゲーションハブ（全ドキュメントへのリンク集）
├── Issues.md          ← 未決定・未解決の Issue 一覧
├── イシュー履歴.md    ← 決定済み Issue の履歴ログ（追記型）
└── {機能名}.md        ← 機能別ドキュメント
```

**不変ルール：** 1 つの事実は 1 つのドキュメントで管理する。書き込み前は必ず重複チェックを行う。

---

## 作業内容

### ステップ1: 操作を特定する

#### 条件

- 常に — 他の何より先に実行する

#### 処理内容

1. ユーザーが何を求めているかを判断する：

   | ユーザーの要求 | 移動先 |
   |---|---|
   | 新規プロジェクトまたは `wiki/` が存在しない | ステップ2（初期化） |
   | 未決定事項・検討事項を挙げたとき | ステップ3（Issue 追加） |
   | 既存 Issue の決定を確認したとき | ステップ4（Issue 決定） |
   | ドキュメントの追加・削除・リネームが発生したとき | ステップ5（home.md 更新） |
   | wiki ドキュメントに情報を書き込む必要があるとき | ステップ6（重複チェック + 書き込み） |

→ 適切なステップへ進む

#### 出力

- 操作タイプを確認済み

---

### ステップ2: wiki の初期化

#### 条件

- `wiki/` が存在しない、またはユーザーが新規プロジェクトのドキュメントを整備したいとき

#### 入力

- プロジェクトルートディレクトリ

#### 処理内容

1. `wiki/` が既に存在するか Glob でスキャンして確認する。
2. `wiki/home.md` を作成または更新する — 全ドキュメントへのリンク集。
3. `wiki/Issues.md` を作成する — 未解決の Issue（まだなければ空でよい）。
4. `wiki/イシュー履歴.md` を作成する — 決定履歴（まだなければ空でよい）。
5. プロジェクトルートの `README.md` に wiki へのリンクを追加する（既存内容は保持）。
6. `CLAUDE.md` に wiki 運用ルールを追記するかユーザーに確認する。

`wiki/` が既に存在する場合：既存ファイルを差分検出して上書きせずにマージを提案する。

→ ファイルの書き込みはステップ6へ進む

#### 出力

- `wiki/home.md`、`wiki/Issues.md`、`wiki/イシュー履歴.md` が作成または確認済み

---

### ステップ3: 新しい Issue を追加する

#### 条件

- ユーザーが未決定事項・検討事項を挙げたとき

#### 入力

- ユーザーの未決定事項の説明

#### 処理内容

1. 次の Issue 番号を決める：
   - `wiki/Issues.md` と `wiki/イシュー履歴.md` の両方を Grep で `ISSUE-(\d+)` 検索する
   - 次の番号 = 見つかった最大値 + 1。一度発行した番号は再利用しない
2. 参考資料の Issue エントリテンプレートを使って下書きを作成する。
3. 複数のサブ質問がある大きな Issue は `### ISSUE-XXX-1`、`### ISSUE-XXX-2` で展開する。

→ ファイルの書き込みはステップ6へ進む

#### 出力

- `wiki/Issues.md` に追記する新しい Issue エントリが準備済み

---

### ステップ4: Issue を決定・クローズする

#### 条件

- ユーザーが既存 Issue の決定を確認したとき

#### 入力

- Issue 番号またはタイトル
- 採用した選択肢と理由

#### 処理内容

1. 番号またはタイトルで `Issues.md` の対象 Issue を特定する。
2. マスタードキュメントを決定する（参考資料のマスタードキュメント原則を参照）。
3. 書き込み前に重複チェック（ステップ6）を実行する。
4. 4 つの書き込みをバックグラウンドのサブエージェントに委譲する（並列実行）：
   - **A** — 機能別ドキュメント（マスター）に決定内容（理由含む）を追記する。
   - **B** — `wiki/Issues.md` から対象 Issue を削除する。
   - **C** — 参考資料の決定履歴テンプレートを使って `wiki/イシュー履歴.md` の末尾に追記する。
   - **D** — 新しいドキュメントが作成された場合は `wiki/home.md` のリンクを更新する。

→ ファイルの書き込みはステップ6へ進む

#### 出力

- マスタードキュメントに決定内容が記録済み、Issues.md から Issue が削除済み、履歴エントリが追記済み

---

### ステップ5: home.md を更新する

#### 条件

- `wiki/` 内でドキュメントが追加・削除・リネームされたとき

#### 入力

- `wiki/` ディレクトリの現在の状態

#### 処理内容

1. `wiki/` を Glob スキャンして現在のファイル一覧を取得する。
2. `home.md` の現在のリンクと差分を検出する。
3. セクション分類の更新を提案する（機能 / 仕様 / API / 参考資料 — プロジェクトに合わせて）。

→ ファイルの書き込みはステップ6へ進む

#### 出力

- 更新済み `home.md` のリンク一覧が準備済み

---

### ステップ6: 重複チェックして書き込む

#### 条件

- `wiki/` への書き込みを行うすべてのステップ

#### 入力

- 書き込み先のファイルと内容

#### 処理内容

1. 対象キーワードで `wiki/` 配下を全文 Grep 検索する。
2. 重複が見つかった場合：
   - マスタードキュメント原則（参考資料を参照）を適用して正しい置き場所を決める。
   - マスター以外のドキュメントでは、重複する内容を参照リンクに置き換える：
     ```markdown
     詳細は [マスタードキュメント — セクション名](wiki/master.md#section) を参照
     ```
   - マスタードキュメントを更新した後は、古いアンカー名を Grep で検索し、他ドキュメントの参照リンクが古くなっていないか確認する。
3. ファイル書き込みはすべてバックグラウンドのサブエージェントに委譲する（`run_in_background=true`）：
   - メインセッションは判断・分析・ユーザーとのやり取りに集中する。
   - サブエージェントは完了を待たずに並列でファイルを書き込む。
4. 書き込み後、ドキュメント末尾の最終更新行を追記または更新する：
   ```markdown
   **最終更新**: YYYY-MM-DD — {変更内容の概要（1行）}
   ```

→ 完了

#### 出力

- ファイル書き込み済み、最終更新行更新済み、重複チェック通過済み

#### 補足

##### 禁止事項

- `wiki/` 内にサブフォルダを作らない
- 同じ事実を複数のドキュメントに書かない — 1 つの仕様は 1 つのドキュメントで管理
- `home.md` を更新せずに新しいドキュメントを追加しない
- 古い情報を残さない — ドキュメントを削除したら `home.md` のリンクも削除
- メインセッションで直接ファイル書き込みしない — バックグラウンドのサブエージェントに委譲

## 参考資料

### Issue エントリテンプレート

```markdown
## ISSUE-XXX: {タイトル}  {未決定 | 検討中 | 保留}

**背景**: {なぜこの Issue が必要か}

**選択肢**:
- **A**: ...
- **B**: ...

**推奨**: {A/B} — {理由}

**関連ドキュメント**: [{ドキュメント名}](wiki/{ファイル名}.md)
```

### 決定履歴テンプレート（`wiki/イシュー履歴.md` に追記）

```markdown
## ISSUE-XXX: {タイトル}

- **質問内容**: {元の Issue の概要}
- **決定した内容**: {採用した選択肢と理由、1〜3 行}
- **決定日**: YYYY-MM-DD
- **転記先**: [{ドキュメント名}](wiki/{ファイル名}.md#{セクション})

---
```

### マスタードキュメント原則

| 情報の種類 | マスタードキュメント |
|-----------|---------------------|
| 機能仕様 | 機能別ドキュメント（例：`feature-x.md`） |
| 全機能共通仕様 | `共通仕様.md` または相当するドキュメント |
| 未決定事項 | `wiki/Issues.md` |
| 決定済みの設計（経緯含む） | 機能別ドキュメント（Issues.md には残さない） |
| API 仕様 | 専用 API ドキュメント |
| AI 構成 / LLM 役割分担 | 専用 AI 構成ドキュメント（存在する場合） |

マスター以外のドキュメントは参照リンクのみ記載 — 内容を重複して書かない。

## プロジェクトへのルール展開

**プロジェクトで初めて使用するとき**、`.claude/rules/wiki-work.md` が存在しない場合に作成します：

1. プロジェクトルートで `Glob(".claude/rules/wiki-work.md")` を実行して確認。
2. 存在しなければ、`.claude/rules/wiki-work.md` を以下の内容で作成：

```markdown
---
paths:
  - "wiki/**/*.md"
---

# Wiki / ドキュメント作業

## マスタードキュメント原則

1つの事実は1つのドキュメントで管理する。wikiファイルを編集する前に、同じ内容が他にないかを確認する。あれば複製せずリンクする。

## フォルダ構成

- すべてのwikiファイルは `wiki/` 直下に配置。**サブフォルダは作らない。**
- `wiki/home.md` はナビゲーションハブ。すべてのドキュメントはここからリンクされている必要がある。

## ドキュメントの追加・削除

- 新しいwikiドキュメントを作成 → `wiki/home.md` にリンクを追加する。
- wikiドキュメントを削除 → `wiki/home.md` および相互参照からそのリンクを削除する。

## wikiドキュメントの編集

書き込む前に対象キーワードで `wiki/` 配下を Grep して重複チェックする。重複がある場合、マスター以外のドキュメントからはマスターへのリンクを記載し、内容を複製しない。

## 最終更新の記録

ドキュメントを更新するたびに（初回作成時を除く）、末尾に以下を追記または更新する：

\`\`\`markdown
**最終更新**: YYYY-MM-DD — {変更内容の概要（1行）}
\`\`\`

## やらないこと

- `wiki/` 内にサブフォルダを作らない
- 同じ事実を複数のドキュメントに書かない
- `home.md` を更新せずに新しいドキュメントを追加しない
```

3. `.claude/rules-jp/wiki-work.md` をスタブとして作成：

```markdown
> **このファイルは日本語ミラーです。本体は `.claude/rules/wiki-work.md`。**
```

4. コミット：`git add .claude/rules/ && git commit -m "chore: add wiki-work rule"`
