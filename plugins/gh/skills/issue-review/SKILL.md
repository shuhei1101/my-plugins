# issue-review — Issue を AI がレビューして方針・質問を返す

ユーザーが書いた（または `/gh:issue-scan` で起票された）Issue に対し、AI が実装方針案・確認したい質問・分割すべき粒度などを **Issue コメント** として残す。ユーザーはコメントで議論を続け、合意できたら `go` ラベルを付けて `/gh:pr-wip-create` で実装フェーズに移す。

## 入力

| 引数 | 必須 | 内容 |
|---|---|---|
| Issue 番号 | 任意 | 省略時は「未レビュー Issue」を全件巡回 |

「未レビュー」の定義: ラベル `ai-reviewed` が付いていない open Issue。

## タスク

### ステップ 1: 対象 Issue を収集

| 状況 | 取得方法 |
|---|---|
| Issue 番号指定あり | `get_issue` で 1 件取得 |
| 指定なし | `list_issues` で `state: open` のうち、ラベル `ai-reviewed` が **付いていない** ものを取得（昇順） |

0 件なら「未レビュー Issue なし」で停止。

### ステップ 2: 観点別レビューを委譲

[サブエージェントで並列実行・完了を待つ] 各 Issue について `issue-reviewer` サブエージェントを起動する。
（戻り値: `{issue_number, comment_body, suggested_labels[], status}`）

入力:
- Issue 番号 / タイトル / 本文 / 既存コメント全文
- リポジトリのコードベース参照可（実装方針を立てるため、実コードを読む）

サブエージェントは以下を整理して返す:
- 実装方針案（複数案あれば比較表）
- 確認したい質問（QA-N 形式）
- 分割提案（1 Issue → 複数 PR への分割が望ましい場合）
- 影響範囲・関連ファイル

### ステップ 3: Issue にコメント投稿

サブエージェントが返した `comment_body` を `add_issue_comment` で投稿。投稿後、ラベル `ai-reviewed` を付与（再レビュー防止）。

| 提案する追加ラベル | 条件 |
|---|---|
| `needs-clarification` | 質問が含まれる場合 |
| `ready-for-go` | 質問がなく実装方針が確定している場合 |
| `split-needed` | 分割提案がある場合 |

### ステップ 4: 結果報告

| No | 報告項目 |
|---|---|
| 1 | レビューした Issue 件数と番号 |
| 2 | 各 Issue の状態（質問待ち / go 待ち / 分割提案あり） |

## 注意

- 実装方針は具体的に。「何となく」「適切に」など曖昧表現は禁止
- 既存コメントを読み、過去の議論を踏まえて返答する
- ユーザーの質問回答後に再レビューが必要な場合は手動で `ai-reviewed` を外す
